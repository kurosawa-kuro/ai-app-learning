# コード探索

小規模修正は`rg --files`、`rg -n`、必要範囲の読取りで進める。関係が分かる前に大量の全文を読まない。

複数ファイルの参照調査では、Serenaが接続済みならシンボル概要→対象シンボル→参照元の順で絞る。設定ファイルの存在だけで接続済みと判断しない。未導入・未接続なら標準検索を使う。設定や起動が必要なときだけ[運用手順](../../../docs/runbooks/ai-coding.md)を読む。

Serena 2.1.0のREPLは`initial_instructions`で取得したsession IDを使い、`s.lsp.get_symbols_overview(...)`等を最後の式に置いて返す。`print`を返却に使わない。LSPが扱えない条件付きコードや対象OS固有の参照は標準検索と対象環境の検査で補う。

探索rootは対象repo。親ディレクトリ、秘密設定、外部repoや生成物へ無差別に広げない。索引除外と読取り設定はOS権限の代わりではない。

RTKは利用可能で診断保持を確認したGit status・Cargo test・pytest・ruff checkを明示的に呼ぶ。正確なdiff・全件一覧・重要診断は通常コマンドで確認し、圧縮結果が不足すれば原文を取得する。元の操作の副作用は変わらないため、試験対象・作業権限は元コマンドと同じ基準で選ぶ。

別タスクは新しいセッションで始める。長期作業のcompact前は、決定・残件・検証結果をタスクへ残す。繰り返す再読や原文再取得を観測したら、入口文書・探索手順を狭く修正する。
