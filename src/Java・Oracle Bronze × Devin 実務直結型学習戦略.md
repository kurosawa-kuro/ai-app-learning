# IT未経験者向け｜Java・Oracle Bronze × Devin 実務直結型学習戦略

## 1. 結論

**IT未経験者は、ITパスポートや基本情報技術者試験から順番に学習するだけでなく、Java Bronze・Oracle Database BronzeをDevin環境で学び、実務に直結する技術を段階的に習得する戦略が有力である。**

目的は資格取得そのものではない。

**採用企業が受け入れやすく、教育・配属コストを抑えられる人材になること。**

特にJava・Oracleを使用する業務システムの開発・保守企業を対象とする場合、次の優位性が期待できる。

- 配属可能な業務を具体的に想定できる
- 採用後の基礎教育負担を軽減できる
- Devinによって開発・テスト・修正の流れを学べる
- 学習成果をGitHubで可視化できる
- Spring Boot・Linux・AWSへ学習を発展させられる
- 最初に習得した知識と成果物を継続的に再利用できる

この戦略の本質は、**資格を集めることではなく、最初の小さな技能から実務参加への距離を縮めること**にある。

しかし、採用側が求めるのは知識だけではない。

**「入社後、何を任せられるか」も重要な判断材料になる。**

Java・Oracleの基礎を学び、簡単なプログラムやSQLを自力で修正できる人材であれば、受け入れ側は初期業務や教育計画を具体化しやすい。

ただし、基本情報を応募要件とする企業では代替にならず、すべてのIT職種でBronze資格が優位になるわけではない。

## 3. なぜJava・Oracle Bronzeなのか

### 3.1 Java Bronze

Java Bronzeは、Javaの基本文法やオブジェクト指向の入門知識を習得する入口となる。

主な学習対象：

- 変数・データ型
- 条件分岐・繰り返し
- クラス・オブジェクト
- メソッド
- 継承・カプセル化の基礎
- Javaプログラムの実行構造

これらの知識は、そのままSpring Bootを用いた業務アプリケーション開発に接続できる。

### 3.2 Oracle Database Bronze

Oracle Database Bronze DBAは、データベースの基本構造や管理・運用を理解するための入口となる。

主な学習対象：

- RDBの基本構造
- Oracle Databaseのアーキテクチャ
- インスタンス・データベース管理
- ユーザー・権限管理
- データベース運用の基礎

**注意：Oracle Bronze DBAはSQL開発力を直接証明する資格ではない。**

Java開発への接続を重視するなら、資格学習と並行して次のSQL実習を行う。

- SELECT / INSERT / UPDATE / DELETE
- JOIN / GROUP BY
- テーブル設計
- 主キー・外部キー
- トランザクション
- JDBCによるDB接続

これにより、Java・Oracle両方の知識を一つのアプリケーションに結び付けられる。

## 4. Devinを利用する意味

### 従来の資格学習

教材を読む → 問題を解く → 暗記する → 資格取得 → 入社後に実務を学ぶ

### Devin環境での資格学習

教材を読む → Devinで動作を確認する → コードを読む → 自分で修正する → テストする → 資格取得 → 次の実務技術へ発展する

### Devinの役割

Devinは単なるコード生成ツールとしてではなく、**実装例・課題・検証・レビューを提供する学習支援環境**として活用する。

具体的には以下を担当させる。

1. 学習テーマに沿ったサンプルコードの作成
2. Java・SQLの実行環境構築支援
3. コードの挙動や構造の説明
4. 段階別の演習課題作成
5. テストコードの作成支援
6. エラーの再現と原因解説
7. 学習者のコードレビュー
8. GitHubへの学習履歴整理

### 人間が必ず行うこと

- コードを読み、処理を説明する
- Devinの実装を一部変更する
- SQLを自力で記述する
- 発生したエラーの原因を考える
- 自分でテストを実行する
- Devinなしで小さな修正を再現する

**Devinが作れたことと、本人が習得したことを混同しない。**

## 5. 発展ロードマップ

学習順序は、すべてを同時に学ぶのではなく、既存知識を再利用できる順番とする。

| Phase | 学習対象 | 習得目標 | 成果物 |
|---|---|---|---|
| 1 | Java Bronze | Javaの基本文法・OOP | Java CLIアプリ |
| 2 | Oracle Bronze＋SQL | RDB・SQL・DB管理の基礎 | DB付きJavaアプリ |
| 3 | Spring Boot | REST API・業務ロジック | Web API |
| 4 | Linux・LPIC範囲 | CLI・プロセス・権限・ログ | Linux上でアプリ運用 |
| 5 | AWS | EC2・IAM・RDS等 | クラウド上でアプリ稼働 |
| 6 | 開発・運用発展 | GitHub Actions・テスト・監視 | 継続改善可能なアプリ |

### 学習順序のポイント

**Java → Oracle / SQL → Spring Boot → Linux → AWS**

この順序なら、学んだ内容を次の段階で再利用できる。

ただし、LinuxやAWSの入門操作は早い段階から併習してもよい。LPICやAWS認定資格の取得まで各段階で必須にする必要はない。

## 6. 一つのアプリケーションを継続的に発展させる

学習段階ごとに新しい作品を作るのではなく、**一つの業務アプリケーションを成長させる**。

例：受注管理システム

- 商品クラス
- 顧客クラス
- 注文クラス
- 注文金額計算
- 入力値チェック

### Phase 2：Oracle Database

- 商品テーブル
- 顧客テーブル
- 注文テーブル
- SQLによるCRUD
- JDBCによるデータ永続化

### Phase 3：Spring Boot

- REST API化
- Controller / Service / Repository
- バリデーション
- 例外処理
- 単体・結合テスト

### Phase 4：Linux

- Linux上でアプリを起動
- 環境変数・設定ファイル管理
- プロセス管理
- ログ調査
- 権限管理

### Phase 5：AWS

- EC2へのデプロイ
- IAMによるアクセス権限管理
- DB接続

※ AWSのDB構成は費用を考慮して選択する。Oracle RDSの利用を学習初期から必須とはせず、ローカルOracle環境なども活用する。

### Phase 6：継続改善

- GitHub Actions
- テスト自動化
- CI/CD
- バグ修正
- 運用手順書
- 障害対応演習

この方式なら、資格学習と実装経験が分離しない。

## 7. 採用企業にとってのメリット

企業にとって未経験者採用の課題は、採用後の教育・指導・配置にある。

Java・Oracleを学習済みの候補者であれば、次のような効果が期待できる。

| 企業側の課題 | 本戦略で期待できる効果 |
|---|---|
| IT基礎からの教育が必要 | Java・RDBの基礎学習を一部完了 |
| 配属適性が判断しにくい | 技術スタックと成果物が明確 |
| コードを読めるか不明 | GitHubの実装・修正履歴で確認 |
| 開発ツールの習得が必要 | Git・テスト・CLIへの事前接触 |
| 新人の習熟状況が不透明 | 課題の達成記録で評価可能 |
| 教育担当者の負担が大きい | 初歩的な説明の一部を削減できる可能性 |

### 配属可能性の拡張

- **Java・Oracle基礎**：保守・テスト・DB操作補助
- **＋Spring Boot**：API改修・アプリケーション保守
- **＋Linux**：ログ解析・運用・デプロイ補助
- **＋AWS**：クラウド環境の運用・保守補助

到達する段階ごとに、応募できる職種や担当できる業務の範囲が広がる。

## 8. 個人にとってのメリット・投資リターン

### 主なリターン

1. **初期就業機会**：Java・Oracle案件への適合性を示せる
2. **学習効率**：AIを使って実装・エラー・テストを体験できる

5. **将来の選択肢**：開発・保守・運用・クラウドへの発展

投資対象は、資格受験料、教材費、Devin利用料、学習時間。

リターンは、資格手当や資格そのものの評価だけで測定しない。

**応募可能な案件数、書類選考・面接通過率、採用後の立ち上がり時間、配属後に任される業務範囲**を指標にする。

現時点でこの育成方式の採用率改善や給与上昇幅を保証するデータはないため、まずは小規模に検証する。

## 9. 破綻条件

### 9.1 Devinへの過度な依存

AIが実装しただけで、本人が内容を理解していない。

**対策：** 各PhaseでAIを使わない実装・修正課題を設ける。

### 9.2 資格取得が目的化する

資格は取得したが、Git・SQL・実装・テストを扱えない。

**対策：** 資格学習と成果物の作成を同時に進める。

### 9.3 対象企業との不一致

Java・Oracleを使わない企業では、特化学習の採用上の優位性が低下する。

**対策：** Java・Oracleを使う業務システム開発・保守企業を優先対象とする。

### 9.4 学習領域の拡散

Java、Oracle、Spring Boot、LPIC、AWSを同時並行で学び、どれも習得できない。

**対策：** Java・SQLの基礎を最優先し、次の段階へ進む条件を設定する。

### 9.5 Bronze資格の過大評価

Bronze資格は基礎知識の証明であり、実務能力や独立した開発能力の保証ではない。

**対策：** 資格と実習成果物をセットで提示する。

## 10. 実行方針

### 最初の到達目標

**Java Bronze＋Oracle Databaseの基礎＋SQL実習＋GitHub成果物**

最初からAWS・LPICまでの資格取得を要求しない。

Java・SQLの基本が理解でき、簡単な業務処理を自分で修正できるところを最初の目標とする。

### 評価方法

以下の項目を満たせば、次の学習段階へ進む。

- Javaの基本処理を説明できる
- クラス・メソッドを自分で修正できる
- 簡単なSQLを自力で書ける
- JavaからDBを操作できる
- GitHubで変更履歴を管理できる
- エラーの原因と修正内容を説明できる
- Devinの支援なしで小規模な修正を完了できる

### 成果物

1. Java Bronze・Oracle Bronze（必要に応じて取得）
2. Java＋DBの動くアプリケーション
3. GitHubリポジトリ
4. README・構成図・実行手順
5. テスト結果と修正履歴
6. 各Phaseでの自力作業評価

## 11. 最終的な戦略評価

この戦略で重視するのは、学習する知識の量ではない。

**企業側が必要とする能力を、最小限の投資で獲得し、その能力を起点に次の学習へ進める構造である。**

Java Bronze・Oracle Bronzeは、あくまで最初の入口となる。

そこからSpring Boot、Linux、AWSへと連続的に発展させることで、業務アプリケーションの開発から運用までを段階的に学べる。

### 戦略の核心

**「広く学んでから仕事を探す」のではなく、「最初に狙う仕事を定め、その仕事に必要な技能を習得し、実務に近い成果物を作りながら成長する」。**

この構造なら、資格取得後も本人の努力と改善を積み上げ続けられる。

IT未経験者の育成戦略として、対象企業を適切に絞れば、十分に検証する価値がある。
