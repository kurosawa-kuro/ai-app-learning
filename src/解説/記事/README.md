# 初回導入サポートと記事・動画の制作設計

このREADMEは、教材提供者が導入サポートと、それを支える記事・動画を作るための設計書です。受講者向けの本文は、この設計をもとに別途制作します。

## 当面の教材リポジトリと制作の起点

教材リポジトリは、当面 [kurosawa-kuro/ai-app-learning](https://github.com/kurosawa-kuro/ai-app-learning) を使います（2026-10-28時点の方針）。後日変更する可能性があるため、記事では参照先を案内する箇所にまとめ、変更時に差し替えられるようにします。

初回の導入サポートで使う「教材の説明と使い方」に加え、**「Devinの基本操作」を独立した記事・動画として用意します。** その操作を使って「教材をAIで改造する方法」へ進める構成にします。サポートの回数を記事の章立てにせず、当日の説明と、その後の読み返しに使える内容にします。

## 質問・作業の種類でAIを使い分ける

2026-10-28の全体方針として、次の役割分担で導入記事・動画を作ります。判断の記録は[ADR 0003](../../../docs/adr/0003-ai-service-roles.md)を参照します。

| 質問・依頼 | 使用するもの | 誰がどう使うか |
|---|---|---|
| プログラムコードについての質問・改造 | Devin | 受講者がコードの説明・調査・変更を依頼する |
| プログラムコードからAIへの質問 | OpenAI API | アプリのコードがAPIを呼び、生成・採点・会話などの応答を受け取る |
| 業務自動化についての質問・作業 | Cursor | 受講者が集計・ファイル整理・文面作成などを相談・依頼する |

**Geminiは教材アプリの接続先として廃止します。** OpenAI APIの準備は、その機能を使う教材に合わせて案内します。

コードについての学習・改造では、次の役割で進めます。

- 提供者は、教材の説明・使い方に加え、Devinの利用準備、教材との接続、依頼から結果確認までの進め方を用意する。
- 受講者は、何をしたいかをDevinに伝え、質問に答え、できたアプリを使って結果を確認する。
- コードの調査・変更はDevinへ依頼する。GAS版・Web版への反映については、Devinに任せる範囲と本人が操作する範囲を、教材ごとに確認して手順化する。

アプリ教材は、Devinのクラウド作業環境でリポジトリを取得（clone）して進めることを標準にします。受講者のWindowsへのダウンロード・解凍は基本的に不要です。教材リポジトリをどのように接続するか、変更をどこへ保存するか、結果をどこで確認するかを、導入準備の重点にします。アカウント作成・認証・契約・キー設定も、本人が行う操作と支援する操作を具体的な手順で明らかにします。

アプリ教材では、初回は教材の説明と使い方、2回目はDevinによる改造、3回目は予備・改造結果のレビューという構成を維持します。Devinの準備をいつ行うかは、初回を延長して改造まで進む場合も考慮して決めます。業務自動化を選ぶ受講者には、Cursorの準備・依頼・出力確認を案内します。

## 受講者が用意するアカウントと費用

**教材・コードの提供と、外部サービスの利用料金は別です。** 初回前に、選ぶ教材・自分で行う範囲・必要なアカウント・支払者を一緒に確認します。以下は受講者自身の環境で使う場合の整理です。提供者の画面で見学する場合や、提供者管理のデモを使う場合は、本人に必要な登録を別途確認します。

公式情報の確認日：**2026-10-28**。以下は課金箇所の整理であり、全員共通の月額見積もりではありません。申込時のプラン・利用枠・自動更新・追加課金の設定を確認し、受講者ごとの予算を決めます。

### 目的別の必要アカウント

「必要」は今回想定する標準の進め方で用意するもの、「条件付き」はその機能・作業を行う場合だけ必要なものです。既存アカウントを使える場合は、新規作成する必要はありません。

| 受講者が行うこと | Google | GitHub | Devin | OpenAI API | Render | Supabase | Cursor |
|---|---|---|---|---|---|---|---|
| GAS版を自分のコピーで使う | 必要 | 改造時 | 改造時 | アプリ内AIを使う場合 | 不要 | 不要 | 不要 |
| GAS版のコードを質問・改造する | 必要 | 必要 | 必要 | アプリ内AIを使う場合 | 不要 | 不要 | 不要 |
| Web版を自分で公開・改造する | 原則不要 | 必要 | 必要 | アプリ内AIを使う場合 | 必要 | 必要 | 不要 |
| 業務自動化を行う | 作業対象次第 | 通常不要 | 不要 | 通常不要 | 不要 | 不要 | 必要 |

- **Google**：GAS・Sheets・必要なDriveを使うためのアカウント。GAS専用の別アカウントを作る意味ではありません。
- **GitHub**：Devinとの接続、受講者用のコード保存先、変更の保存に使います。公開教材を読む・取得するだけの操作と、本人の変更を保存する操作を分けます。
- **Devin**：コードの質問・改造をクラウド環境で行うために使います。
- **OpenAI API**：アプリ内AIを動かす側のプロジェクト・キー・利用料金を管理します。GASの英語・写真日記など、本人のキーで使う教材では本人が準備します。AIのない教材に一律に要求しません。
- **Render・Supabase**：本人がWeb版を公開・管理する場合に用意します。完成済みの公開アプリを使うだけなら、利用者全員がこの二つへ登録するわけではありません。
- **Cursor**：手元の業務ファイルを使った自動化の相談・作業に使います。アプリ改造用のDevinとは役割を分けます。

GoogleやGitHubで別サービスへログインできても、各サービスの契約・利用枠・請求が一つにまとまるわけではありません。どのアカウントでどの組織・プロジェクトを所有するかも確認します。

### どの操作・契約で料金が発生し得るか

| サービス | 無料で始める範囲・今回の前提 | 課金が発生し得る箇所 | 初回前に確認すること・公式情報 |
|---|---|---|---|
| Google／GAS | 個人Googleアカウントで扱える範囲を使う。GASには実行回数・時間などの制限がある | Google Workspaceや保存容量などの有料契約を選ぶ場合。アプリが呼ぶOpenAI APIの料金は別 | GASの上限到達は実行停止になる。上限と有料サービスの契約を混同しない。[GASの制限](https://developers.google.com/apps-script/guides/services/quotas) |
| GitHub | コード保存はGitHub Freeを基本候補にする | 有料プラン、Actions等の有料利用・無料枠超過。教材をコピーした後に自動テストが動く場合も対象を確認する | DevinでcloneするためだけにGitHubの有料プランを必須にしない。[プラン](https://docs.github.com/en/get-started/learning-about-github/githubs-plans)・[Actionsの課金](https://docs.github.com/en/billing/concepts/product-billing/github-actions) |
| Devin | 今回はDevin Cloudを使う。無料のDesktop向け利用枠とCloud利用条件を区別する | Cloudを利用できるプランの契約料、追加利用の購入。確認時の個人Proは月20米ドルでCloudアクセスと追加利用購入を案内 | 実際に申し込むプランのCloud利用可否、含まれる利用枠、追加購入、自動更新を確認する。[公式料金](https://devin.ai/pricing) |
| OpenAI API | 対象アプリのAPIキー方式で利用する。無料クレジットがあることを前提にしない | 生成・採点・会話・画像を含む入力など、API呼び出しのモデルと利用量。接続テストやDevinによる実APIテストも対象 | キーの発行・設定と、有料のAPI実行を区別する。利用額、通知、実行を止める上限を確認する。[API料金](https://developers.openai.com/api/docs/pricing)・[課金上限](https://developers.openai.com/api/docs/guides/spend-limits) |
| Render | 学習用にFreeインスタンスを選べるが、制限とワークスペースの料金は別に確認する | 有料ワークスペース／インスタンス、送信帯域・ビルド時間等の追加利用 | Freeでも支払い方法登録済みなら帯域・ビルド枠の超過で追加請求があり得る。未登録時は停止等の制限になる。[無料枠](https://render.com/docs/free)・[料金](https://render.com/pricing) |
| Supabase | Freeプランの範囲で試す。Freeのままでは料金は発生せず、制限を受ける | 有料プラン、Compute、追加プロジェクト、容量・転送等の超過、追加機能 | ProのSpend Capは全項目をカバーしない。Computeなどは対象外。[費用制御](https://supabase.com/docs/guides/platform/cost-control) |
| Cursor | 無料プランの利用枠で始められる範囲を確認する | 有料プラン、追加利用・クレジット購入、プランに含まれないモデルの利用等 | 新旧プランで課金方式が異なるため、本人の契約の含有枠・追加利用・上限設定を確認する。古い教材のHobby等の名称だけで判断しない。[公式料金](https://cursor.com/pricing)・[追加利用の上限](https://cursor.com/help/account-and-billing/spend-limits) |

金額を載せた箇所は確認日時点の表示です。支払通貨・税・為替・契約周期を含む本人の請求額は、申し込み画面で確認します。GitHub Actionsなどの追加サービスは、教材で利用する場合だけ準備・費用の対象にします。

### 費用を分けて説明する

- **コードを調べる・改造する費用**：Devinの利用料。
- **アプリがAIを呼ぶ費用**：対象アプリに設定したOpenAI APIプロジェクトの利用料。Devinに改造を頼む利用料とは別に管理する。
- **Web版を動かし続ける費用**：Render・Supabaseの契約や利用量。ブラウザーを閉じても有料リソースの契約が終わるわけではない。
- **業務自動化を依頼する費用**：Cursorの契約・追加利用。

例えば「Devinで英語アプリを改造し、実際にAI採点を試す」場合は、Devin側の利用とOpenAI API側の利用がそれぞれ発生します。Web版を公開していれば、Render・Supabaseの費用も別に確認します。これは課金先の整理であり、各社の無料枠や契約内利用枠を必ず超えるという意味ではありません。

### 登録・課金を進める順序

1. **使う教材と作業範囲を決める。** 使うだけか、コードを改造するか、自分で公開するかを確認する。
2. **既存アカウントを確認する。** Google・GitHubなどを含め、どのアカウントで所有・管理するかを決める。
3. **必要なサービスだけ準備する。** 改造はGitHubとDevin、GASはGoogle、Web公開はRenderとSupabase、業務自動化はCursorを準備する。
4. **料金と本人の予算を確認してから契約・追加利用を選ぶ。** 有料化、追加購入、自動補充の有無は本人が把握した状態で決める。
5. **アプリ内AIを使う場合にOpenAI APIを準備する。** APIキーを設定し、利用額と上限を確認してから小さな実通信を試す。
6. **継続・終了の方法を渡す。** 利用額を確認する場所、次回更新日、追加利用の停止、解約・リソース整理の方法を案内する。

## ユーザーがつまずきやすい箇所・懸念候補

導入記事・動画で何を説明するかを考えるための候補一覧です。実際に起きた問題や、確認済みの操作手順を示すものではありません。選んだ教材・版・利用方法に必要な項目を使います。すべてのアカウント作成を全員に求める前提にはしません。

### 教材を選ぶ・Devinの環境へ取得する

- 教材の入口：どのページを開き、何から読めばよいか。
- 教材・版の選択：自分に合う教材はどれか。GAS版とWeb版のどちらを使うのか。
- GitHubとの接続：どのアカウント・リポジトリをDevinへ接続し、どのアクセス権限を用意するのか。
- 教材の取得：Devinにどう取得を頼むのか。リポジトリ全体と使う教材のフォルダーの関係が分からない。
- 作業場所：Devinの環境と自分のWindowsはどう違うのか。どちらに教材があり、どこで操作するのか。
- 変更の保存：配布元と自分の作業先をどう分けるのか。改造した結果をどのリポジトリ・ブランチへ保存し、次回どう再開するのか。

#### 標準の導入：Devinの環境でcloneする

Devinのクラウド環境でコードを取得・改造するため、Windowsの保存先やZIPの解凍を標準の導入手順から外します。Devinの公式資料でも、リポジトリをcloneした作業環境を用意する方式が説明されています。[環境設定の公式案内](https://docs.devin.ai/onboard-devin/environment)（2026-10-28確認）。

1. 教材と、受講者が変更を保存する作業先のリポジトリを決め、Devinからアクセスできるようにする。
2. Devinに対象リポジトリの取得・環境準備を依頼する。cloneなどのコマンド操作はDevin側で行い、受講者がWindowsで実行する前提にしない。
3. 使う教材のフォルダー・版を指定し、READMEや実行手順を確認してもらう。
4. 教材の使い方を確認し、改造時にはDevinへ希望を伝える。変更の保存先とGAS／Web版への反映方法は、対象教材の手順で確認する。

cloneはコードを取得する操作です。GitHubへの変更保存や、GAS・Render・Supabaseへの反映まで自動で完了する意味ではありません。配布元への読み取り権限と、受講者の作業先への書き込み権限を区別して準備します。

Windowsで教材ファイルが必要になるのは、Cursorで手元の業務ファイルを扱う場合や、PCに保存して参照する場合などです。その場合だけ、末尾の「Windowsで必要な場合の保存先と解凍方法」を使います。

### GAS版・Googleアカウント

- Googleアカウント：今のアカウントでよいか。新規作成が必要か。複数アカウントのどれを使っているか分からない。
- GASへのアクセス：GASとは何か。どのページから開くのか。Google Driveやスプレッドシートとの関係が分からない。
- 教材の配置：Devinで取得・改造したコードをどうGASへ反映するのか。Devinに依頼する作業と、本人が行う操作・設定は何か。
- データの準備：教材で使うスプレッドシートなどをどう用意し、どこで紐付けるのか。
- 初回実行・権限：承認画面が出たら何を確認すればよいか。アクセスできない場合はどうするか。
- アプリを開く：編集画面と利用画面はどう違うか。公開・更新の操作と、次回開くURLが分からない。

### OpenAI APIを使う教材（プログラムからの問い合わせ）

- APIの必要性：この教材でAPIが必要なのはどの機能か。設定前に使える範囲はあるか。
- 申し込み：どこで利用を申し込むのか。ChatGPTの利用・契約とAPIの利用はどう関係するのか。
- 支払い・料金：支払い設定は必要か。何をすると料金が発生するのか。利用額をどこで確認するのか。
- APIキーの発行：どの画面で発行し、何を保存すればよいか。キーを見失った場合はどうするか。
- アプリへの連携：発行したキーをGAS版・Web版それぞれのどこに設定するのか。設定項目名と値の対応が分からない。
- 接続の確認：何をすれば連携できたと分かるか。エラー時にどこを確認するのか。
- キーの管理：どこに保管するか。コード・画面共有・AIへの相談に含めてよい情報と、伏せる情報をどう見分けるか。

### Web版・Render・Supabase

- サービスの役割：GitHub・Render・Supabaseは何を担当するのか。どの順番で準備するのか。
- Renderアカウント：登録・ログインをどう行うのか。どのプランや設定を選ぶのか。
- Supabaseアカウント：登録後に何を作ればよいか。プロジェクトとデータベースの関係が分からない。
- GitHubとの接続：Renderにどのリポジトリを接続するのか。自分用のコピーやアクセス許可は必要か。
- データベースの準備：テーブルやサンプルデータをどう用意するのか。接続先や認証情報をどこで確認するのか。
- Renderへの設定：各種APIキー・接続先・認証情報を、どの設定名でどこに入力するのか。「環境変数」が何か分からない。
- 設定値の区別：APIキー、データベース接続情報、URLなどのどれを使うのか。教材が要求する値をどう見分けるのか。
- 公開・接続確認：公開できたかを何で判断するのか。画面が開かない、データが保存されない場合は何を見るのか。
- 更新・運用：改造後にどう反映するのか。再公開でデータはどうなるか。料金や停止・削除の方法をどこで確認するのか。

### Devinの利用準備と改造（コードについての質問・依頼）

- アカウント・利用準備：どこから登録し、どの契約・設定で始めるのか。利用量や料金をどう確認するのか。
- 教材との接続：Devinにどう教材を渡すのか。GitHubへの接続やアクセス許可をどう設定するのか。
- 作業場所：Devinが変更するのはどのリポジトリ・教材・版か。配布元と自分の作業場所、PCにダウンロードしたファイルはどう違うのか。
- GAS版との連携：どの方法でGAS版を変更するのか。変更されたコードをGASへ反映する作業は誰が行うのか。
- Web版との連携：変更をGitHubやRenderへどう反映するのか。データベースの変更が必要な場合はどう扱うのか。
- 改造の依頼：どのくらい具体的に頼めばよいか。教材の場所、変えたい点、残したい動作をどう伝えるのか。
- 結果の受け取り：AIが完了と言った後に何を確認するのか。変更の採用・修正依頼・元に戻す操作をどう行うのか。

### Cursorの利用準備（業務自動化についての質問・依頼）

業務自動化の標準はCursorです。業務自動化を選ぶ受講者には、Cursorの登録・導入と、対象ファイルを使った依頼・結果確認を案内します。コードの改造をDevinに頼む流れとは、目的と操作を分けて説明します。

- アカウント・導入：登録、インストール、ログインをどう行うのか。プランや利用料金をどこで確認するのか。
- 教材を開く：解凍したどのフォルダーを開けばよいか。AIがどのファイルを参照・変更しているか分からない。
- AIへの相談・変更：どこに質問を入力するのか。説明を聞く場合と、ファイルを変更してもらう場合をどう使い分けるのか。
- 作業後の確認：出力ファイルをどこで確認するのか。集計・整理・文面が依頼どおりか、元ファイルが保全されているかをどう確かめるのか。
- ツールの役割：コードについての質問はDevin、プログラムからの問い合わせはOpenAI API、業務自動化はCursorという区分が分かるか。

### 初回後・共通の不安

- 準備の負担：初回までに何を済ませるのか。登録や設定で止まった場合も手伝ってもらえるか。
- 再開：後日どのURL・アプリ・フォルダーから再開すればよいか。
- 説明との違い：記事や動画と画面が違う、ボタンがない場合はどうするか。
- 不具合の相談：何を試したか、どの画面やエラーを伝えればよいか。どこまで自分で試し、いつ相談すればよいか。
- 改造への不安：壊したら元に戻せるか。動いたものを見てもらえるか。どこまで変更してよいか。
- サポートの使い方：次回までに何をするのか。3回目の予備・レビューをどのように頼めばよいか。

記事化するときは、各候補について「対象の教材・版」「使い方編か改造編か」「事前準備か当日の支援か」「説明後に何を確認するか」を決めます。サービスの現行画面・料金・利用条件・連携方法は、具体的な手順を書く段階で公式情報と対象教材の実装を確認します。

## 設計の前提

提供者の見立ては、**AI・使えるコード・導入記事・動画が揃えば、1回30分のサポートで学習を始められる**というものです。30分は制作上の仮説であり、全員に必要十分な時間と実証されたわけではありません。

3回×30分のサポート枠は、受講者が「一度説明を受けた後も相談できる」と感じ、安心して始められるように用意します。回数は学習内容の積み上げから算出したものではありません。

基本の進め方は、**1回目に教材の説明と使い方、2回目にAIを使った改造の仕方**を扱う構成です。理解や操作がスムーズで、本人が先へ進みたい場合は、初回の後半から改造に入り、時間を延長して進めます。30分は基本枠とし、延長した時間は別に記録します。

記事・動画は「教材の説明と使い方」「Devinの基本操作」「Devinを使った教材の改造」に分けて制作します。必要な材料は初回から参照できるようにし、本人のペースで先に進めるようにします。**3回目は、1・2回目でも解消できなかった疑問・不安・つまずきへの対応、または2回目で取り組んだ改造の結果レビューに使う予備枠**です。必要に応じて使い、新しい学習内容をあらかじめ割り当てません。

## 初回で目指す状態

本人の目的に合う教材を選び、支援を受けながらでも、次を確認できる導入を作ります。

- 教材が何のためのもので、何ができるかを理解する。
- 教材を開き、基本の操作を試し、結果を確認する。
- 続きを始める場所、記事・動画の参照先、相談先を確認する。

その場ですべてを覚える必要はありません。AIへの改造依頼は2回目の基本内容とし、初回全員の条件にはしません。使い方の質問をAIに聞くことはできますが、初回の中心は教材そのものの説明と利用です。Javaの実務技能など、目的ごとに必要な習得はその後の学習で確かめます。

本人がまだ「一人で続けるのは不安」と感じていても、経験できたことと不安の内容をそれぞれ扱います。提供者が説明を終えたことだけでは、導入できたとは判断しません。

## 制作するものと役割

| 材料・支援 | 担うこと | 制作時に確かめること |
|---|---|---|
| コード・サンプル | すぐに触れられる出発点と、結果を比較できる材料 | 選んだ版と環境で、最初の操作が動くか |
| 使い方の記事・動画 | 教材の目的、基本操作、結果、困ったときの参照先を示す | 初回後に教材を開いて使い始められるか |
| Devin基本操作の記事・動画 | ログイン、教材へのアクセス、質問の送り方、返答・作業状況の確認、再開方法を示す | 教材について一つ質問し、返答を確認して追加質問できるか |
| 改造の記事・動画 | Devinへの依頼から変更、結果確認、戻し方までを示す | 2回目や初回の延長で、一つの変更を試せるか |
| Devin | 本人に合わせた説明、質問への応答、コードの調査・変更や確認の補助 | 対象の教材を参照でき、依頼から結果確認まで進められるか |
| OpenAI API | アプリのコードからの問い合わせに応答する | 対象教材で必要な接続設定と、生成・採点・会話などの結果を確認できるか |
| Cursor | 業務自動化の質問・作業依頼に対応する | サンプルの業務ファイルで依頼し、出力と元ファイルの保全を確認できるか |
| 初回サポート | 教材を説明し、使い方を一緒に試す | 本人が基本操作と結果を確認できたか |
| 2回目のサポート | AIを使った改造の仕方を一緒に試す | 希望をAIに伝え、小さな変更と結果確認を経験できたか |
| 3回目のサポート（予備・レビュー） | 未解消の疑問・不安・つまずきへの対応、または2回目の改造結果をレビューする | 残った問題の解消、または改造が本人の意図どおりかを確認できたか。残件の次の扱いが明らかか |

記事は当日の説明にも、後日の読み返しにも使います。記事と動画を両方見終えることを、参加の必須条件にはしません。

## Devinの基本操作を独立した記事・動画にする

Devinに不慣れな受講者が、教材の内容を考える前に操作で止まることを減らします。教材ごとに同じ操作説明を繰り返さず、各教材から参照できる共通資料として作ります。

基本操作編の到達点は、**対象の教材についてDevinに質問し、返答を読んで追加質問でき、後日その続きを開けること**です。最初の練習は「この教材で何ができるか説明して」と聞く程度にし、コードの変更は改造編で扱います。

| 説明する範囲 | 記事・動画に用意する内容 |
|---|---|
| 利用開始 | アカウント・ログインと、利用条件・料金を確認する場所 |
| 教材へのアクセス | GitHubとの接続、対象リポジトリ・教材の指定、Devinの作業環境への取得 |
| 最初の質問 | 入力する場所、質問例、送信と返答の確認 |
| やり取りを続ける | 分からない点を聞き直す、Devinからの質問に答える、意図を訂正する |
| 作業中の確認 | 状況をどこで見るか、待っている理由や問題をどう確かめるか、必要なときの停止方法 |
| 結果と再開 | 回答・成果物・会話の場所を確認し、次回続きを始める方法 |

これは制作範囲の案です。具体的な画面名・操作・料金の案内は、制作時の公式資料と実際の利用画面で確認します。記事は操作を探して読み返せる形、動画は同じ操作を画面で追える形にし、見出しを対応させます。

基本操作編はDevinを初めて使う前に案内します。事前に読める・見られるようにし、必要ならサポート中にも該当箇所を一緒に確認します。全編の事前視聴を参加条件にはせず、操作支援にかかった時間も導入の検証へ含めます。独立した資料を作ることを、サポート回数を増やす理由にはしません。

## 作る順序

### 1. 最初に支援する一人・一つの用途を選ぶ

まず、既存教材から最初に導入を作る対象を一つ選びます。全教材分を同時に書き始めず、次の項目を一枚に整理します。

| 決めること | 記入する内容 |
|---|---|
| 対象と目的 | 誰が、何をしたいか。本人の希望を使う |
| 最初の一歩 | 初回に試す基本操作と期待結果、2回目に試す小さな改造 |
| 開始時の障壁 | 操作への不慣れ、環境準備、何を頼めばよいかなど |
| 用意する支援 | 提供者が準備するもの、その場で手伝うこと |
| 続き方 | 同じ課題を再度試す方法と、小さく変えて試せること |
| 確認方法 | 本人が結果を比べられる例と、元に戻す方法 |

記録には既存の[初回支援シート](../../../docs/templates/ai-pairing-session.md)の目的・準備・支援枠の欄を使います。同シートの「AIへの依頼・試行・結果確認」は、今回の構成では改造を扱う回の記録に使います。初回の教材利用と、AIを使った改造の達成は分けて記録します。アプリ利用、事務処理、資格・実務学習では、課題と成果をそれぞれの目的に合わせます。

### 2. 教材を使う手順と、改造する手順をそれぞれ通す

提供者自身が、受講者へ渡すものだけを使って、初回の「教材を開く → 基本操作を試す → 結果を確認する」と、2回目の「Devinで対象教材を参照できることを確認する → 改造したいことを依頼する → 変更をアプリへ反映する → 動作を確認する」をそれぞれ通します。リンク、教材の版、操作手順、期待結果、戻し方を確認します。

Devinへの依頼例には、本人の目的、対象のリポジトリ・教材・版、今回試す範囲、確認方法を含めます。PCにあるファイルや教材の内容を自動で知っている前提にせず、何を接続・指定・添付するかを決めます。接続方法や公開先への反映方法は、利用環境で確認した手順を記事にします。

この段階で、アカウント・インストール・ログインなどの準備を洗い出します。事前に本人が行うことと提供者が支援することを明記し、未準備の場合の進め方も決めます。準備に必要だった時間は、30分の導入とは別に記録します。事前作業を増やして見かけだけ30分に収める設計にはしません。

アプリ教材の実装・検証は各教材の正本に従います。提供者の制作順はWeb → GAS、受講順はGAS → Webという既存方針を維持します。このREADMEだけで未検証の教材を利用可能とは扱いません。

### 3. 当日の進行メモと、記事の最小原稿を作る

初回は、次の流れを基本にします。時間配分の細分化は、最初の試行を見て調整します。

1. 本人のやりたいこと・不安を確認する。
2. 教材の目的と、できることを実際の画面で説明する。
3. 本人と一緒に基本操作を試し、使い方と結果を確認する。
4. 再開する方法と、次にAIで改造する流れを案内する。

2回目は、使ってみた感想や疑問を確認し、本人が変えたいことを一つ選んで、AIへの依頼・変更・結果確認・戻し方を扱います。初回で使い方をつかみ、本人も改造を試したい場合は、後半からこの内容へ進みます。延長できる時間をその場で確認し、通常の使い方説明を急がせずに進めます。

記事には、この流れを支える説明と参照先を用意します。親の[入門ガイド](../README.md)を材料に、導入時に必要な説明を選びます。コンピューター・プログラム・AIから学ぶ意味の説明は、本人が今回の体験を理解するために必要な深さにします。詳しい基礎解説は、後から読める補足へつなげます。

初回後に渡す案内は、「次に開く場所」「基本操作をもう一度試す手順」「使い方の記事・動画」「人への相談方法」を一か所からたどれるようにします。改造編への参照先も示し、改造を扱った後には、使った依頼文・結果の確認方法・戻し方を残します。

### 4. 記事をもとに、同じ体験の動画を作る

最小原稿と動作確認済みの教材を使い、教材の使い方編・Devin基本操作編・教材の改造編を分けて収録します。見返したい場面へ移れるよう、記事の見出しと動画の区切りを対応させます。初回に改造まで進む場合も、同じ基本操作編・改造編を使います。

最初の試行に必要な動画を先に用意し、画面や説明の修正が容易な形にします。凝った編集や全教材分の収録は、導入の流れを確かめた後に進めます。

### 5. 記事・動画・AI・コードを揃えて、初回30分を試す

用意した一式で実際に支援し、次を短く記録します。

- 事前準備に必要だった時間と支援。
- 初回に体験できたこと、提供者が手伝ったこと、残ったこと。
- 教材の説明・使い方にかかった時間と、改造まで進んだ場合の延長時間。
- 長く説明した箇所、操作が止まった箇所、本人の疑問や不安。
- 初回後に、教材やAIを使って取り組めたことと、相談が必要だったこと。

初回を延長して改造まで進めた場合は、改造も含めて30分でできたとは記録しません。2回目に改造を扱う進め方と、初回に続けて扱う進め方をそれぞれ確認します。

30分で終わらなかったときは、準備・説明・操作・課題の大きさなど、実際の理由を確認します。課題を小さくする、手順を直す、補足を加える、支援の進め方を変える、のどれが有効かを判断します。必要な体験を省いて時間だけを合わせません。

### 6. 共通部分を整え、次の対象へ広げる

試行で使えた説明や案内を共通化し、本人の目的・教材・最初の体験に関わる箇所を差し替えます。新しい対象でも最初の体験を確かめます。

共通記事を増やす優先順位は、実際に繰り返し必要になった説明から決めます。受講者が一度だけ困ったことは、個別の補足で足りるかも検討します。

## 2回目と、初回から続けて進む場合

2回目の基本内容は、Devinを使った改造の仕方です。教材を使ってみて変えたいことを一つ選び、希望を言葉にする、Devinに対象教材を指定して依頼する、変更をアプリへ反映して試す、期待した結果と比べる、必要なら戻す、という流れを体験します。

理解や操作がスムーズな人は、初回後半を延長してこの内容まで進めます。基本操作をつかんでいること、改造への関心があること、本人と提供者の時間が取れることを目安にします。改造を前倒しで経験した場合、次の回はその後の疑問や試したい変更に合わせます。

## 3回目は、未解消の問題への対応や改造結果のレビューに使う予備

3回目は、本人の状況に合わせて次の用途に使います。

- **未解消の問題への対応**：1・2回目でも残った疑問・不安・つまずきを確認し、必要な説明や操作を一緒にやり直す。
- **改造結果のレビュー**：2回目に取り組んだ改造や、その後に本人が進めた結果を見ながら、何を変えたか、意図した動作になっているか、元の基本操作も使えるかを一緒に確認する。必要なら修正点と次に試すことを整理する。

問題が起きていなくても、改造結果を確認してほしい場合に使えます。問題への対応もレビューも必要なければ、利用は不要です。3回目専用の講義・記事・動画はあらかじめ作らず、本人の改造結果と、使い方編・改造編の該当箇所を使って進めます。

使い方で止まっている場合はそこから確認し、相談のために先にAIで何度も失敗することは求めません。予備枠でも解消できなかった場合は、残った問題と原因、次の扱いを記録します。

案内では、例えば次のように伝えます。

> 最初は教材の説明と使い方を一緒に確認し、2回目はAIを使って自分の目的に合わせて改造する方法を試します。使い方をつかめて時間も取れる場合は、初回を延長して改造まで進められます。3回目は、まだ分からないことや不安が残った場合の相談、または改造した結果を一緒に確認するための予備として用意しています。記事や動画はいつでも見返せます。

予約方法、利用期間、回の間の質問窓口と対応範囲、費用、不具合の扱いは、提供前に具体化します。初回で進められても、案内した残りの相談機会は維持します。全3回の利用を、学習達成の条件にはしません。

## 当面の制作範囲

アプリ教材で最初に完成させる単位は、**共通のDevin基本操作編と、一つの教材の使い方編・改造編の記事・動画・進行メモ**です。動く教材、必要な教材ではOpenAI APIの接続案内、各回の後に読み返す案内を揃えます。

制作は、選んだ教材を使ってDevin基本操作の流れを確認し、基本操作編と教材の使い方編を用意してから、同じ教材の小さな変更を題材に改造編を作ります。受講者への提示順は本人の状況に合わせます。業務自動化の資料では、Cursorへの依頼と結果確認を扱います。

次に決めるのは「誰の、どの教材の使い方から作るか」と「その教材で最初に試す改造」です。それが決まったら、まず手順を通し、その結果から記事と動画を作ります。各制作物の完成状況と、実際のサポートでの検証状況は分けて管理します。

## 補足：Windowsで必要な場合の保存先と解凍方法

Cursorで手元の業務ファイルを扱う場合や、教材をPCで参照・保存する場合の補足です。Devinでアプリ教材を取得・改造する標準の導入では、この手順は不要です。

**ZIPはWindowsの「ダウンロード」に保存し、解凍後の教材は「ドキュメント」の中の「教材」フォルダーに置く**方法をおすすめとして案内します。PCに保存する場合の説明では、この保存先を使います。

1. 上記の教材リポジトリを開き、「Code」→「Download ZIP」を選びます。
2. ZIPファイルを「ダウンロード」に保存します。保存先を聞かれずにダウンロードされた場合は、ブラウザーのダウンロード履歴から保存場所を確認します。
3. エクスプローラーで「ドキュメント」を開き、「教材」という名前のフォルダーを作ります。
4. ダウンロードしたZIPを右クリックし、「すべて展開」を選びます。
5. 展開先を「ドキュメント → 教材」に指定して、展開します。展開先の入力欄にZIP名のフォルダーが自動で付いている場合も、ここでは「教材」フォルダーを指定します。
6. 「ドキュメント → 教材」にできた教材フォルダーを開きます。以後は、この解凍後のフォルダー内の教材を使います。

保存先の例です。ZIP名と展開後のフォルダー名は、ダウンロードしたブランチなどによって変わります。

```text
ダウンロード
└ ai-app-learning-main.zip       ← ダウンロードしたZIP

ドキュメント
└ 教材
   └ ai-app-learning-main        ← 解凍後、実際に使うフォルダー
```

Windowsの画面では「ダウンロード」「ドキュメント」という表示を目印にします。英語表記はそれぞれ「Downloads」「Documents」です。実際の保存場所はPCの設定によって異なるため、固定の絶対パスを入力する手順にはしません。

記事・動画では、**ZIPを開いて中身を表示することと、「すべて展開」で解凍することの違い**も示します。最後に、解凍後のフォルダー内に `README.md` と `src` フォルダーが見えることを確認し、選んだ教材の使い方へ進みます。
