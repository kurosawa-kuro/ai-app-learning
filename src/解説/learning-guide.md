# AIと学ぶ共通ガイド

[入門ガイド](README.md)で選んだ課題を、小さく試して確かめるための手引きです。必要なところから使ってください。具体的な起動方法や操作は、選んだ教材の手順に従います。

## やりたいことを小さな作業に分ける

最初に「誰の、何を楽にしたいか」「どんな結果ならうれしいか」を一文にします。その後、入力・作業・出力・確認に分け、最初の一つだけを試します。

例えば「毎月の集計を楽にしたい」なら、最初は架空の3行の金額を合計するだけにします。100円・200円・300円なら期待値は600円です。分類別の集計や見た目の整備は、この確認ができてから考えます。

AIには、次のように依頼できます。

> 架空の3行の表で、金額の合計を出したいです。元ファイルは変更・移動・削除せず、コピーを作って作業してください。まず、必要な作業を小さく分け、最初の一つと確認方法を説明してください。期待する合計は600円です。追加の機能はまだ不要です。

説明が難しいときは「専門用語を言い換えて」「一つずつ操作を説明して」「身近な例を使って」と伝えます。分からない指示を、そのまま実行する必要はありません。

## 試す前に戻せる状態を作る

1. 練習用のファイルやアプリを用意し、架空のデータを使います。
2. 変更前のコピーや版を保存し、どれが元の状態か分かる名前を付けます。
3. 変更する箇所を一つに絞り、期待する結果を先にメモします。
4. 今回の変更を戻す方法を、教材の手順や提供者と確認します。

ファイルだけでなく保存データも変える場合は、データを戻す方法も別に確認します。コードを戻しても、書き換えたデータが自動で元に戻るとは限りません。戻し方が分からない段階では、その変更を進めず相談します。

## AIの結果を確かめる

「AIが正しいと言った」だけでは確認を終えません。自分で答えを確かめられる小さな例で、予想と実際を比べます。

| 対象 | 確認の例 |
|---|---|
| アプリの表示変更 | 指定した文言が変わったか。変更前に動いた操作も引き続き使えるか |
| 計算や集計 | 手計算の結果と合うか。空欄・0・対象外の行を、決めたルールどおり扱っているか |
| Javaの処理 | 入力を変えたときも予想どおりの出力か。修正した処理の意味を説明できるか |
| 学習問題の採点 | 自分で確認した正答・誤答に対する判定と解説が、信頼できる教材と一致するか |

確認した入力・期待値・実際の結果を短く残します。一つの例で動いたら、次に別の入力でも試します。確かめた範囲を超えて「全部正しい」と判断しないことが大切です。

## うまくいかなかったとき

動かないコード、意図と違う変更、修正による別の不具合も、学習中に起こり得ます。それだけで「自分には無理」と決める必要はありません。

まず、追加の修正を止め、次の情報を整理します。エラー文や画面を共有する前に、氏名・メールアドレス・接続情報・秘密キーなどを取り除きます。

```text
やりたいこと：
使っている教材・版・環境：
直前に変更したこと：
試した操作・架空の入力：
期待した結果：
実際の結果：
エラーメッセージ（秘密情報は除く）：
すでに試したこと：

原因の候補と、最初に確かめることを一つ説明してください。
修正が必要なら、小さな変更案と、確認方法・戻し方を示してください。
```

修正を試したら、直した箇所と、以前は動いていた操作の両方を確認します。同じ失敗を繰り返す、別の箇所が壊れる、変更の意味が分からなくなる場合は、事前に決めた手順で最後に動いた状態へ戻します。戻せない場合やデータに影響がある場合は、そこで止めて[人に相談](support-guide.md#人に相談する目安)します。

最後に「何が原因だったか」「何を試したか」「次は何を確認するか」を一言ずつ残せば、失敗も次の学習に使えます。教材や環境の不具合は、本人の理解不足とは分けて扱います。

## 目的別の到達チェック

これは試験ではなく、次の課題を選ぶための目安です。「説明を読んだ」「支援付きでできた」「自分でできた」「別の条件でもできた」を分けて記録します。まだできない項目があれば、その一つを次に試せます。

| 入口 | 初回に確かめること | 次へ進む目安 |
|---|---|---|
| アプリ学習 | 希望した小さな変更をAIに依頼し、変更前後の動作を比較できた | 変更の意味を大まかに説明できる。不具合を伝えられる。自分で考えた小さな変更を試して結果を確認できる |
| Javaの資格・実務学習 | サンプルを実行し、出力の変更を確認できた | 学んだ範囲の短い処理を、AIの完成コードを写さず自力で修正し、理由と結果を説明できる。SQLを学ぶ場合も小さな修正と結果確認を行う |
| 事務作業の自動化 | 架空データを処理し、期待値との一致と元ファイルの保全を確認できた | 入力・集計条件・出力を指定し、別の架空データでも結果を確かめられる。誤りがあれば修正を依頼できる |

非エンジニアのアプリ利用や事務作業では、コードを一行ずつ説明することを一律に求めません。Javaの資格知識と実務技能も、別々に確かめます。

初回の成果は「本人の希望を伝え、AIと試し、結果を比べたこと」です。その後に自分で課題を決める段階では、「目的を一文にする」「作業を小さく分ける」「期待する結果を決める」「結果を確かめて次の行動を選ぶ」ができるかを振り返ります。人に相談できることも、その力の一部です。

## 英語学習アプリを資格学習へ応用する例

例えば「資格の用語を一つ、自分の言葉で説明できるようになりたい」という目的を立てます。出題・回答・採点・振り返りの流れを再利用し、扱う知識と判定の基準を変えてみましょう。

これは任意の改造課題です。英単語暗記、正答率集計、苦手問題の自動復習などが、既存教材にすべて備わっているという意味ではありません。利用する版の機能を確認してから変更を決めます。

| 段階 | 再利用・変更するもの | 確かめること |
|---|---|---|
| 1問だけ置き換える | 出題・回答の流れを使い、自作の資格用語問題に変える | 問題が表示され、回答できる。元の練習環境は残っている |
| 採点基準を変える | 英語表現の評価から、用語の理解を確かめる基準に変える | 用意した正答・誤答・一部だけ正しい回答の判定と解説を照合する |
| 振り返って使う | 利用する版にある振り返り・履歴の仕組みを確認し、活用する | 問題と回答の対応をたどり、自分が何を間違えたか分かる |
| 必要な機能を選ぶ | 正答率の集計や苦手問題の復習を、必要なら一つずつ追加する | 少数の既知の回答から、計算結果や復習対象を確かめる |

AIへの最初の依頼例です。

> この英語学習アプリを、資格用語の学習に使いたいです。まず現在の機能を確認し、再利用できる部分を説明してください。練習用のコピーで、私が用意する1問だけを出題・回答できるようにする変更案を示してください。採点基準の変更は次の作業に分けます。今回の確認方法と、元に戻す方法も説明してください。

問題・正答・解説は、自分で作成したものや利用許可のある資料を使います。採点基準を変えるときは、確認済みの正答例・誤答例と、その判定理由を渡します。AIの採点と解説は、信頼できる教材と照合し、判断できないものは保留して詳しい人に確認します。

慣れたら、架空の社内研修や業務マニュアルの理解確認にも応用できます。どの場合も、題材だけでなく正誤の基準と確認方法を見直します。実際の業務情報を扱う場合は、利用の許可と共有範囲の確認が先です。

これらは受講者が選べる応用の例です。資格学習用などの完成アプリを追加配布する約束や、初回サポートに含まれる作業ではありません。

## AIに渡す情報と、実務で使う前の確認

練習には架空のデータを使います。パスワード、秘密キー、個人情報、顧客情報、許可されていない業務資料はAIに渡しません。名前だけを消しても、内容から人物や取引先が分かる場合があります。迷ったら、その情報を送らず相談してください。

AIの出力は、内容と影響を確認してから使います。実際のファイルの一括処理、メール送信、外部公開などへ進む前に、練習用のコピーや下書きで結果を確認し、必要な許可を得ます。
