## 結論：Java × Oracleの選択には、教育戦略として明確な合理性があります

> 2026-10-28 方針更新：プログラムコードについての質問・改造はDevin、作成したプログラムからのAI問い合わせはOpenAI API、業務自動化の質問・作業はCursor。教材アプリのGemini採用は廃止する。本人によるコード・SQLの理解と自力修正を確かめる学習方針は維持する。 判断の正本は[AIの役割分担（ADR 0003）](../../docs/adr/0003-ai-service-roles.md)。

今回の目的を整理すると、3つの価値があります。

1. Java：企業開発で評価される静的型付け・オブジェクト指向・アーキテクチャ設計を学ぶ。

という成長経路を作れるわけです。

特に、初学者が最初から良いコードに触れることを重視するのであれば、JavaとClean Architectureの組み合わせには十分な意味があります。

## 4. 破綻条件

注意したい点は2つです。

第一に、Clean ArchitectureやDDDが難しすぎて、初学者がJavaの基本構文さえ理解できなくなることです。

対策として、テンプレートの設計品質は高く維持しつつ、教材の解説順序を段階化します。初めはControllerとUseCaseを追い、次にDomain、Repository、依存性逆転を理解するようにします。

第二に、Oracle固有の知識と、汎用的なRDB設計を混同しないことです。

Oracleを主DBにすることには賛成ですが、テーブル設計、正規化、トランザクションなどの共通知識と、Oracle固有の運用・SQL構文は区別して教えるべきです。

## 3. なぜJava・Oracle Bronzeなのか

### 3.1 Java Bronze

Java Bronzeは、Javaの基本文法やオブジェクト指向の入門知識を習得する入口となる。

主な学習対象：

- 変数・データ型
- 条件分岐・繰り返し
- クラス・オブジェクト
- メソッド
- 継承・カプセル化の基礎
- Javaプログラムの実行構造

これらの知識は、そのままSpring Bootを用いた業務アプリケーション開発に接続できる。

### 3.2 Oracle Database Bronze

Oracle Database Bronze DBAは、データベースの基本構造や管理・運用を理解するための入口となる。

主な学習対象：

- RDBの基本構造
- Oracle Databaseのアーキテクチャ
- インスタンス・データベース管理
- ユーザー・権限管理
- データベース運用の基礎

**注意：Oracle Bronze DBAはSQL開発力を直接証明する資格ではない。**

Java開発への接続を重視するなら、資格学習と並行して次のSQL実習を行う。

- SELECT / INSERT / UPDATE / DELETE
- JOIN / GROUP BY
- テーブル設計
- 主キー・外部キー
- トランザクション
- JDBCによるDB接続

これにより、Java・Oracle両方の知識を一つのアプリケーションに結び付けられる。

## 4. Devinを利用する意味

### 従来の資格学習

教材を読む → 問題を解く → 暗記する → 資格取得 → 入社後に実務を学ぶ

### Devin環境での資格学習

教材を読む → Devinで動作を確認する → コードを読む → 自分で修正する → テストする → 資格取得 → 次の実務技術へ発展する

### Devinの役割

Devinは単なるコード生成ツールとしてではなく、**実装例・課題・検証・レビューを提供する学習支援環境**として活用する。

具体的には以下を担当させる。

1. 学習テーマに沿ったサンプルコードの作成
2. Java・SQLの実行環境構築支援
3. コードの挙動や構造の説明
4. 段階別の演習課題作成
5. テストコードの作成支援
6. エラーの再現と原因解説
7. 学習者のコードレビュー
8. GitHubへの学習履歴整理

### 人間が必ず行うこと

- コードを読み、処理を説明する
- Devinの実装を一部変更する
- SQLを自力で記述する
- 発生したエラーの原因を考える
- 自分でテストを実行する
- Devinなしで小さな修正を再現する

**Devinが作れたことと、本人が習得したことを混同しない。**

4. **実績の可視化**：資格＋GitHub成果物＋自力での課題解決履歴
5. **将来の選択肢**：開発・保守・運用・クラウドへの発展

### 費用対効果の考え方

投資対象は、資格受験料、教材費、Devin利用料、学習時間。

リターンは、資格手当や資格そのものの評価だけで測定しない。

**応募可能な案件数、書類選考・面接通過率、採用後の立ち上がり時間、配属後に任される業務範囲**を指標にする。

現時点でこの育成方式の採用率改善や給与上昇幅を保証するデータはないため、まずは小規模に検証する。

## 9. 破綻条件

### 9.1 Devinへの過度な依存

AIが実装しただけで、本人が内容を理解していない。

**対策：** 各PhaseでAIを使わない実装・修正課題を設ける。

### 9.2 資格取得が目的化する

資格は取得したが、Git・SQL・実装・テストを扱えない。

**対策：** 資格学習と成果物の作成を同時に進める。

### 9.3 対象企業との不一致

Java・Oracleを使わない企業では、特化学習の採用上の優位性が低下する。

**対策：** Java・Oracleを使う業務システム開発・保守企業を優先対象とする。

### 9.4 学習領域の拡散

Java、Oracle、Spring Boot、LPIC、AWSを同時並行で学び、どれも習得できない。

**対策：** Java・SQLの基礎を最優先し、次の段階へ進む条件を設定する。

### 9.5 Bronze資格の過大評価

Bronze資格は基礎知識の証明であり、実務能力や独立した開発能力の保証ではない。

**対策：** 資格と実習成果物をセットで提示する。

## 10. 実行方針

### Java・Oracle系の仕事を目指す場合の到達目標例

**Java Bronze＋Oracle Databaseの基礎＋SQL実習＋GitHub成果物**

Java・SQLの基本が理解でき、簡単な業務処理を自分で修正できるところを、該当する仕事へ向けた目標とする。初回のAI並走支援は、小さな1課題で区切り、この到達までの支援を自動的に含めない。

### 評価方法

以下は資格・実務学習を続ける場合の確認候補。選んだ課題に必要な項目を確認し、次に何を学ぶかは本人の目的から決める。すべてを初回成功やプログラマーになるための条件にしない。

## 11. 最終的な戦略評価

この戦略で重視するのは、学習する知識の量ではない。

**企業側が必要とする能力を、最小限の投資で獲得し、その能力を起点に次の学習へ進める構造である。**

Java Bronze・Oracle Bronzeは、あくまで最初の入口となる。

そこからSpring Boot、Linux、AWSへと連続的に発展させることで、業務アプリケーションの開発から運用までを段階的に学べる。

### 戦略の核心

**「広く学んでから仕事を探す」のではなく、「最初に狙う仕事を定め、その仕事に必要な技能を習得し、実務に近い成果物を作りながら成長する」。**

この構造なら、資格取得後も本人の努力と改善を積み上げ続けられる。

IT未経験者の育成戦略として、対象企業を適切に絞れば、十分に検証する価値がある。
