# 横展開前に解消する課題

更新日：2026-10-27。対象：このSpring Bootスターターテンプレート。

本書は今後の改修課題であり、実装済み仕様や公開環境の動作保証ではない。現行仕様は[README](../README.md)・[テンプレート仕様](../テンプレート仕様.md)、構造は[アーキテクチャ](architecture.md)を参照する。

## 目的と優先度

利用者が自分で内容を修正でき、失敗から復旧でき、提供者が毎回DB操作や原因調査を代行しなくて済む土台にする。提供者の支援は合意した課題・回数・期間で終了できるようにし、新機能の追加を無期限のフォローにしない。

- **P0**：継続利用するアプリへ横展開する前に解消する課題。公開範囲の制御は、外部公開する前の必須条件。
- **P1**：共通テンプレートとして優先的に整える課題。画像中心のアプリへ展開する場合、画像UIはその展開の受入条件とする。
- 「一部実装」は残課題がある状態。コード、隔離テスト、実際の対象環境での確認を分けて記録する。

これは提供者側の品質要件である。学習者に全機能・全技術の学習を要求しない。本人に意味のある一つの課題で、AIへの依頼・試行・結果確認を経験できることを初回の成功とする。

## P0：横展開の前提

| ID／課題 | 現状と問題 | 最小限の対応 | 完了条件 |
|---|---|---|---|
| P0-01 投稿編集・画像差し替え | 作成・閲覧・削除はあるが、保存済み投稿の編集は未実装。訂正に削除・再投稿が必要 | タイトル・本文の編集と、画像の維持・差し替え・解除を用意。失敗時は元データを保持 | 本文のみ変更、画像差し替え・解除を操作できる。DB／Storage失敗時は旧投稿・旧画像を維持し、再試行できる |
| P0-02 ユーザー情報の編集 | アイコン変更はあるが、表示名を編集する画面はない。名前の変更を提供者へ依頼する必要がある | 管理画面から表示名を変更。ID・投稿との関係・アイコン・既定ユーザーを維持 | 一覧・詳細・選択メニューへ変更が反映される。空欄・文字数超過を拒否し、失敗時に入力を保持 |
| P0-03 バックアップと復元 | CSVは投稿・ユーザーの出力用。画像・設定を含む完全復元はできず、復元手順の検証も不足 | DB・画像・設定を対象とするバックアップ範囲、取得手順、保存先、復元手順を定義。秘密情報は別管理 | 独立した検証環境へ復元し、件数・投稿とユーザーの対応・画像・設定が戻ることを確認。所要時間と復旧可能な時点を記録 |
| P0-04 障害を判断できる状態表示 | 未設定表示や操作時エラーはあるが、DB／Storageの状態をまとめて判断できない | 管理画面に、未設定・機能禁止・接続失敗・正常を区別した状態と最終確認時刻、次の操作を表示 | DB接続失敗、Storage未設定／失敗、画像禁止を別々に再現し、原因と対処が判別できる。キー・パスワード・内部応答を表示しない |
| P0-05 画像処理の再試行と整合性確認 | アイコン・シードの削除待ちキューと `seed-cleanup` は実装済み。管理画面の再試行導線はなく、投稿作成時の補償削除失敗はログ対応 | 保留件数・処理結果・再試行を管理画面に用意し、補償処理を共通化。参照中画像と孤立画像、元ファイル欠損を区別 | 障害復旧後の再試行で保留を解消。繰り返しても参照中画像を削除しない。元画像が失われた場合は再アップロード等の対処を示し、自動復旧可能と誤表示しない |
| P0-06 環境の取り違え防止 | テスト用スキーマ分離・シードの許可スキーマ制限はあるが、画面上の環境識別が不足 | 管理画面に開発／検証／公開環境と、秘密情報を含まない接続先の識別名を表示。破壊的シードの実行条件を明確化 | 実際の接続先と表示が一致する。本番相当環境では意図しない `seed-reset` が拒否され、通常起動でシードを投入しない |
| P0-07 公開範囲の制御 | ログインは意図的に未実装。ローカルでは127.0.0.1に限定しているが、管理画面という名前に権限制御の意味はない | 用途ごとにローカル限定・ネットワーク制限・外部認証等を選び、閲覧・変更可能な範囲を決める | 公開先で許可していない接続から投稿・管理操作に到達できないことを確認。独自ログインの実装を一律必須にしない |

## P1：共通テンプレートとして整える機能

| ID／課題 | 現状と最小限の対応 | 完了条件 |
|---|---|---|
| P1-01 画像前提の一覧・詳細UI | 現状は表とサムネイル。[画像投稿UI改善案](image-post-ui-plan.md)に従い、カード型フィード・画像拡大・縦横比維持・読込状態を整える | 画像あり／なし、縦長／横長、図・文字入り画像、長文が混在してもPC・スマホで読める。画像を勝手に切り抜かない |
| P1-02 検索・並び替え | 投稿者絞込み・ページャー・固定の日時順はある。タイトル／本文の検索と並び替え操作を追加 | 検索・投稿者・並び順をページ移動でも維持し、条件変更時は先頭へ戻る。0件時に解除・再検索できる |
| P1-03 未保存変更の保護 | 投稿送信失敗時の入力保持は一部対応済み。編集中の離脱確認が不足 | 変更した入力がある場合に離脱確認し、保存成功後は不要な確認を出さない。失敗時に本文と画像選択を保持できる範囲を明記 |
| P1-04 サーバー側の二重登録防止 | ブラウザーの保存中ボタン無効化はあるが、通信断後の再送まで重複防止を保証していない | 同一操作の識別子等を用い、応答だけ失われた後の再送でも投稿・画像を重複作成しない。異なる新規投稿は正しく登録 |
| P1-05 操作結果を追える記録 | 個別のログはあるが、管理操作と障害の調査に必要な記録が整理されていない | 設定変更・保存失敗・画像処理失敗の日時、操作、結果、照会用IDを記録。秘密情報・本文・画像を不用意に記録しない。認証なしの選択ユーザーを本人確認済みの実行者として扱わない |
| P1-06 シードと受入確認の一体化 | 12投稿・2枚の画像、複数ページ、画像補完、実アプリの確認スクリプトは対応済み。縦長画像・読込失敗・空状態等の組合せが不足 | 下記のケースを再現できるデータと確認手順を用意。コードだけでなく対象環境へのデータ反映と実表示を確認 |

## シードは機能を試せる状態を作る

「ページャーがあるが1ページ分しかない」「画像対応だが画像が入っていない」という状態を防ぐ。画像許可ONと、投稿に画像が保存済みであることを区別する。

| ケース | 現状／残課題 |
|---|---|
| 複数ページ・最後の端数ページ | 対応済み：シード12件。1ページ10件を超え、前後移動を確認できる |
| 画像あり・画像なし・短文・長文 | 対応済み：2枚の横長サンプル図と文章の混在。不足画像は `seed-images` で補完可能 |
| 縦長・横長・正方形・文字入り画像 | 追加課題：切抜きや縦長占有、拡大時の読みやすさを確認する組合せ |
| 画像読込中・失敗・元画像欠損 | 追加課題：テスト用環境で遅延・失敗を再現。既存利用者の画像は壊さない |
| 投稿0件・検索0件・画像なし | 空状態用の独立した検証条件を用意。全削除で日常データを作り直さない |
| ユーザー独自投稿との共存 | 維持：追加シードは不足する固定IDだけを追加。本文・既存画像・ユーザー投稿を上書きしない |

実データの検証では、実行前後の件数・追加／削除数・画像の取得とデコード・PC／スマホの画面を確認する。共有DBへ入れたデータと隔離テスト内のデータを混同しない。

## 着手順

1. **P0-01・02**：投稿編集とユーザー名編集を実装し、日常の訂正をアプリ内で完結させる。
2. **P1-01・06**：画像UIとシードを一緒に整える。先に検証用の画像・文章を用意して画面を評価する。
3. **P0-04・05・03**：状態確認、再試行、バックアップ／復元を整え、提供者の直接介入を減らす。
4. **P0-06・07**：環境と公開範囲を確認して横展開する。外部公開を先に行う場合は、この確認も前倒しする。
5. **残るP1**：用途に合わせて検索、未保存変更の保護、二重登録防止、操作記録を整える。

各課題の実装時は、対象・変更範囲・失敗時の挙動・確認方法を作業記録に具体化する。実装後に現行仕様へ反映し、本書に検証日と証跡へのリンクを残す。仕様の合意だけで課題を完了扱いにしない。

## 現段階の共通必須にしないもの

- AI処理本体、外部AIとの接続、実利用額の集計。
- アプリ固有のCSVインポート。
- 独自ログイン・パスワード管理。
- 複数画像投稿、写真検索用グリッド、ゲーム等への投稿フィードの一律適用。

これらは用途が決まってから別課題とする。既存のAI許可設定・ダミー金額表示を、実AI処理・実課金集計の完成とは扱わない。
