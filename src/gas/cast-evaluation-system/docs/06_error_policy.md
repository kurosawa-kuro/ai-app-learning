# 06 エラー方針

根拠: [基本仕様・設計 v0.3.0（Draft）](<tasks/01_idea/Cast Evaluation System — 基本仕様・設計.md>) §6、§7、§11。正本を優先し、以下は実装・運用準備のための文書とする。実施済み・受入済みの記録ではない。

## 正本で定義されている制約

管理者のみアクセス可能とし、サーバー側で入力を検証する。営業実績は0以上の整数（売上は整数円）、同一営業日・キャストの重複は禁止。同時更新の排他制御を設け、GASの実行制限を考慮する。

正本はエラーコード・表示文言・再試行回数・ログ保持期間・競合時のUIを定義していない。以下はこれらの要件を満たすための**詳細設計案**であり、実装時に確定して受入ケースへ反映する。

## エラー分類と対応案

| 分類 | 例 | 対応案 |
|---|---|---|
| 入力不正 | 負数、小数の実績、不正な日付・ID | 保存せず、修正対象を示す。クライアント検証だけに依存しない |
| 重複 | 同じ営業日・キャストの新規登録 | 新規追加を拒否し、登録済み実績の確認・編集へ案内する |
| 権限不足 | 管理者以外の利用、認可不備 | データを返さず操作を拒否。権限設定を確認する |
| 同時更新 | ロック取得不可、競合 | 保存完了と表示せず、現在値を確認して再操作する |
| ルール不整合 | unit=0、category欠損・重複、型不正 | 誤ったポイントを確定表示せず、設定確認へ案内する |
| 接続・実行失敗 | Sheetsアクセス不可、実行制限、通信失敗 | 成功と見せず失敗を通知。保存の成否を照合する |

ルール不整合の許容範囲・拒否条件、存在しないmember_idの扱い等は [未決事項](00_index.md#未決事項) として決定する。数量の端数計算を入力不正と混同しない。

## 再試行・保存成否の案

通信失敗だけでは、サーバーで保存されなかったとは断定できない。再読込でrecord_idや営業日・キャストに対応する現状を確認し、重複登録を避ける。書き込みの無条件な自動再試行は前提にしない。

実際の再試行可否、待機時間、ロック解放方法、部分更新時の復旧は実装時に決定する。初期構成にキューや複雑な再試行基盤を追加する要件はない。

## 記録・調査

秘密情報や不要な個人情報をログに出さない。運用時の調査記録案は、発生日時、操作、対象環境、再現条件、保存成否、対応結果とする。公開文書やテスト証跡では実データ・認証情報を伏せる。

ログ出力先・保持期間・閲覧権限は未決定。高度な監査基盤を実装済みとみなさない。障害対応で確定した手順は [リリースRunbook](08_release_runbook.md)、回帰条件は [テスト戦略](07_test_strategy.md) に反映する。
