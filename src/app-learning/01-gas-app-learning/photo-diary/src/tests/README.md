# テストの目的と実行方法

`src/` で `npm test` を実行する。設定を生成してから全 `*.test.mjs` を実行する。
生成物を書き換えずに一括検証したい場合は `npm run check`、画面のブラウザ検証は `npm run test:browser`。
特定の障害テストだけなら `node --test tests/resilience.test.mjs`。
通常のテストでは実OpenAI・Drive・Sheetsへ接続しない。

## 何を検証するか

Domain / Applicationの独立テストは `domain-application.test.mjs`。GAS模擬環境を読み込まず、純粋な判断と注入した保存先・時計等で動く処理を検証する。`architecture.test.mjs` で依存方向も検査する。

| 領域 | 主なファイル | 検証内容 |
|---|---|---|
| DB・移行 | database-v2.test.mjs | 要求の照合、部分保存の回復、移行中断・再開、旧データ保全 |
| 障害・再送 | resilience.test.mjs | 台帳・子・親の書込前後8パターン、部分保存の中止、競合時の無変更、Drive作成の応答喪失 |
| AI | openai-*.test.mjs / resilience.test.mjs | 応答形式・失敗分類、ロック外の生成、処理中の同一要求、結果保存失敗後の再課金防止 |
| 保持期間・キャッシュ | resilience.test.mjs | 15分・30日・6時間の境界、手動整理後の採用済み日記保全、キャッシュ停止時の読書き |
| 画像 | uploads.test.mjs / resilience.test.mjs | 添付順序・上限、再送、参照中の整理拒否、アップロード後の共有状態・所属・削除の再検証 |
| 画面 | ui.test.mjs / upload-ui.test.mjs | 入力保持、古い応答の排除、保存・生成の応答喪失、失敗画像の再送 |

| 模擬環境 | harness.test.mjs | 時刻の独立性、ロック競合・解放、キャッシュTTL・UTF-8容量 |

## 障害テストの書き方

- 毎回新しい `createGas()` / `driveGas()` を作り、状態を共有しない。
- 時間に依存する検証は `createGas({ now: "2026-10-01T00:00:00Z" })` と `gas.clock.advance(ms)` を使う。実時間のsleepに頼らない。
- `failure-helpers.mjs` の `failNextWrite` は実際の模擬シートの `setValues` 前後で1回だけ例外を発生させる。対象の書込が発生したことも `fired` で確認する。
- 失敗応答だけで終わらせず、同じ要求の再送、一覧・詳細、台帳状態、親子の件数・参照・順序まで確認する。
- ロック競合は `gas.lock.held = true` で再現する。失敗した呼出が別の実行のロックを解放しないことも確認する。
- テスト対象の業務処理を丸ごと成功するスタブへ置き換えない。AI応答等の外部境界を置き換え、予約・検証・保存は本来の処理を通す。

## 模擬環境の限界

Node VMはGASサーバー全体を実行するが、実GASではない。ロック競合は状態と処理への割込みで再現しており、並列プロセスやロック待機時間を再現しない。
Sheetsの数値変換・一部の書式・行操作だけを模擬する。数式、権限、ネットワーク遅延、GASの実行時間制限は対象外。
キャッシュはTTLと容量を再現するが、サービス側の早期破棄は自動発生しない。必要なテストでは明示的に消す。
Driveの画像は固定作例で、共有・所属・削除状態を模擬する。実Googleアカウントの権限は確認できない。
30日の保持期間は現在の実装に合わせ、ちょうど30日では保持し、30日を超えた履歴を手動整理の対象にする。
ブラウザテストもローカルの通信代替を使う。公開URL、スマホ実機、実画像の回転・縮小、実APIの品質と応答時間は別途確認が必要。
