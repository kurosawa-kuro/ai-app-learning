# 写真日記：GASとWebの基本機能を揃える

2026-10-28。写真・タグ・AI下書き・本人の手直し・保存・一覧・詳細を基本体験とする。保存済み日記の編集・削除やSNSは追加しない。

| 項目 | 現行GAS仕様 |
|---|---|
| 新規入力 | タイトル120字・本文5000字・タグ5個・写真3枚。日記の日付は2000-01-01〜2100-12-31 |
| 日付 | `entryDate`を保存。DBの`v2_posts.entry_date`はYYYY-MM-DDの文字列。旧行の空値は作成日を表示 |
| タグと日記 | 既存の`v2_post_tags`で多対多。1日記に複数タグ、同じタグを複数日記へ |
| 一覧の絞込み | 複数タグのOR条件。選択タグのどれかを持つ日記を表示。全解除で全件 |
| タグ管理 | 名前1〜30字で追加、改名、未使用タグの削除。改名はIDを維持。使用中はサーバー側でも削除拒否 |
| 通信互換 | `getAll(tagId, cursor)`のtagIdは従来の1 IDも、カンマ区切りの複数IDも受付。選択変更でページ先頭へ戻る |
| 既存記録 | 保存済みの6タグ以上も削らず読める。日付を追加しても作成日時・本文・既存関連を変更しない |

タグの追加・改名・削除はロック内で参照確認して保存する。同名追加の再送は同じタグを返し、同名別IDへの改名は拒否する。管理更新後は一覧・詳細のキャッシュを失効する。

日記作成要求の内容照合には、日付指定時のみ`entryDate`を含める。旧要求の日付なしの内容照合を壊さない。日付を変えて同ID再送した場合は異内容として拒否する。

## 既存環境への反映

新コードの列定義は旧5列に`entry_date`を末尾追加した6列。`upgradeDiaryEntryDate`をエディタで明示実行する。旧5列と完全一致した場合だけヘッダーを追加し、既に6列なら何もしない。別の列構造は変更せず止める。**既存環境に新規Seederを実行しない。**

公開版更新と列追加は[Runbook](../08_release_runbook.md)に従う。コードpushとDB更新・公開受入は別で、現状は[横断実行記録](../../../../docs/tasks/gas-release-20261028.md)に記す。
