# Capability Boundary — photo-diary

[AGENTS.md](../../AGENTS.md) と [CLAUDE.md](../../CLAUDE.md) に基づく、このプロジェクトで扱う操作と資産。汎用の考え方は [アーキテクチャ](kurosawa-thin-harness-architecture.md) を参照する。

## 対象資産

- clasp / Google アカウントの認証情報。文書・ソース・生成物・ログへ混入させない。
- 既存の GAS スクリプト、デプロイ ID と公開 URL、本人のみの公開範囲。
- スプレッドシートの日記・関連行と、env/ の設定・マスター。試行用データという前提でも、通常更新で削除しない。

## 操作の境界

| 操作 | 対象と扱い |
|---|---|
| ローカル検索・文書編集・テスト | 依頼範囲で実行。npm は src/。Makefile を実装済みと扱わない |
| 設定データの生成 | env/ を入力にする。旧 data/ 参照は修復済み。generated.js は手で直さない |
| GAS ソースの送信 | npm run push は --force。対象・接続先を確認し、反映の依頼範囲で行う |
| 公開版更新 | npm run deploy で既存 ID を更新。テスト・push と公開後確認を省略しない |
| シート削除・再初期化・列変更 | 関連行・retiredSheets の影響と復旧方法を明確にする別作業 |
| 公開範囲・実行主体・接続先変更 | MYSELF / USER_DEPLOYING と既存接続先を変えるため、目的と依頼範囲を確認する |
| 実写真・実 AI の追加 | Drive写真・OpenAI下書きは実装・公開@20の主要操作確認済み。権限・秘密情報・通信・費用の変更は引き続き個別に扱う |

Doppler、IaC、SQL migration、外部通知、パッケージ公開は現アプリの運用手順ではない。他プロジェクト向けのツール一覧を実態として移植しない。

## 文書と強制設定の区別

この表は作業方針であり、ツールの allow / ask / deny 設定の実行結果を保証しない。実際の制御は利用環境と .claude/settings.json・hooks による。今回の docs 更新では settings / hooks を変更していない。設定の適用確認・調整は別作業とし、文書編集だけで権限が変わったと報告しない。

既存のユーザー承認・依頼範囲を考慮し、同じ操作の承認を重ねて要求しない。外部反映の依頼がない文書更新では push / deploy を行わない。
