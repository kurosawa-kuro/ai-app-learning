# Runtime Protocol — photo-diary

[README](../../README.md)・[CLAUDE](../../CLAUDE.md)・[AGENTS](../../AGENTS.md) を共通基準にする。Claude 固有 skills は必要な時に利用し、Codex が自動で読む前提にしない。

## 作業の流れ

1. 依頼の目的・対象・完了条件を確認する。
2. 基準文書と関連するコード・設定を確認する。過去のタスク記録を現在の検証結果に代用しない。
3. 小さな文書修正はそのまま進める。複数層にまたがる実装変更は task に範囲・手順・検証方法を記録する。
4. [変更境界](change-boundary.md) と [操作境界](capability-boundary.md) を確認して、依頼された変更を行う。
5. [検証方針](evidence-policy.md) と [テスト戦略](../07_test_strategy.md) に従って結果を確認する。
6. 変更・検証結果・未確認事項・外部反映の有無を報告する。

## 現在の作業上の注意

npm / clasp は src/ で実行する。Makefile はテンプレートで .git はない。生成処理・生成テストとも env/ 参照へ修復済み。2026-10-24 に全48テスト成功。公開画面の操作確認とは区別する。

範囲外の不整合は [候補一覧](../tasks/03_active/refactoring-candidates.md) に残し、独立して進められる依頼作業を完了する。検証失敗は原因・変更との関連・影響を調べる。証拠なしに PASS にせず、単に失敗回数が増えたという理由で必要な調査を打ち切らない。

## 確認が必要な場合

- 依頼されていない GAS への反映、シートの破壊的変更、公開範囲や実行主体の変更が必要になった場合。
- 既存のDrive・OpenAI連携を超える、権限・秘密情報・費用を伴う追加が必要な場合。
- 利用者に見える仕様の意味が不明で、既存の実装・基準文書でも解消できない場合。

既存の依頼と承認を引き継ぐ。確認は不明な対象・影響を具体化したうえで行う。承認済み範囲の可逆な修正や文書整合は自律で進める。実際のツール制約を迂回しない。
