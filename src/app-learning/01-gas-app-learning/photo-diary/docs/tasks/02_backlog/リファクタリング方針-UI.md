## 1. 結論

- **骨組みは変えず、「色の値」と「動き」だけを変える。** admin-pico のレイアウト・部品・HTML・画面の流れはそのまま使う
- **ただし、今の CSS は「色を 1 か所で替えれば全部変わる」状態になっていない**（2 章）。そこで第 1 弾は 2 段に分ける
  1. **色の直書きを変数（トークン）に寄せる。** この段では見た目を 1 ピクセルも変えない
  2. **トークンの値を新しい配色に差し替える。** 地の色を暗い色から明るい色に替え、役割の色を付け替える
- **第 2 弾のアニメーションは CSS だけで作る。** 動きは位置と透明度だけにし、端末の「視差効果を減らす」設定では止める

順番を守る理由：①を飛ばして色を替えると、直書きの暗い色・ライムが画面のあちこちに残り、配色がまだらになる。

## 2. 現状（2026-10-24 に調べた事実）

### 色の書き方

| ファイル | トークン経由の色 `var(--admin-*)` | 直書きの色（`#…`・`rgba()`・`hsl()`） |
|---|---|---|
| `client/vendor/admin-pico/admin-components.html` | 82 | **78** |
| `client/vendor/admin-pico/admin-theme.html` | 28 | 25（多くはトークンの定義そのもの） |
| `client/vendor/admin-pico/admin-layout.html` | 4 | 4 |
| `client/styles/components.html` | 25 | 6 |
| `client/styles/overrides.html` | 9 | 5 |
| `client/core/photo-view.html` | 0 | 5（ダミー写真の絵。写真の代わりなので配色の対象外） |

直書きの中身：

- **ライムとピンクの半透明**（`rgba(164, 255, 0, …)`・`rgba(255, 45, 143, …)`）が 19 か所。枠線・選択中・影に使われている
- **白の半透明**（`rgba(255, 255, 255, 0.02〜0.06)`）が多数。暗い面を少し明るく見せるためのもので、明るい地では意味が逆になる
- **カードやヒーローの背景のグラデーション**（`#1c2023` などの暗い色）。カードの写真の枠は今は写真で隠れている

### ダーク固定

- `client/index.html` の `<html data-theme="dark">`、`admin-theme.html` の `color-scheme: dark` で、暗い配色に固定している
- 明るい配色にするには、Pico の `data-theme` も明るい側に替える必要がある

### 色の役割（今）

| 役割 | 今の色 |
|---|---|
| 地・面・表 | 黒〜暗い灰色 |
| 操作・成功・選択中・フォーカス | ライム `#a4ff00` |
| 危険・必須・エラー | ピンク `#ff2d8f` |

**ピンクを主役の色にすると、「危険」と「かわいい」の区別がつかなくなる。** 危険の色は別に用意する（3 章）。

## 3. 目指す配色（第 1 弾）

### 方向

- **明るい白地に、写真が主役、温かいグラデーションをアクセントにする。** Instagram・Pinterest に共通する「写真が引き立つ明るい画面」と「ときめく差し色」を参考にする
- **各社のロゴ・固有のグラデーション・アイコンはそのまま写さない。** 参考にするのは雰囲気（明るさ・彩度・余白）までで、模倣にしない
- 管理画面らしい「無彩色の地」は保つ。色は操作・選択・キーワードに絞り、画面全体を派手にしない

### パレット（作戦の時点の案。**実際の値は 9 章**。コントラスト検査で一部を替えた）

| 役割 | 色（案） | 使う所 |
|---|---|---|
| 地 | ミルク白 `#FFF8FB` | 画面の背景 |
| 面 | 白 `#FFFFFF` | カード・フォーム・サイドバー |
| 線 | 淡いピンク灰 `#F1E4EC` | 枠・区切り |
| 文字 | 濃い紫灰 `#2B2233` | 本文・見出し |
| 補助の文字 | 紫灰 `#7A6F80` | 日付・説明 |
| **主役のアクセント** | ピンク → コーラル → 蜂蜜色のグラデーション（`#FF5C8A` → `#FF8A5B` → `#FFC15E`） | 主ボタン（日記を書く・保存する）・ブランドのマーク |
| 選択中 | ピンク `#FF5C8A`（淡い地 `#FFE3EC`） | 押したチップ・選んだ写真の枠と番号・サイドバーの現在地 |
| 差し色 | ラベンダー `#A78BFA`・ミント `#3CCFB4` | キーワードのチップの彩り・成功の通知 |
| **危険・必須・エラー** | 赤 `#E5484D`（淡い地 `#FDECEC`） | 「必須」の印・エラーの注意書き・入力の不備 |

## 5. 第 2 弾：アニメーション（案）

| 場所 | 動き | 長さの目安 |
|---|---|---|
| 画面の切り替え（一覧・詳細・作成） | ふわっと現れる（透明度＋少し下から） | 200ms |
| 一覧のカード | 読み込み後に、上から順に浮かび上がる（1 枚ずつ少し遅らせる。最初の 8 枚まで） | 1 枚 250ms、間隔 40ms |
| 写真・キーワードの選択 | 押すと少し沈み、選ぶとぽんと弾む | 150ms |
| 保存できたとき | 通知が下から現れ、小さなハートかきらめきが出る | 400ms |
| 読み込み中 | 「読み込み中…」の文字の代わりに、カードの形の下地がきらめく（スケルトン） | 繰り返し |
| AI 下書きが入ったとき | タイトルと本文がふわっと現れる | 300ms |

守ること：

- **動かすのは位置・大きさ・透明度だけ**（`transform`・`opacity`）。スマホでもカクつかせない
- **端末の「視差効果を減らす」設定（`prefers-reduced-motion`）では動きを止める**
- **操作を待たせない。** アニメーションの終わりを待たずに次の操作を受け付ける
- 外部のアニメーションライブラリは使わない（外への通信は Pico の CDN だけ、の約束のため）

第 2 弾は第 1 弾の段 3 のあとに着手する（動きの色・影は新しい配色に合わせるため）。

### フォントの計測（後回しにした理由）

Google Fonts の Zen Maru Gothic（400・700、`display=swap`）を、入れた場合と入れない場合で比べた（Chromium、スマホ幅、キャッシュなし、各 3 回、2026-10-24）。

| | 最初に文字が出るまで | 読み込みが終わるまで | フォントのデータ量 |
|---|---|---|---|
| なし | 204〜368ms | 206〜265ms | 0 |
| あり | 296〜328ms | 450〜685ms | 306〜409KB |

最初に文字が出る時間はほぼ同じだが、初回ごとに約 300〜400KB を余分に読み、読み込みの終わりが 0.2〜0.4 秒遅れ、フォントが届いたところで文字の形が切り替わる。GAS はもともと表示が重いので（旧メモ「GASの弱点」（現配置にファイルなし））、「遅くなるなら後回し」に当たると判断した。入れるなら、読み込みを表示の妨げにしない書き方（`media="print"` で読んで後から切り替える）と、使う文字だけに絞る指定（`text=`）を試してから計り直す。
