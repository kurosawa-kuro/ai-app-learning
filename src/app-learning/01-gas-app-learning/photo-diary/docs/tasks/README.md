## 状態と進め方

```text
01_idea → 02_backlog → 03_active → 04_verifying → 05_done
```

- idea は構想、backlog は未着手・判断待ち、active は実行中の作業と候補索引。
- verifying は実装と基本検証が済み、実機等の必要な結果の観測が残る場合に使う。
- done はそのタスクに必要な検証が完了した時。文書のみならリンク・内容確認で判定でき、GAS 公開確認を一律に要求しない。
- 不合格が見つかれば active に戻して経緯を記録する。移動前にリンクへの影響を確認する。
- 候補一覧に登録したことは着手・実装完了・外部反映の承認を意味しない。

作業開始時に目的・範囲・完了条件を確認する。実装タスクは必要に応じて個別ファイルに Goal / Context / Scope / Plan / Acceptance Criteria / Verification / Notes を記録する。中規模以上の構造変更では先に責務と検証方針を決める。

検証コマンドは [04](../04_workflows.md)、完了判定は [07](../07_test_strategy.md)。npm は src/ で実行し、Makefile や Git が使えると仮定しない。

確定仕様は 01〜08 または specs/、判断理由は [decision-log](../decisions/decision-log.md) に反映する。独立した ADR / runbook が必要になればディレクトリを作るが、現在の運用手順は [08](../08_release_runbook.md) に集約する。Claude 固有の再利用手順は .claude/skills/ に置き、共通規約は AGENTS.md に残す。
