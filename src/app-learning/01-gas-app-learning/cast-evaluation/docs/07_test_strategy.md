# 07 テスト戦略

根拠: [基本仕様・設計 v0.3.0（Draft）](<tasks/01_idea/Cast Evaluation System — 基本仕様・設計.md>) §5〜8、§11〜13、§16。正本を優先し、以下は実装・運用準備のための文書とする。実施済み・受入済みの記録ではない。

## 現状・証拠の区別

テストコード・テストランナー・実行コマンドは未整備。`make test` は雛形のメッセージ出力であり、合格の証拠にしない。以下は実装時に自動テスト・実機操作へ落とし込む検証計画。

| 検証層 | 確認内容 | 証拠 |
|---|---|---|
| 独立ロジック | 期間集計、計算式、有効／無効、順位 | 入力・期待値・実結果・実行コマンド |
| データアクセス結合 | 登録・編集・重複防止・退店後保持・一括読み書き | 検証用Sheetsの更新前後・再読込 |
| GAS実機 | 認証・認可、通信、保存、同時登録、3画面 | 対象版・権限・操作・画面と保存結果 |
| 実店舗運用 | スマホ操作、入力負担、既存業務との共存 | 操作観測・入力時間・継続率 |

モック成功だけでクラウド接続や公開成功としない。検証は店舗の本番実績を汚さない検証用データ・環境で準備する。

## 計算・状態の具体的ケース

以下の数値は正本の式から導いたテスト用期待値。配点は正本§7.2の仮設定を使う。

| ID | 条件 | 期待結果 |
|---|---|---|
| T01 | 月内合計：ドリンク10、ボトル2、指名3、同伴1、売上12,000円。SALES無効 | 10 + 10 + 9 + 5 = 34P。売上12,000円は表示 |
| T02 | T01でSALESを有効化 | floor(12000 / 10000) × 2 = 2Pを加算し36P |
| T03 | 別日の売上6,000円＋6,000円、SALES有効 | 期間合計12,000円で2P。日次切り捨ての合計0Pにしない |
| T04 | 売上9,999／10,000／19,999／20,000円 | 売上ポイント0／2／2／4P |
| T05 | 数量3、単位2、配点1の有効な数量ルール | 計算値1.5P。勝手に整数へ切り捨てない。表示精度は未決 |

| T08 | A:34P/12,000円、B:34P/15,000円、C:34P/15,000円、D:40P/0円 | D、B=C、Aの順。BとCは同順位。次の順位番号は未決 |

表示精度、同順位の次の番号、売上順表示時の順位欄など未決事項について、実装に合わせた期待値を後付けしない。

## 入力・永続化・権限

| ID | 条件 | 確認する性質 |
|---|---|---|
| D01 | メンバー登録・名前編集 | 一意IDが自動発行され、名前変更後もIDで実績を追跡できる |
| D02 | ACTIVE→INACTIVE | メンバー・過去実績を削除しない |
| D03 | 実績に負数・小数 | サーバー側で拒否。整数円・整数件数の制約を守る |
| D04 | 同一日・同一キャストを2回登録 | 1レコードを超えて増えない |
| D05 | 同一日・同一キャストを同時登録 | 排他制御により重複しない。応答の詳細は設計時に確定 |
| D06 | 登録済み実績を編集・再表示 | 新規重複を作らず更新値を確認できる |
| D07 | 管理者以外でアクセス | 画面だけでなくサーバー側の読書きも許可されない |
| D08 | データアクセスの検証 | 行番号を業務IDにせず、一括読み書きの設計が実装されている |
| D09 | 保存応答の喪失 | 現在値照合で成否を判定できるか検証。具体挙動はエラー詳細設計で確定 |

不正ルール・不明ID・空欄・不正日付等の期待挙動は [エラー方針](06_error_policy.md) の設計案を確定してから追加する。

## 初期検証KPI

| 指標 | 仮目標 | 測定計画 |
|---|---|---|
| 日次入力 | 全キャスト分5分以内 | 対象人数・操作開始終了・条件を記録 |
| 継続率 | 営業日の90%以上 | 観測期間の営業日数・登録状況を記録。全員登録を満たす日の定義等は事前に決定 |
| 計算整合性 | テストケース100%一致 | 採用したケース数・一致数・失敗内容を記録 |
| 既存業務の変更 | 原則不要 | POS・会計の変更有無と追加負担を記録 |

仮目標は実店舗で調整する。技術テスト成功と事業・運用仮説の成立は別々に評価する。
