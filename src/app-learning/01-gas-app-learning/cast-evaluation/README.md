# キャスト評価：GAS Create／Read版

まず **メンバー登録・一覧、日別実績の登録・一覧、配点の確認、月次集計・同点順位** まで動かし、Web版から引き算した比較教材を用意する。すべての機能・教材の修了を求めず、1つの登録と結果確認をAIと並走して経験する。

| 項目 | 現状 |
|---|---|
| GAS本体・Sheets保存コード | 実装済み（`src/`） |
| ローカルの保存・業務テスト | 7件成功 |
| PlaywrightのPC／スマホ操作 | 2ケース成功、スクリーンショット目視確認 |
| 実GAS配置・Sheets実接続・公開・コピー受入 | **未実施** |

ローカル検証はGAS APIを模擬したメモリ保存。実環境の動作保証とは分ける。

## まず試すこと

メンバーを追加し、ドリンク2・ボトル1・指名0・同伴0・売上12000円を保存すると **5.00 pt**。同じ人・同じ営業日の再登録は拒否する。

## 起動・テスト

このディレクトリで実行する。Node.jsはローカル検証用で、GAS実行には不要。Node 24で確認。

```bash
npm ci
npm test
npm run dev
# 別ターミナルではなく、devを止めてからブラウザテストを実行
npx playwright install chromium
npm run test:browser
npm run format:check
```

ローカル画面は `http://127.0.0.1:8192`。サーバー停止でメモリ内データは消える。GASへは[公開手順](docs/08_release_runbook.md)で配置する。Makefileの雛形は検証に使わない。

## 今回の境界

- 作成と読取りだけを先行する。名前・在籍状態の編集、実績編集、配点変更UIは今回未実装。
- 独自ログイン・AI・運用向け管理システムは持たない。架空データと本人限定のGAS公開設定で試す。
- 保存ID、入力検証、同じ要求の再送対策は保持する。ページを閉じた後の自動復旧までは扱わない。

## コードの読み方

| ファイル | 役割 |
|---|---|
| `src/application.js` | 表定義・初期データ・業務処理 |
| `src/store.js` | Sheetsの読取り・追記・初期化 |
| `src/web.js` | HTML配信と操作名を限定したRPC |
| `src/index.html` / `src/app.html` | 入力・結果表示 |
| `src/bridge.html` | 通信、送信中表示、再送ID |
| `src/style.html` / `src/pico.html` | 同梱Pico CSSとレイアウト |

共通の保存・通信・見た目の小さな実装を2教材で揃え、各アプリ単独で配置できる。外部の共通ランタイムは導入しない。
