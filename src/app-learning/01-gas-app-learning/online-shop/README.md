# online-shop

注文を扱う RDB の考え方を学ぶ、小規模な GAS 製 EC アプリ。ログインなしで事前登録した架空のユーザーを選び、単一店舗での商品選択・注文・履歴確認を扱う。

現在は設計段階。要件・設計の正は [ec-shop-gas のアイディア](docs/tasks/01_idea/ec-shop-gasのアイディア.md) とする。以下は実装予定の仕様であり、実装完了を示すものではない。

## ページと機能

| ページ | 主な機能 |
|---|---|
| 商品一覧 | 販売中の商品表示、カテゴリー絞り込み |
| 商品詳細 | 商品情報の確認、数量指定、カート追加 |
| カート | 数量変更・削除、参考合計の表示 |
| 注文確定 | 最新価格で内容確認、注文保存、同ページで完了表示 |
| 注文一覧 | 選択ユーザーの注文履歴表示 |
| 注文詳細 | 注文時点の明細・金額表示、注文全体のキャンセル |

カートは画面上で保持し、専用テーブルを設けない。再読み込みやタブを閉じると失われる。
ユーザー選択は本人確認ではなく、架空データを使う学習用の仕組みとする。

## データ設計と初期範囲

Google スプレッドシートで、1 テーブルを 1 シートとして再現する。

| シート | 役割 |
|---|---|
| `users` | 事前登録ユーザー |
| `products` | 商品名・現在価格・販売状態 |
| `categories` | カテゴリー |
| `product_categories` | 商品とカテゴリーの多対多 |
| `orders` | 注文者・注文日時・状態 |
| `order_items` | 注文時の商品名・単価・数量 |

ユーザーと注文、注文と注文明細は 1 対多。単一店舗のためショップテーブルと `shop_id` は設けない。
過去の注文金額は明細の保存単価から計算する。スプレッドシートには RDB の制約・トランザクションを前提とせず、GAS 側で検証・排他・途中失敗への復旧を設計する。

決済・配送・在庫引当・会員登録・運営者権限・管理画面・カート永続化は初期範囲外。
金額は日本円の整数とし、税額計算・送料・値引きは含めない。カラム・画面遷移・保存方針・受入条件はアイディア文書を参照する。

## セットアップ

現状の Makefile は雛形で、下記コマンドは TODO メッセージを表示する。起動・テスト環境が整備済みという意味ではない。

```bash
make setup    # 依存取得 + ビルド
make dev      # 開発サーバー起動
make test     # テスト
```

設定は `env/config.yaml`（非機密）、`env/secret.yaml`（ローカル秘密情報）、Doppler（チーム共有・本番秘密情報）で管理する。
`env/secret.yaml` は `.gitignore` で除外されるためコミットしない。

Codexの探索SkillとSerenaの任意設定は生成済み。小規模修正は標準検索、RTKは明示呼出し、Serenaは既定無効から必要時だけ使う。[AIコーディング環境](docs/runbooks/ai-coding.md)で端末の準備と実利用確認を行う。生成器はツール本体をインストールしない。
