## 対象者とゴール

身近な遊び・写真日記・英語学習・店舗業務を題材に、AIへ希望を伝え、試し、結果を確かめたい人が対象。本人に合う1教材・1課題から始め、必要に応じて保護者や講師が操作・言語化を支援する。

受講順は **01 GAS → 02 Web**、提供者の制作順は **02 Web → 01 GAS**。全5教材の履修やWebへの進級は必須ではない。初回成功は意味のある1課題で依頼・試行・確認を経験することとし、全技術の習得や自立を要求しない。

## 実行基盤・AI・認証

| 項目 | この版の構成 |
|---|---|
| 実行・画面 | Google Apps Script／HTML Service |
| データ・画像 | Google Sheets。写真日記の画像はGoogle Drive |
| アプリ内AI | 写真日記・英語のみOpenAI Responses API、`gpt-4.1-mini` |
| キーの保存 | 各GASのScript Propertiesに`OPENAI_API_KEY`。コード・Sheets・Gitへ入れない |
| 公開範囲・認証 | 本人限定公開（`MYSELF`／`USER_DEPLOYING`）。架空利用者の選択は本人認証ではない |

日記の「AI接続設定」、英語の「設定」からもキーを登録できる。保存済みキーは画面へ返さない。Googleの初回権限承認とOpenAIの認証は別。手順は[写真日記](photo-diary/docs/openai-setup.md)／[英語](english-trainer/docs/openai-setup.md)を参照する。

コードの質問・改造はDevin、アプリからのAI呼出しはOpenAI API、業務自動化の質問・作業はCursorという分担。AI不要の教材へ接続機能を追加しない。

## 始め方と改修の進め方

1. 上の一覧から1教材を選び、そのREADME・AGENTS.md・現行仕様を読む。
2. 架空サンプルで基本操作を体験し、変えたい箇所と期待結果を一つ決める。
3. Webで確認した業務ルール・入力例・期待結果を再利用し、GAS固有の保存・権限・排他・公開を個別に確かめる。
4. 対象教材のコマンドでローカル検証し、配置対象を確認して公開する。公開後に保存・再読込・PC／狭幅表示を確認する。
5. 依頼文・確認方法・戻し方を渡し、合意した回数・時間・期間で支援を終了する。

既存データ・旧履歴は保持する。日記の保存上限や既存日付の扱い、英語の旧機能との互換、じゃんけんの配置対象は各教材の正本に従う。ブラウザー操作は[実GASの接続・検証手順](../docs/runbooks/gas-playwright-chrome.md)を参照する。

## 文書の更新ルール

このREADMEは入口と現状要約を管理する。教育設計・事業仮説・詳細仕様・長い作業ログを複製せず、上記の正本を更新する。

GAS・WebのREADMEは見出し順、教材の掲載順、対応表と状態表の列を揃える。対応範囲を変えた場合は両版の表と機能分担を照合し、片方の実装・検証だけで他方を完了扱いにしない。状態の更新には確認日・公開版・根拠を添える。コード実装、ローカル検証、公開反映、実環境受入、本人の学習成果を区別する。
