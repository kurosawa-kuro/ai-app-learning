# 提供を続けられる条件と事業仮説

[全体案内](../README.md) · [配布範囲](feature-allocation.md) · [初回支援](06_first-pairing-pilot.md) · [出典](reference/00_source-map.md)

2026-10-27更新。事業化・価格・需要は未検証。現在の優先は、一つの課題でAIとの並走を経験でき、提供者も合意した支援を終えられること。協力者は未定であり、有料募集や販売開始を示す文書ではない。

## 提供が可能になる理由

提供者が毎回ゼロからアプリを受託開発する形では継続できない。基本範囲を限定した教材と、繰り返し使える依頼文・確認例・戻し方を用意し、支援する課題・回数・時間・期間・窓口を先に決める。**サポートとフォローの終わりが曖昧にならないことが、提供者のメリットであり、提供できる条件になる。**

| 誰にとっての価値か | 今回確かめること |
|---|---|
| 受講者 | 本人に意味のある一つの課題で、AIに依頼し、試し、結果を確認する経験を得る |
| 提供者 | 同じ教材・確認手順を再利用し、合意した支援枠で引き渡しと終了まで進められる |
| 次の受講者 | 前回のつまずきを反映した説明・サンプル・確認方法で始められる |

本人の自立や全技術の習得を達成するまで、無期限に支援を継続する約束にはしない。初回成功に支援を認め、長期の成長と今回の支援契約を分ける。

## 提供物と終了条件

| 区分 | 用意するもの | 終了時の確認 |
|---|---|---|
| 基本教材 | 合意した範囲のコード・説明・サンプル・期待結果 | 対象版と利用環境で基本操作を確認した記録がある |
| 初回支援 | 一つの課題の言語化、AIへの依頼、操作・結果確認の補助 | 本人が何を経験・判断したかと、介助した範囲が残る |
| 引き渡し | 依頼文、確認手順、戻し方、既知の制約、残件の扱い | 本人または保護者が後で参照できる |
| 任意の横展開 | 目標提案・参考プロンプト・確認例 | 応用先の完成品・継続保守は含まないことが分かる |

[初回支援シート](../../../docs/templates/ai-pairing-session.md)に、回数・時間・期間・窓口、標準教材の不具合対応、追加要望の扱いを記入する。30分×3回は枠の一例であり、固定商品や習得保証ではない。

枠が終了した時点で未達なら、未達の理由と次の扱いを記録する。標準教材の不具合は合意した対応範囲で扱い、新しい要望は今回へ自動追加しない。必要なら別課題として条件を決め直す。

## 制作・保守の上限

- 両基盤の完成版配布は写真日記・キャスト評価・英語訓練のみ。同じ基本機能で完成とする。
- じゃんけんはGASの通常対戦からWebのスキル・AIセリフ事前作成へ、ショップはGASの直接注文からWebのカート注文へ進む小さな教材差に留める。
- コードと解説は02 Web → 01 GASで作り、サンプル・期待結果・説明を再利用する。基盤固有の確認は省かない。
- 応用は目標と参考プロンプトを渡す。資格学習版、旅行記版、別業種評価版を提供者が追加制作する計画にはしない。
- 音声・決済・在庫・POS・複数店舗・実課金集計を、Webだから必要という理由で追加しない。
- 記事や短い実演は共通のつまずきに合わせて整える。全教材の動画講座を最初から制作する条件を置かない。

## 最初に観測すること

まず[1人・1課題](06_first-pairing-pilot.md)で確かめる。本人の初回成功と、提供者の負担が枠に収まるかは別々に評価する。

| 観測 | 記録する内容 |
|---|---|
| 本人の目的 | 何を変えたかったか、本人に使う理由があったか |
| 並走の経験 | 依頼・試行・確認で本人が行ったこと、必要だった補助 |
| 準備負担 | 環境準備・サンプル作成・予行にかかった時間 |
| 支援負担 | 当日の時間、質問件数、終了後の対応時間、範囲外の依頼 |
| 引き渡し | 依頼文・確認例・戻し方で説明が足りたか |
| 継続可能性 | 同じ課題の次回に再利用できるもの、削るべき範囲 |

成功しても毎回長時間の個別作業が必要なら、課題や説明・提供範囲を縮める。未達でも支援枠を無期限に延長せず、環境・課題・説明・本人の関心を切り分ける。一人の事例だけで教育効果や採算を一般化しない。

## キャスト評価を使う場合

対象の仮説は、ナイトワークの単一店舗で複数キャストの実績と評価を扱いたいオーナー・店長。独立予定というだけで適しているとは判断せず、評価業務の必要性を確認する。

提供範囲は管理者限定の実績入力・評価ルール・月次集計・順位。GAS・Webで同じ基本機能とし、POS・会計・給与・複数店舗・本人用画面を取り込まない。既存の配点を一つ変え、架空の実績で期待値と比較する課題から始める。ルール変更で過去期間の再計算結果も変わる制約を説明する。

管理者限定は実際のアクセス制御で確認する。画面のユーザー選択を本人認証と扱わない。AIは依頼・説明・検証の補助に使い、評価アプリ本体へAI機能を追加しない。

## 将来の事業化仮説

教材の再利用と有限の支援が成立してから、提供条件を示して支払い意思を確かめる。教材単体、初回支援付き、別途合意する個別相談を区別し、継続契約を前提にしない。

過去の検討値は教材19,800円、30分×3回の伴走付き59,800円。月5件・3件で278,400円、同条件12か月で3,340,800円という計算が元資料にある。**いずれも未検証の旧仮説であり、現行価格・販売目標・収益予測ではない。** 教材制作・更新・準備・質問対応などを除いた売上計算なので、提供可能性の根拠には使わない。

以前の「知人以外の3人が購入し、90分後に独力で変更できる」という案も、現在の合格条件にしない。本人の初回経験、引き渡し、支援負担、購入意思、実際の購入を分けて記録し、必要な検証人数や枠はその段階で決める。

外部サービスの契約・料金は教材代と分け、提供時点の条件を確認する。特定AIツールの契約やコード記述を全員の受講条件にしない。ソース利用条件、教材更新、不具合対応、個別改修の範囲も提供前に明示する。
