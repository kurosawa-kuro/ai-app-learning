## 将来の事業化仮説

### 本業の専門能力を再利用できる教材へ

事業化は後回しとし、以下は将来の判断材料として残す。AIプラットフォームエンジニアのフリーランス活動を収入・専門能力の基盤と位置付け、教材ではその一部を、一般の人が理解し使えるコード・動画・記事・導入手順へ変換して蓄積する。

| 観点 | フリーランス活動で重視すること | 教材・導入伴走で検証すること |
|---|---|---|
| 提供価値 | 専門技術による個別課題の解決 | 学習者が自分で変更・運用できる能力 |
| 収益 | 案件・専門性・稼働に応じた対価 | 教材の再利用と範囲を決めた支援への対価 |
| 資産 | 実績・専門能力・業務理解 | コード・模範実装・動画・指導ノウハウ |
| 人との接点 | 企業・案件ごとの関係 | 既存の相談、紹介、学習体験からの関係 |
| 成立条件 | 案件に必要な成果を出せる | 教材だけで進める範囲が増え、支援負担を把握できる |

収入額の優劣を目標にせず、専門能力と教材資産が相互に育つ構造を目指す。教材の再利用で稼働依存を下げられる可能性はあるが、制作・更新・支援の時間がなくなるわけではない。

保護者からの相談、海外志向の英語学習者、ナイトワークや独立予定者との接点は、課題を聞いて試してもらう入口として活かす。接点があること自体を、購入需要や教育効果の証明とはしない。

### 仮価格による売上シミュレーション

将来の価格仮説は教材単体19,800円、対面30分×3回（計90分）の伴走付き59,800円。伴走の提供範囲をこの検証用の仮案に合わせる。確定価格ではなく、支援範囲・対象教材・提供条件を決めてから検証する。

| 商品案 | 仮単価 | 仮の月間件数 | 月間販売額 |
|---|---:|---:|---:|
| 教材単体 | 19,800円 | 5件 | 99,000円 |
| 教材＋対面90分の伴走 | 59,800円 | 3件 | 179,400円 |
| 合計 | — | 8件 | 278,400円 |

- 月商の単純試算：278,400円。
- 同じ販売数が12か月続くと仮定した年間売上：3,340,800円。
- 対面枠のみの時間：90分×3人＝270分＝4.5時間／月。

件数・価格は仮説であり、予測や達成目標ではない。教材制作・更新、事前準備、移動、集客、質問対応、個別改修、決済手数料、税金等を差し引く前の売上。4.5時間は総労働時間ではない。利益や本業との比較には、実際の総工数と費用を別途記録する。

### 事業化を検討する段階での初期検証

将来の有料検証の目安は、**自分の知人以外の3人が購入し、90分の伴走後に合意した小さな変更を自分で行い、検証・説明できること**。紹介経由でも本人とは面識がない購入者等を対象にし、既存の知人の好意による評価と分けて記録する。

現時点で有料募集や売上目標を設定するものではない。先に教材の再現性と対象者別の学習成果を確認する。子供向けでは購入者の保護者と学習する本人を区別し、本人の理解を評価する。

記録するのは、購入条件、開始時の経験、本人が行った変更、伴走前後の到達、追加支援時間。3人の成立だけで継続的な収益性まで証明したとは扱わない。

次の状態では商品・教材・支援範囲を見直す。

- 個別サポートが毎回何時間も必要になる。
- Devinの操作や変更判断を代行し続け、提供者が実質的に開発を請け負う。
- 動画と手順で導入・確認を再現できない。
- 関心は示されるが、示した条件で購入する人がいない。
- 2つの技術基盤の保守が、得られる学習価値や提供余力に見合わない。

安価な受託開発へ変質させず、支援外の個別開発は別途扱う。学習者が自立するほど、教材・伴走の目的を達成できたと判断する。

### 資産が蓄積する循環

既存テンプレートを整備 → 記事・動画・対面で自立を支援 → 利用者の質問・改善を観測 → 共通教材と模範実装を改善 → 次の学習者へ再利用する。

当初は講師の能力に依存する部分を、説明・例題・受入テスト・導入手順へ移していく。本業で培うAI活用・業務分析・データモデリング・自動化・プロダクト設計も、教材化を通じて説明可能な知識へ整理する。これを小規模な教育・ソフトウェア事業へ発展させられるかは、将来あらためて検証する。

## 独立開業者向けの内製化支援キット

事業化を検討する段階での提供案。当面は既存教材・模範実装・教育手順の整備を優先する。

### 提供する価値

**「自分のお店の仕組みを、自分で作り、変えられるようになる。」**

共通の教育モデルを独立開業者向けに具体化する。キャスト評価アプリを入口に、独立後も店舗の業務を自分で改善し続ける能力を提供する。プログラミングやGASの習得自体を目的にせず、オーナーが店舗のルールを理解し、設定変更や必要な改修を判断できるようになることを重視する。

商品名の仮案は **Cast Evaluation Starter Kit — 独立開業者向け・AIで育てる店舗評価システム**。完成アプリ・ソースコード・Devinを使う改修環境の案内・導入運用動画を組み合わせた、小規模店舗向けの内製化支援を目指す。

これは商品構想であり、現在の販売商品ではない。キャスト評価アプリは設計段階で、完成アプリ、配布用コード一式、Devin環境、教材動画、導入・復旧手順の検証はこれから準備する。需要、学習効果、支払い意思も未検証。

### 対象者と訴求

主な対象は、**ガールズバー・スナックでの独立を計画し、将来キャストを複数人雇う予定がある人**。キャスト経験を持ち、自分の店の評価ルールを考えたい人を想定する。

独立希望者全般を一律の対象にしない。一人で運営する予定ならキャスト評価が不要な場合があり、物件・開業資金・集客より優先順位が低い可能性もある。評価業務への具体的な必要性を先に確認する。

案内の中心は「このアプリを作れるようになりませんか？」から、次へ置き換える。

> 独立したとき、自分のお店のルールに合わせた管理アプリを、自分で作って変更できるようになりませんか？

### 商品構成の案

| 提供物 | 内容 | 購入者が目指す状態 |
|---|---|---|
| GASアプリ＋MVPソースコード | メンバー管理、5項目の日次実績、ポイント設定、月次評価・ランキング | 自分のGoogleアカウントで導入・運用できる |
| Devin活用環境・教材 | GitHubリポジトリ、設計書、テスト、環境設定の案内、改修依頼用プロンプト | 店舗の要望を整理し、AIに変更案を依頼できる |
| 導入・運用の学習動画 | アカウント準備、GAS導入、日々の操作、設定変更、検証、公開、復旧 | 動画を見ながら必要な操作を再現できる |
| 検証・変更・復旧の一式 | 検証データ、テストコード、変更確認の手順、更新前の退避・戻し方 | 改修の影響を確認し、問題時に戻せる |
| 任意の個別支援 | 初回導入、店舗設定、必要な改修の相談 | 自力で難しい部分だけ支援を受けられる |

購入者が自分のGoogle・GitHubアカウントでコードとデータを管理し、特定の開発会社に頼り切らずに運用できる形を目指す。ソースの利用・改変・再配布の範囲は販売前に利用条件として定める。「ソース提供」と「著作権の譲渡」は同一視しない。

DevinはAI改修のための道具として位置付ける。Devinの契約・利用料は商品価格と分け、利用を希望する購入者が自身のアカウントで契約する想定。AI改修を希望しない人も、完成アプリの導入・日常運用・設定変更まで行える商品設計にする。

### 習得ステップ

| 段階 | 体験 | 到達の確認 |
|---|---|---|
| 1. 使える | 動画を見ながら導入し、キャストと実績を登録する | スマートフォンで登録・編集・月次評価を確認できる |
| 2. 設定を変えられる | 配点・計算単位・有効／無効を自分の店に合わせる | 変更後の期待値を説明し、結果が一致することを確認できる |
| 3. AIで作り変えられる | Devinに要望・対象範囲・期待する結果を伝える | 変更案と差分を確認し、検証環境で試せる |
| 4. 継続して改善できる | 必要な改修だけを反映し、問題時は戻す | テスト・反映・復旧を含む変更手順を再現できる |

最初からコードを書くことや、段階3への到達を全員に求めない。「まず動くアプリを使う → 必要な設定を変える → 必要になったら改修を学ぶ」の順序で、独立準備中の負担を抑える。

### 動画教材の構成案

1. 店舗の評価業務を整理する：対象者、5項目の実績、既存POS・会計との役割分担。
2. 自分の環境へ導入する：Googleアカウント、Sheets、GAS、管理者の権限とスマートフォンでの確認。
3. 日々の運用を行う：メンバー登録、実績入力・訂正、退店時の無効化、月次評価。
4. 店舗の設定を変える：配点・単位・有効／無効、計算例、過去期間への影響。
5. Devinで改修案を作る：GitHub、設計書とテスト、要望の書き方、変更差分の読み方。
6. 検証して反映する：検証用環境、期待値との比較、対象版と公開範囲の確認。
7. トラブルから復旧する：保存成否の照合、コード・データ・ルールそれぞれの戻し方、支援が必要な場合の連絡材料。

動画は配布するコードの版に対応させる。第三者サービスの画面や条件が変わった際の教材更新範囲も販売前に定める。

### 共通部分と店舗ごとの変更を分ける

| 区分 | 方針 |
|---|---|
| 共通テンプレート | 標準コード・設計書・テスト・教材を版とともに管理する |
| 店舗設定 | 配点・計算単位・有効／無効など、標準機能の設定で変えられる部分を明示する |
| 店舗固有の改修 | 設定では足りない変更だけを別の差分として管理し、検証範囲と支援条件を決める |

「同伴を週末だけ2倍にする」といった要望は、現在の固定カテゴリ・単純配点を超える**将来の改修例**であり、標準MVPで設定可能と案内しない。まず必要性・仕様への影響・既存業務での代替可否を検討する。

現在のMVPでは、評価ルール変更時に過去期間も再計算される。設定変更の教材にもこの制約と管理者確認を含める。AIがコードを変更できたことを、本番で問題なく運用できる証拠にしない。テスト環境で確認してから反映し、コードだけでなくデータ・設定の復旧も扱う。

任意のコード改変まで一律に無制限サポートする設計にはしない。標準版の不具合、導入支援、設定相談、店舗固有改修を区別し、対象版・期間・回数・対応範囲を明示する。共通テンプレートへ取り込む改善は、実店舗の必要性と検証結果を基に選ぶ。

### 提供・収益モデルの仮説

| モデル | 提供するもの | 収益の考え方 |
|---|---|---|
| アプリ販売・利用提供 | 完成した評価アプリの利用 | 月額等の利用料 |
| 制作教材 | コード、動画、変更手順、AI活用教材 | 教材・講座の代金 |
| 伴走型 | 店舗への導入と、変更できるようになるまでの支援 | 初期支援＋任意の継続支援 |

**将来事業化を検討する際は、少人数の伴走型で、購入者がどこまで自力で進められるかを検証する。** 共通のつまずきをコード・動画・手順へ反映し、その後に自習用キットの提供を検討する。継続支援を必須にして依存を残すより、設定変更や運用を自分で行える範囲が広がったことを成果として評価する。

| 商品案 | 検証用の仮価格 |
|---|---:|
| GASソース＋導入・運用動画＋Devin活用教材 | 19,800円 |
| 上記＋対面30分×3回（計90分）の伴走 | 59,800円 |
| 店舗独自の改修・相談 | 個別見積もり |

これらは提示されたFBに基づく価格仮説であり、販売価格・支払い意思を検証済みという意味ではない。税込／税別、利用条件、提供期間、更新・支援範囲は販売前に決める。

売上の仮試算と有料検証の目安は [将来の事業化仮説](05_business-hypotheses.md#将来の事業化仮説) を参照。コードと動画を再利用できても、購入者ごとの支援負担を含めて判断する。

Devin・Google・GitHub等の第三者サービスは、料金・利用条件・必要なプランを販売時点の公式情報で確認する。本書では具体的なDevinのプラン価格や「すべて無料」を確約しない。教材代、任意の支援費、外部サービス利用料を分けて案内する。

### 将来の需要検証

事業化を検討する段階で実施する案。現段階の教材づくりでは、理解・操作・検証の再現性を先に確認する。

最初から大規模な有料講座を作らず、対象に合う5〜10人へ評価アプリのデモを見せて確認する。現状は設計段階なので、実際に触れる検証用MVPを用意してから操作を伴う検証を行う。

| 確認すること | 記録する反応・行動 |
|---|---|
| 評価業務の必要性 | 採用予定人数、開業時期、現在または予定している評価方法、他の開業課題に対する優先度 |
| アプリへの需要 | 既存の評価方法を自分の店でも使いたいか、日次入力の負担を許容できるか |
| 自分で変更する価値 | ポイントを自分で変えたいか、何を変えたいか |
| 学習への需要 | アプリだけ欲しいか、設定変更まで学びたいか、AI改修も学びたいか |
| 支払い意思 | 教材・導入支援・個別改修のどれに、どの条件なら支払うか |
| 実際の到達 | テンプレートで配点を変更し、期待した結果を自分で確認できたか |
| 支援負担 | 自力で完了した範囲、かかった時間、質問数、介助が必要な箇所 |

口頭の興味、操作できた事実、支払い意思、実際の購入を別々に記録する。動画だけで進めた場合と伴走した場合の違いも確認する。

結果に応じて次を判断する。

- アプリは必要だが制作学習の需要が弱いなら、利用・設定中心の商品にする。
- 学習意欲があり設定変更を再現できるなら、教材化を進める。
- 導入のつまずきが多いなら、動画・標準コード・初回支援を改善して再検証する。
- 評価自体の優先度が低い、対象店舗の需要がない、支援負担が大きすぎる場合は、対象者・商品構成・価格を見直す。

開業教育の市場があることと、キャスト評価アプリの制作学習に需要があることは別の仮説として扱う。外部の開業支援事例を使って告知する場合は、出典・開催時期・内容を確認し、未確認の紹介文を市場検証の証拠にしない。

### 個別アプリとの関係

この構想は「アプリを教材にした内製化支援」という提供方法を追加するもので、Cast Evaluation Systemをオールインワン店舗管理へ広げるものではない。プロダクトは引き続き **Small Core / Integration First** に従う。

将来、別の店舗業務との関係を検討する場合も、キャスト評価アプリにPOS・会計・給与等を取り込まない。当面の題材は既存5教材に固定し、新規教材やキャスト評価の第2パターンは作らない。Devinは開発・学習用の道具であり、評価アプリ本体へAI機能やDevin連携を追加することをMVP要件にしない。
