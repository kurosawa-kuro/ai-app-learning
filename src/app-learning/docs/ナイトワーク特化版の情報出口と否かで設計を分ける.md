# 情報出口の分離：調査経緯と実施結果

更新日：2026-10-28（日本時間）。内部管理資料。公開物へ含めない。

## 1. 現在の結論

素材の制作元を共通にし、当面は次の3出口を独立して管理する。本名の公開範囲とナイトワークを扱うかどうかは別の設定軸とする。

| 番号 | 出口ID | 本名 | ナイトワーク |
|---|---|---|---|
| ① | `realname-general` | 公開 | 触れない |
| ② | `alias-nightlife` | 非開示 | 触れる。写メ日記・キャスト評価を推す |
| ③ | `alias-general` | 非開示 | 触れない |

本名サイトの作成に時間がかかっても②・③の原稿整備を進められる構成にした。②と③は別の活動名にすることをユーザーが確定した。プロフィール・連絡先も分ける。正式名は未確定。名刺用WIPはユーザーの仮データ指定に従い別々の仮名で先行公開した。固定URL・QR・名刺と残作業は[WIP公開・印刷運用](publication/wip-release.md)を参照。

①は独自ドメイン必須。②・③は独自ドメイン必須ではなく簡易サービスでもよく、公開技術はできるだけ共通にする。教材単位で①・③から外すのはキャスト評価だけで、他の教材は中立的な説明・サンプルなら掲載候補にできる。確定要件の詳細は下記の分離ポリシーを参照する。

将来は①・②の2出口を基本想定とするが、③の終了・移管を自動化しない。③から①への転送や本名への置換は対応関係を明かすため、別途判断する。中立的な本文の共用と、人物の対応関係の公表は別の操作である。

## 4. この構成を選んだ理由

最初は一般向けと専門向けの2出口を検討した。その後、本名サイトの準備と、本名を出さない一般向けの案内を並行して進めるため、3出口へ拡張した。アプリの種類だけ、または本名公開の有無だけでフォルダーを二分すると、③の置き場所と公開許可が曖昧になる。

そこで、内部設計と公開原稿を分けたうえで、3出口を固定IDで管理する。共通のコード・仕様を出口ごとにコピーせず、共通本文と専用の導入文を組み合わせる。現在の公開候補は少数の紹介ページだけとし、全教材を一括公開しない。

サイト分離は情報の混入を防ぐ仕組みであり、匿名サイトを一般の人が見つけない保証ではない。②を一般公開すれば第三者も見られる。招待制は推奨案として残しており、採用は未決定。noindexやrobots.txtを閲覧制限の代わりにしない。

## 5. 移行時に残る確認

- 制作元の公開範囲、既存のREADME・履歴・配布物・公開デモ・検索結果を確認する。
- 各出口の名義・連絡先・ドメイン・公開水準を決める。未設定を他出口で補完しない。
- 公開ファイル、検索、配布教材、デモ、問い合わせを同じ出口で揃える。名刺、署名、著者・所有者、会議・画面共有の表示も含める。
- 原稿レビュー、出口別の生成・配置、実環境の受入を行う。実データと教材用の架空データを分ける。
- 既存デモや旧配布物は、リンクを削っただけで非公開化したとは扱わない。停止・保護・差替えの対象を個別に決める。

第三者へ渡ったコピーや既に知られた事実を元に戻せるとは扱わない。GitHubでも、公開リポジトリを非公開に変更しても公開forkは非公開化されない。[GitHub公式](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility)

## 6. 実施した配置と編集方法

`src/app-learning/docs/publication/` に内部の共通方針と3出口の設計・運用、`src/app-learning/publishing/` に公開用の共通素材・3出口の原稿・設定を配置した。詳細なツリーと正本の分担は[索引](publication/README.md)に一元化した。

| 変更 | 編集先 |
|---|---|
| アプリの保存・計算・DB等 | 既存の各アプリのコード・仕様。出口側の説明も必要に応じて確認 |
| 写メ日記の紹介 | `publishing/alias-nightlife/content/` |
| 一般向け説明 | 対応する一般出口の `content/`。中立の共通部分は `common/content/` |
| 公開名・問い合わせ設定 | 当該出口の `publish.yaml` |
| 素材の公開許可・依存物 | `publishing/catalog.yaml` |
| 分離ルール | `docs/publication/separation-policy.md` |
| 一回の実施・検証記録 | リポジトリ直下の `docs/tasks/` |

`publishing/dist/` は生成物専用でGit管理外。現時点では空の配置先だけを用意し、公開成果物があるように扱わない。原稿を直すときにdistを直接編集せず、必要な仕様・原稿・設定を一組で更新する。

旧案で示した `general/`・`nightlife/` の2フォルダーは作らず、3出口のIDを使用した。旧案の最初の8ファイルに相当する役割を3出口へ拡張し、運用手順と入力検査まで整えた。既存アプリの実装、DB、デモ、受講順と制作順はこの整理で変更していない。
