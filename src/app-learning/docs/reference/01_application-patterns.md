# 応用パターン：既存の仕組みを小さく使い替える

[全体案内](../../README.md) · [配布範囲](../feature-allocation.md) · [目標と参考プロンプト](../04_extension-catalog.md) · [出典](00_source-map.md)

2026-10-27更新。ここは本人が次に試す題材を考えるための参考資料。提供者の制作一覧でも、プログラマーになるための必修知識一覧でもない。最初は一つの課題でAIへの依頼・試行・結果確認を経験できればよい。

## 既存の仕組みと小さな使い替え

| 教材 | 再利用できる考え方 | 最初に変えるもの | 確認例 |
|---|---|---|---|
| photo-diary | 写真・文章・タグを関連付け、AI下書きを本人が確認して保存する | 旅行記・観察日記向けのタグ、文体、説明 | 写真にない事実を補っていないか、手直しした文が保存・表示されるか |
| english-trainer | 問題・回答・評価・会話・振り返り・履歴を分ける | 資格学習の少数の問題と採点基準、会話の目的 | 正答・誤答を参考資料と照合し、回答と評価が対応して残るか |
| cast-evaluation | 実績と配点を分け、期間を決めて集計する | 既存項目の配点と架空の実績 | 同じ入力で期待したポイント・順位になるか |
| skill-janken-game | 入力・ルール・結果を分ける | GASでは説明文、Webでは事前作成セリフの文体 | 表示だけ変わり、勝敗・得点・スキル効果が意図せず変わらないか |
| online-shop | 注文前の選択と、確定した注文・明細を分ける | 商品・カテゴリのサンプル | 数量・合計・注文時点の単価が一致するか |

同じ基本機能を両版で配布するのは写真日記・キャスト評価・英語訓練。じゃんけんはWebでスキルとAIセリフ事前作成、ショップはWebでカート注文を扱う。GASへ同じ追加機能を持ち込まない。

## 応用を小さくする手順

1. 本人の目的を一つ決める。全部の型を学ぶことを目的にしない。
2. 対象版で実装・検証済みの仕組みを選ぶ。未実装のものを応用課題の前提にしない。
3. 文言・サンプルデータ・設定・生成指示のいずれか一つから変える。
4. 変更前後の入力と期待結果を比較し、元に戻せるようにする。
5. 新しい画面・業務モデル・外部サービスが必要なら、今回の範囲を縮めるか別課題に分ける。

資格学習への題材変更は、資格全範囲の問題集制作や合格保証ではない。旅行記への変更は共有サービスの開発ではない。キャスト評価の配点変更は別業種版の制作ではない。目標・参考プロンプト・確認例を提供し、応用先の完成と保守は自動的な提供範囲にしない。

## 同じ見た目でも業務の意味は分ける

| 似ているもの | 分ける理由 |
|---|---|
| ゲームの得点と店舗の評価ポイント | 勝敗・スキルに関する計算と、営業実績への配点は異なる |
| 日記のAI下書きと学習のAI採点 | 本人が編集して採用する文章と、回答・基準に対応する評価記録は異なる |
| 注文金額と店舗の評価用売上 | 注文確定時点の情報と、既存の業務で確定した評価用金額は異なる |
| ユーザー選択と本人認証 | 操作主体の選択だけでは、アクセス権や本人確認を保証しない |

共通テンプレートでは画面・入力・画像・AI通信・要求状態・復旧の仕組みを再利用し、日記・採点・実績・注文を同じ業務モデルへ統合しない。詳細は[共通仕様](../../02-web-app-learning/template/docs/shared-foundation-requirements.md)。

## 旧資料の広い応用案の扱い

旧資料には銀行・ウォレット、転職・人材マッチング、予約・在庫、組織承認、定期契約、リアルタイム共有、外部同期などの例があった。これらは今回の教材制作・Web限定機能・テンプレートの不足一覧には採用しない。

業界ごとの権限・状態・整合性・運用が追加で必要になり、今の小さな教材と同じ負担では作れないため、詳細なモデル・画面・工程を本書の実践候補から外した。将来必要になった場合だけ別の目的と範囲で調査する。元資料との対応は[出典・編集対応表](00_source-map.md)に残す。

キャスト評価はナイトワーク特化の1パターン。一般業務向け第2パターンの仕様・画面・実装計画は今回作らない。
