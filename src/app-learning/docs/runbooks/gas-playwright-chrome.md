# GAS実環境を通常ChromeからPlaywrightで検証する

2026-10-28、Playwright ExtensionとMCPクライアント「GAS acceptance」を接続し、ログイン済みの通常ChromeでGAS公開画面を操作・撮影できることを確認した。別の自動操作用ブラウザーでGoogleログインが拒否された場合も、今回接続できた通常Chromeのセッションを利用する。

## 接続と承認の分担

1. Googleへログイン済みの通常Chromeで、対象教材のGAS公開URLを開く。
2. ChromeにPlaywright Extensionを導入し、拡張機能へ接続するPlaywright MCPクライアントを起動する。拡張機能のインストールだけでは接続完了にならない。
3. 接続確認でクライアント名を確認し、ユーザーが接続を許可する。タブ選択がある場合は対象教材を選ぶ。
4. 接続後、検証担当が対象URLと画面を確認して操作する。現在選択されているタブだけを頼りにしない。
5. GAS側で初回の権限承認を求められた場合は、ユーザーが承認する。その後の入力・保存・再読込・スクリーンショット確認は検証担当が実施する。

Chromeへの接続許可、各GASの初回権限承認、OpenAI APIの認証は別のもの。Chromeへ接続できてもAI疎通確認済みにはならない。接続トークン・Cookie・認証情報は文書やリポジトリへ保存しない。

## 検証方法

- 公開URLのGAS画面を対象に、入力→保存→一覧・詳細→再読込を確認する。教材に応じて重複送信・集計・ユーザー切替も確認する。
- GASのアプリ本体は埋め込みフレーム内にある。今回の対象は `userHtmlFrame` を使用した。対象フレームと操作する要素を確認してから入力する。
- 同じタブをユーザーと検証担当が同時に操作しない。画面が変わった場合は、保存済みかを確認してから再試行し、新規データを重複作成しない。
- PC幅1440pxとモバイル幅390pxでスクリーンショットを撮り、実際に画像を開いて、はみ出し・文字・入力欄・ボタン・結果表示を確認する。390pxの確認は実機スマートフォンでの検証とは区別する。
- 画面の保存成功だけで完了にせず、再読込後の保持と保存先Sheetsとの照合を分けて記録する。

ローカルの模擬GASを使うPlaywrightテストと、この通常Chromeでの実GAS検証は別工程。既存のローカルテストコマンドが自動的に実GASを検証するようになったわけではない。
