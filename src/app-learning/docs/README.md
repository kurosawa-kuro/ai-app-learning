# アプリ学習の横断設計

[アプリ学習の入口](../README.md) · [01 GAS](../01-gas-app-learning/README.md) · [02 Web](../02-web-app-learning/README.md) · [Webスタックの採用判断](../../../docs/adr/0001-web-app-stack.md)

教材ごとのGAS版・Web版のAI機能の要否は、[アプリ学習の対応表](../README.md)を正とする。

配布範囲は[機能分担](feature-allocation.md)を参照する。写真日記・キャスト評価・英語訓練は両版を同じ基本機能で完成とする。じゃんけんは通常対戦からスキル・AIセリフ事前作成へ、ショップは直接注文からカート経由注文へ進む。Web版を理由に機能を積み増さない。

**両基盤の完成版配布が必要なのは、写真日記・キャスト評価・英語訓練の3教材だけ。** じゃんけん・ショップに両版の完成品を揃える要件は課さない。配布範囲の正本は[入口の対応表](../README.md)。

このディレクトリは、GAS配下から昇格した**アプリ学習全体の横断設計の正本**。01・02に共通する対象者・ゴール・教育設計・題材・制作・検証・支援終了の方針を管理する。個別アプリの詳細仕様・実装済み機能・接続先・検証状況は、そのアプリの正本と実装を参照する。

## 受講順とコード・解説の制作順

| 対象 | 順番 | 理由 |
|---|---|---|
| 受講者 | **01 GAS → 02 Web** | 身近なアプリでAIとの並走を体験し、Webアプリ制作へ進む |
| 提供者 | **02 Web → 01 GAS** | ローカル起動・DB確認・自動テストを行いやすいWeb側で、コードと解説を先に作成・検証する |

提供者はWeb側で業務ルール、サンプル、期待結果、テスト、解説の構成を整え、GAS側へ展開する。フォルダー番号は受講順で固定し、制作順に合わせて入れ替えない。Webでの検証結果をGASの検証済み証拠にはせず、Sheets・Drive・GASの権限、排他、保存、公開、実行制約はGAS側で確認する。

本書群のGAS5教材に関する記述は題材の設計資産として保持する。GAS固有の6工程や指導時間をWeb側へ一律適用せず、それぞれの対象者と到達目標に合わせて利用する。

身近な遊び・写真日記・英語学習・店舗業務を入口に、AI・プログラミング・データモデリングを学ぶための教材群。本人が理解している世界を、データと処理の仕組みへつなげる。

## 読み方と管理方針

個別アプリの現行仕様・開発・公開手順は、各READMEから正本をたどる。全体方針は個別仕様を上書きしない。**実装・検証・公開の状態、学習到達目標、未採用の拡張案、事業仮説を分けて管理する。**

キャスト評価はナイトワーク特化の1パターンのみ。将来2パターンに分離する余地だけ注記し、第2パターンの文書・仕様は作成しない。

本一式は分割文書パッケージから `src/app-learning/docs/` に配置された資料。このREADMEは文書索引、アプリ集の入口は1階層上のREADMEとする。個別アプリは1階層上の各プロジェクトを参照し、現行仕様はそこで管理する。
