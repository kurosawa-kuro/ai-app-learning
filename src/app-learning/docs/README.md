初回の成功は、本人に意味のある一つの課題でAIへの依頼・試行・結果確認を経験すること。操作・言語化の支援を認め、全5教材・全技術・独力での改修を終了条件にしない。提供者は課題と支援枠を合意し、依頼文・確認例・戻し方・残件の扱いを渡して終了する。

教材ごとのGAS版・Web版のAI機能の要否と使用形態（アプリ内AIなし・事前生成・利用時の生成／評価）は、[アプリ学習の対応表](../README.md)を正とする。AIとの並走による学習は、アプリ内AIの有無にかかわらず扱う。

配布範囲は[機能分担](feature-allocation.md)を参照する。写真日記・キャスト評価・英語訓練は両版を同じ基本機能で完成とする。じゃんけんは通常対戦からスキル・AIセリフ事前作成へ、ショップは直接注文からカート経由注文へ進む。Web版を理由に機能を積み増さない。

**両基盤の完成版配布が必要なのは、写真日記・キャスト評価・英語訓練の3教材だけ。** じゃんけん・ショップに両版の完成品を揃える要件は課さない。配布範囲の正本は[入口の対応表](../README.md)。

このディレクトリは、GAS配下から昇格した**アプリ学習全体の横断設計の正本**。01・02に共通する対象者・ゴール・教育設計・題材・制作・検証・支援終了の方針を管理する。個別アプリの詳細仕様・実装済み機能・接続先・検証状況は、そのアプリの正本と実装を参照する。

## 受講順とコード・解説の制作順

| 対象 | 順番 | 理由 |
|---|---|---|
| 受講者 | **01 GAS → 02 Web** | 身近なアプリでAIとの並走を体験し、Webアプリ制作へ進む |
| 提供者 | **02 Web → 01 GAS** | ローカル起動・DB確認・自動テストを行いやすいWeb側で、コードと解説を先に作成・検証する |

提供者はWeb側で業務ルール、サンプル、期待結果、テスト、解説の構成を整え、GAS側へ展開する。フォルダー番号は受講順で固定し、制作順に合わせて入れ替えない。Webでの検証結果をGASの検証済み証拠にはせず、Sheets・Drive・GASの権限、排他、保存、公開、実行制約はGAS側で確認する。

本書群のGAS5教材に関する記述は題材の設計資産として保持する。GAS固有の6工程や指導時間をWeb側へ一律適用せず、それぞれの対象者と到達目標に合わせて利用する。

身近な遊び・写真日記・英語学習・店舗業務を入口に、AI・プログラミング・データモデリングを学ぶための教材群。本人が理解している世界を、データと処理の仕組みへつなげる。

## 現在の優先順位

**事業化は後回し。題材は既存5プロジェクトに固定し、新しい教材テンプレートを増やさない。**

役割分担と共通の基本要件・受入条件を整理し、提供者はWeb側のコード・解説を先に整える。両版で完成版を配布する3教材は、その基本範囲をGAS側にも展開し、各基盤で検証する。全5教材を一律の完成品として二重に準備しない。

既存GAS版の過去の状況は[ポートフォリオ](01_portfolio.md#プロジェクト一覧)に集約する。現在のコード・公開状況は各教材の正本で確認し、過去の記録を再検証済みとして転記しない。

Web共通テンプレートは既にある。次に整える共通の不足は[共通仕様](../02-web-app-learning/template/docs/shared-foundation-requirements.md)のAI入出力・要求状態・投稿依存の分離に絞る。ダミーデータでの画面・操作確認と、実DB・Storage・AIでの受入を区別する。

## 読み方と管理方針

個別アプリの現行仕様・開発・公開手順は、各READMEから正本をたどる。最新の提供方針と既存仕様が食い違う場合は、差分を記録して個別改修へつなぐ。文書更新だけでコードも新方針へ変わったとは扱わない。**実装・検証・公開の状態、学習到達目標、未採用の拡張案、事業仮説を分けて管理する。**

キャスト評価はナイトワーク特化の1パターンのみ。将来2パターンに分離する余地だけ注記し、第2パターンの文書・仕様は作成しない。

本一式は分割文書パッケージから `src/app-learning/docs/` に配置された資料。このREADMEは文書索引、アプリ集の入口は1階層上のREADMEとする。個別GASアプリは `../01-gas-app-learning/`、Webの土台は `../02-web-app-learning/template/` を参照し、詳細仕様・実装・検証はそれぞれで管理する。
