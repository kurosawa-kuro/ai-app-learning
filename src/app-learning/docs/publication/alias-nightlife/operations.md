# ②の運用

状態：内部手順。2026-10-28。公開未実施。

1. [設計](site-design.md)と既存アプリの正本を確認し、専門用原稿・架空例を編集する。
2. [制作入力の手順](../../../publishing/README.md)に従い、`--site alias-nightlife` で検査する。
3. 活動名・ブランド・専用連絡先を設定する。本名・①・③の設定で補完しない。
4. 公開水準を決める。招待制なら紹介・添付・デモ・配信元・プレビューまで保護する。一般公開なら第三者が存在を知れることを運用上受け入れる判断を記録する。
5. 本人情報の混入と公開範囲を手動確認し、生成・配置・公開先受入を別途行う。現時点で生成・配置の自動処理はない。

受付フォーム、送信者名、送信元・返信先、署名、予約・会議主催者、共有ファイルの所有者・著者は②用に統一する。専門用のブラウザープロフィールを使い、本名の画面を共有しない。③の問い合わせ先を兼用しない。

共通要件は[分離ポリシー](../separation-policy.md)。混入が判明した公開物は停止し、添付・検索・配布先も確認して正本から修正する。現行公開デモの停止や認証変更は今回のフォルダー整備では実施していない。
