# 教材の配布範囲と横展開の提供方針

[アプリ学習の対応表](../README.md) · [横断設計の索引](README.md) · [目標と参考プロンプト](04_extension-catalog.md)

2026-10-27更新。これは今後の提供範囲を決める文書。実装・検証・配布済みの状態は各教材のREADMEと記録で確認する。

## 提供者が完成させる範囲

**GAS版とWeb版で完成版を配布するのは、写真日記・キャスト評価・英語訓練の3教材だけ。3教材は同じ基本機能で完成とし、Webだから追加機能が必要という扱いにしない。** コード・解説は02 Web → 01 GASの順で制作し、受講順は01 GAS → 02 Webを維持する。

| 教材 | GAS版 | Web版 | 配布範囲の終点 |
|---|---|---|---|
| photo-diary | 写真・タグ・AI下書き・本人の手直し・保存・一覧・詳細 | GASと同じ | 本人が下書きを確かめて保存し、一覧・詳細で読める。手直しは保存前の操作 |
| cast-evaluation | 管理者限定・単一店舗の実績入力、評価ルール、月次集計・順位 | GASと同じ | 既存仕様の実績登録・編集と配点設定から、期待する集計・順位を確認できる |
| english-trainer | 個人用のクイズ・AI採点・テキスト会話・振り返り・学習履歴 | GASと同じ | 問題に答え、評価・会話・振り返りを確認し、学習記録を残せる |
| skill-janken-game | スキルなしの通常じゃんけん、勝敗・得点・履歴 | スキルありのじゃんけん＋AIセリフ事前作成 | 既存の小さなスキル構成を再利用し、セリフを事前生成・採用・保存して表示できる |
| online-shop | 商品・数量を指定して直接注文し、注文・明細を保存・確認。カートなし | カートで商品・数量を確認・変更してから注文 | 注文前の一時データと、確定した注文・明細の違いを体験できる |

じゃんけんとショップには両版の完成品を揃える要件を課さず、上記の段階差を教材として用意する。AIの要否は[入口のAI対応表](../README.md)に従い、ショップ・キャスト評価へAI機能を追加しない。

初回配布に向けた基本機能は上表の範囲で固定する。新しい案は完成後の任意の応用として整理し、SNS、発注・在庫管理、キャラクター・スキル合成、画像生成のために基本教材や共通テンプレートの完成条件を増やさない。基本機能の不具合修正と受入に必要な品質確保は継続する。基本範囲を見直す場合は、目的・制作と支援の負担・両版の受入条件への影響を確認し、対応表と本書を揃えて更新する。

## 段階差を小さく保つ

### じゃんけん：スキルとセリフ事前作成まで

Web版は既存のスキルと通常の判定処理を再利用する。AIは提供者・管理側がゲーム前に短いセリフを作る用途に限り、内容を確認して採用・保存する。対戦中は保存済みのセリフを表示し、未生成や生成失敗でも定型文で遊べる。対戦のたびにAIへ問い合わせず、勝敗・得点・スキル効果をAIに決めさせない。

攻略アドバイザー、戦略分析、対人戦、リアルタイム同期、新しい複雑なスキル体系は今回の提供範囲に加えない。

### ショップ：直接注文からカート経由の注文へ

GAS版はDB・セッション・画面内のいずれにもカートを作らない。商品・数量を注文フォームで指定し、確定時に注文と明細を保存する。「カートなし」はDBや注文保存が不要という意味ではない。

Web版は画面内のカートで商品・数量・合計を確認・変更してから注文する範囲。永続カート・端末間の引き継ぎ・決済・配送・在庫引当は加えない。確定時点の商品・価格、注文整合性、再送時の二重注文防止、注文全体のキャンセル等の基本ルールは両版に残す。

### 英語訓練：問題管理画面は任意の小さな応用

基本の完成範囲はGAS・Webで同じ。その後のWeb応用として、**問題一覧・新規作成・編集**の画面を検討できる。既存の問題形式・保存先・検証処理を使い、問題を画面から用意する範囲に絞る。AIによる一括問題生成、取込、講師管理、音声対応等を付随させない。

この画面は未採用の応用候補であり、配布前の必須作業にしない。採用する場合は既存の問題版管理を尊重し、問題を編集しても過去回答や採点記録の意味が変わらないことを確認する。

## 横展開では目標と参考プロンプトを提供する

提供者が用意するのは、基本範囲の教材と、そこから一つの変更を試すための**目標・参考プロンプト・確認例**。横展開先の完成アプリ、全演習の模範コード、全端末での追加機能検証を制作対象にしない。

| 元の教材 | 任意の目標 | まず変えるもの |
|---|---|---|
| 英語訓練 | 資格学習へ題材を変えてみる | サンプル問題、採点基準、テキスト会話の目的、表示文言 |
| 写真日記 | フォローシステムを備えたXのようなSNSへ展開する | 投稿者と公開範囲、フォロー・解除、フォローした人の投稿を読むタイムライン |
| キャスト評価 | 自分の店舗で重視したい項目の配点を試す | 既存項目の配点と確認用サンプル実績 |
| じゃんけん | キャラクターやスキルの合成、生成AIによる画像作成へ展開する | 合成元と合成結果のデータ、合成ルール、キャラクター画像・スキル画像 |
| ショップ | 発注管理・在庫管理などの店舗業務へ展開する | 仕入先への発注・明細、入荷の記録、入出庫履歴と在庫数 |

具体例は[目標と参考プロンプト](04_extension-catalog.md)。一度に一つだけ選び、受講者がAIと相談して試す。資格学習への応用を、新たな資格教材一式の制作・試験対策保証として扱わない。

## 今回の制作計画から外すもの

| 領域 | 提供者の追加制作に含めない機能 |
|---|---|
| 写真日記 | 保存後の日記編集・削除、画像差し替え、共有アルバム、コメント、画像一括処理 |
| キャスト評価 | ルール履歴、月次結果の確定保存、本人用画面、複数店舗、POS連携 |
| 英語訓練 | 音声入出力・音声管理、自動学習計画、一括問題生成、講師との共有 |
| ショップ | 決済・返金・配送、在庫引当、永続カート、運営者管理一式 |
| 共通 | 応用のためだけの新しい認証・共有基盤（Web版のSupabase Auth移行は[ADR 0004](../../../docs/adr/0004-auth-gas-simple-web-supabase.md)で別に計画）、ストリーミング、処理待ち行列、大量取込・外部同期 |

これは現在の配布・制作計画の境界。共通テンプレートに既にある編集・管理・出力等の機能を削除する指示ではなく、各教材へ自動的に採用しないという意味。既存のAI利用金額のダミー表示を、実課金集計の新規開発へ広げない。

## 土台で共通化する範囲

[Web共通仕様](../02-web-app-learning/template/docs/shared-foundation-requirements.md)のF1（テキスト＋画像のAI入力）、F2（要求状態・再送・結果利用）、F3（投稿固有の管理・復旧依存の分離）を先に整える。ユーザー・設定・画像・DB・画面部品・Playwright・復旧は既存基盤を再利用する。日記・問題・採点・実績・スキル・カート・注文は教材側の責務とし、土台の完成条件へ積み増さない。

ダミーデータによる画面・操作の確認は制作途中の検証として使う。実際の保存・AI・画像との接続を確認した完成版とは区別する。

## 完成と支援の終了

配布する基本機能は、対象の操作・保存結果・必要な公開範囲・失敗時の案内と復旧を各基盤で確認する。既存の検証手順や共通テンプレートを再利用し、データを守る処理を省いて規模を減らすことはしない。

提供者は合意した基本範囲、導入・確認・戻し方、任意の目標とプロンプトを渡し、決めた支援の枠で終了する。枠終了時に未達なら未達と記録し、標準教材の不具合・本人の継続課題・別の要望を分けて次の扱いを明記する。初回は一つの課題でAIへ依頼・試行・結果確認を経験できれば成功。横展開先の完成や継続保守を支援終了の条件に加えない。

## 現行実装・仕様との差分

| 対象 | 文書更新時点の差分 |
|---|---|
| じゃんけんGAS版 | 既存READMEにはスキル・管理画面AIの実装記録がある。通常じゃんけんへの簡略化は別の実装変更。既存データの削除・初期化で済ませない |
| ショップGAS版 | 既存設計には画面内カートがある。新方針は直接注文。画面・注文手順・受入条件の更新が必要であり、変更済みとは記載しない |
| 写真日記・英語訓練 | 現行GASの基本機能をWebでも完成範囲とする。写真日記の保存後編集や英語の音声機能をWebへ追加する前提を撤回 |
| キャスト評価 | 現行の管理者限定・単一店舗の基本設計を両版で使う。ルール履歴等の発展機能は制作対象にしない |

この文書は範囲の決定。アプリコード・DB・公開環境の改修完了や、新規配布済みの証拠にはしない。
