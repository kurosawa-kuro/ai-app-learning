# 横展開の目標と参考プロンプト

[配布する基本範囲](feature-allocation.md) · [アプリ学習の対応表](../README.md) · [初回のAI並走](06_first-pairing-pilot.md)

提供者は、完成した基本範囲を使い、受講者がAIと一つの変更を試すための目標・参考プロンプト・確認例を渡す。以下は**任意の学習材料**であり、応用アプリの制作一覧や、提供者が完成・保守する機能の一覧ではない。全部を試す必要はない。

## 使い始める条件

以下のプロンプトは、対象版で記載した基本機能が実装・検証されてから使う。未実装なら、既存データを読んで変更案・期待結果を作るところで止め、応用のつもりで基本機能一式の制作を抱え込まない。検証用コピーを使い、採用した変更と戻し方を残す。

## 目標の選び方

| 教材 | 目標の提案例 | 再利用する仕組み | 本人が確かめること |
|---|---|---|---|
| english-trainer | 英語学習を資格学習へ変えてみる | 問題・回答・AI採点・テキスト会話・振り返り・履歴 | 正答・誤答の評価、説明の根拠、履歴への保存 |
| photo-diary | フォローシステムを備えたXのようなSNSへ展開する | 写真・タグ・AI下書き・手直し・保存・一覧・詳細 | フォロー・解除でタイムラインが変わり、非公開の日記が他の利用者に表示されないこと |
| cast-evaluation | 店舗で重視したい項目の配点を変えてみる | 既存の実績・設定・月次集計・順位 | 同じサンプル実績で、計算結果が事前の予想どおりに変わること |
| skill-janken-game | キャラクターやスキルの合成、生成AIによる画像作成へ展開する | Web版のスキル・対戦判定・保存・表示 | 合成結果と対戦時の効果が決めたルールに合い、生成画像が対象のキャラクターやスキルに表示されること |
| online-shop | 発注管理・在庫管理などの店舗業務へ展開する | 商品・数量・明細の保存、一覧・詳細、入力検証 | 発注数と入荷数を区別でき、入出庫履歴から計算した在庫数が一致すること |

## 英語訓練から資格学習へ

GAS・Webの英語訓練は、個人用のクイズ・AI採点・テキスト会話・振り返り・学習履歴で完成。応用では学習対象を変え、既存の流れを再利用する。資格の全範囲や試験制度への対応を一度に目指さず、本人が選んだ一分野と少数のオリジナル問題から始める。

| 英語学習での役割 | 資格学習へ変更する例 |
|---|---|
| 英語のクイズ | 資格で学ぶ用語・仕組みの確認問題 |
| 自由記述のAI採点 | 答えに必要な要点と、根拠に沿った説明の確認 |
| テキスト会話 | 学習者が用語や理由を説明し、AIが問い返す練習 |
| 振り返り | 間違えた理由と、次に確かめることの整理 |
| 学習履歴 | 問題・回答・評価を後で確認する記録 |

参考プロンプト：

```text
この英語学習アプリを、私が学ぶ［資格名・分野］の練習用に変えてみたいです。
現在のクイズ・AI採点・テキスト会話・振り返り・学習履歴を再利用してください。
まず［参考資料・自分の学習メモ］を基に、少数のオリジナル問題で試したいです。
変更が必要な表示文言、問題データ、採点基準、会話の指示を調べ、最小の変更案を示してください。
新しい外部サービス・音声・自動学習計画・一括生成は追加しません。
既存の英語教材や履歴を壊さないコピーまたは検証環境で、一つずつ変更します。
正答・誤答の例と期待する結果、保存確認、変更の戻し方も示してください。
仕様上そのまま使えない部分は、追加実装する前に理由と小さく試す方法を説明してください。
```

本人は参考資料と期待する要点を用意し、AIの評価・説明を照合する。完成した資格学習アプリや、試験範囲全体の問題集を提供者の追加成果物にはしない。

## 写真日記からフォロー型SNSへ

目標例：写真・タグ・AI下書き・投稿の仕組みを再利用し、フォローシステムを備えたXのようなSNSへ展開する。最初はフォロー・解除と、フォローした人の公開投稿を新しい順に読むタイムラインを試す。写真日記の基本完成後に選ぶ任意の応用として扱う。

```text
この写真日記を、フォローシステムを備えたXのようなSNSへ発展させたいです。
写真・タグ・AI下書き・手直し・保存・一覧・詳細の仕組みを再利用してください。
まず利用者の識別、投稿者、公開範囲の現状を調べ、必要な画面・保存項目・処理の最小変更案を示してください。
フォロー・解除と、フォローした人の公開投稿を新しい順に読むタイムラインを、一つずつ追加して試したいです。
既存の日記は勝手に公開せず、投稿者が公開を選んだものだけを他の利用者に表示してください。
検証用コピーで架空の利用者3人と投稿を用意し、フォロー前・フォロー後・解除後の表示を比べてください。
自分自身へのフォローと重複登録を防ぎ、非公開の日記が一覧・詳細・画像から他の利用者に見えないことも確認してください。
最初はいいね・返信・リポスト・通知・DMを加えず、変更の戻し方も示してください。
```

## キャスト評価の配点を変える

目標例：同じ実績でも、重視する項目によって順位がどう変わるかを予想して試す。既存のナイトワーク向け・単一店舗の範囲内で扱い、別業種版は制作しない。

```text
この評価アプリで、既存項目の［項目名］を重視する配点に変えてみたいです。
新しい項目・ルール履歴・月次確定・複数店舗・外部連携は追加しません。
変更前後の配点と、架空の少人数の実績で期待するポイント・順位を示してください。
検証用コピーで既存の設定を変更し、計算結果を照合する手順と戻し方を教えてください。
ルール変更で過去期間の再計算結果も変わる現行仕様を前提にしてください。
```

## じゃんけんからキャラクター・スキルの合成と画像生成へ

Web版の基本提供はスキルありのじゃんけんと、AIによるセリフの事前作成まで。完成後の任意の応用として、キャラクター同士やスキル同士を合成する仕組みと、生成AIで作成したキャラクター画像・スキル画像の利用へ展開する。最初は少数の合成例と、事前に生成して採用した画像で試す。

```text
Web版じゃんけんを、キャラクターやスキルを合成して遊べるように発展させたいです。
キャラクター画像・スキル画像も生成AIで作成して使いたいです。
まず既存のスキル・対戦判定・保存・表示を調べ、キャラクター管理を含めて不足する仕組みと最小変更案を示してください。
検証用コピーで、キャラクター同士とスキル同士の合成を一例ずつ用意し、一つずつ試します。
合成元、合成条件、合成後の能力・効果、元のキャラクターやスキルを消費するかを明示してください。
合成結果と対戦時の効果は決めたルールに従って処理し、期待する結果と照合してください。
合成前後の特徴が伝わる画像生成用プロンプトを用意し、事前に生成・確認した画像を対象に紐づけて表示する手順を示してください。
合成結果を保存して再表示でき、画像がない場合も遊べることを確認してください。
同じ操作の再送で合成や消費が二重に行われないことを確認し、変更の戻し方も示してください。
```

## ショップから店舗の発注管理・在庫管理へ

目標例：商品・数量・明細を扱う仕組みを再利用し、仕入先への発注管理や、入出庫を記録する在庫管理へ展開する。基本の注文教材を完成させた後、まず単一店舗・少数の商品で発注、入荷、在庫確認の流れを一つずつ試す。

```text
このショップ教材を、店舗側の発注管理・在庫管理へ発展させたいです。
既存の商品・数量・明細の保存、一覧・詳細、入力検証を再利用してください。
顧客からの注文と仕入先への発注を区別し、必要な画面・保存項目・処理の最小変更案を示してください。
まず検証用コピーで、架空の単一店舗・仕入先・少数の商品を使います。
仕入先への発注と明細、入荷の記録、入出庫履歴と在庫数の確認を、一つずつ追加して試したいです。
発注しただけでは在庫を増やさず、入荷済みの数量だけを加算し、出庫時に減算してください。
初期在庫10個、発注5個、一部入荷3個、出庫2個なら、在庫11個・未入荷2個になることを確認してください。
同じ入荷の再送で在庫が二重に増えないことと、入力誤りの訂正方法も示してください。
最初は実際の仕入先への送信やPOS連携・複数店舗対応を加えず、変更の戻し方も示してください。
```

## Web英語訓練の任意の応用：問題管理画面

基本の完成後に選べる小さな候補。問題一覧・新規作成・編集までとし、既存の問題形式や版管理を再利用する。提供者の必須の追加制作や、今回の実装着手を意味しない。

```text
既存の英語訓練アプリのWeb版で、問題を画面から作成・編集できるか検討したいです。
まず現在の問題形式、保存処理、入力チェック、問題版と過去回答の関係を調べてください。
問題一覧・新規作成・編集の最小構成を提案し、既存の処理を再利用してください。
AI一括生成、CSV取込、音声、講師管理などは追加しません。
作った問題を既存クイズで使え、編集しても過去回答・採点記録の意味が変わらない確認方法を示してください。
大きな基盤変更が必要なら、実装前に範囲を減らす案を示してください。
```

## 提供と支援を終える条件

提供者は基本教材と、このような目標・参考プロンプト・確認例を渡す。学習者は次に試す一つを選んでも、今回は終えてもよく、全応用の達成や、応用先の継続保守を提供者の終了条件にしない。相談を受ける場合も、合意した課題・回数・期間で区切る。

旧案の音声、決済・在庫引当、複数店舗・POS、共有、攻略アドバイザー等は、今回の教材制作計画から外す。上記のSNSや発注管理・在庫管理への展開は、基本完成後に選ぶ任意の学習材料として扱う。提供者の必須制作機能を「Web限定候補」として積み上げる運用は行わない。

## 保留する過去案：AI利用金額の実集計

以下は過去の追加構想の参照記録であり、今回の完成条件・横展開課題には加えない。既存のダミー表示と実課金集計を分け、実集計は別に採用を決めた場合だけ扱う。

AI を利用する各アプリで、利用ごとの金額・今月の合計・累計を確認できるようにする構想。元のメモを横断的な追加機能案として整理したもので、各アプリへの実装済み要件ではない。

| 項目 | 表示・記録する内容の案 |
|---|---|
| 利用ごとの金額 | 1 回の AI 要求に対応する利用量と推定金額 |
| 今月の使用金額 | 定義した月の範囲に含まれる要求の推定金額合計 |
| 累計の使用金額 | 記録開始以降の推定金額合計 |
| 根拠 | 実行日時、アプリ、要求 ID、モデル、入力・出力等の利用量、適用単価と通貨 |
| 成否・不明状態 | 成功・失敗・結果不明と、利用量を取得できたかどうか |

将来あらためて採用する場合だけ確認すること：

- 月の区切りは Asia/Tokyo を候補とし、集計対象の利用者・アプリ・記録開始日を定義する。
- 推定金額とプロバイダーの請求額を区別する。単価・モデル・料金の適用時点を記録し、実装時に公式の料金情報を確認する。
- 同じ要求 ID の結果再取得を新たな AI 利用として二重計上しない。実際に追加の API 呼び出しが発生した場合は、その実行を区別して記録する。
- 結果不明や利用量未取得を 0 円とみなさない。未集計件数などで不完全な集計だと分かるようにする。
- 表示機能と、利用上限・警告・課金停止は別機能として扱う。

現時点の対象候補は写真日記・英語訓練の両版と、じゃんけんのWeb版でのAI利用。EC とキャスト評価の初期仕様には AI 機能がないため、金額表示のためだけに AI 機能を追加しない。
