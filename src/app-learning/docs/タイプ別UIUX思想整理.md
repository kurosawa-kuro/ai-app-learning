## 1. 思想：主役・機能・作業段階で決める

主役は、その画面に来た目的となる内容・作業。機能は、主役を探す・扱う・確定する・続けるための手段である。分類の単位はアプリ名ではなく画面と作業段階。一つのアプリに一覧・詳細・編集・実行の型が混在してよい。

| 原則 | 配置や操作の判断 |
|---|---|
| 主役を先に見せる | ニュースは情報カード、学習は問題と回答、動画仕分けは内容を判断する動画。管理情報を先に通過させない |
| 必須操作を隠さない | 回答・提出・判断・保存・録音停止は、必要な段階ですぐ使える。支える機能を低重要度と同義にしない |
| 次の操作を近くに置く | 入口→選択→適用→次の行動の距離を見る。画面が広がっても右端や中央への移動を増やさない |
| 名前を探す人に合わせる | 「クイズ」「フリーテキスト」など利用者が探す名前を使う。説明文や内部処理名へ置換しない |
| 作業の文脈を守る | 対象名・条件・位置・未保存入力を保持。新着・再取得・保存で勝手に対象を飛ばさない |
| 成功の意味を分ける | 入力、保存、受付、実行、反映、結果確認を区別。失敗・未取得を0件や完了にしない |
| 管理を整えて主画面を軽くする | 継続設定・登録・診断を管理へ整理。日常の回答・判断・棚切替は主画面に残す |
| 型に合う品質で測る | 一覧の密度、学習の集中、編集の確実さ、起動の速さを別々に評価。同じ列数や余白を全画面へ強制しない |

「思想が未整理」「思想に実装が追いつかない」「文書が古い」「実機で未確認」は別の課題。公開済みの改修を、未測定項目があるだけで未設計へ戻さない。

### 2.3 配置案の比較と採否

| 論点 | 採用する考え方 | 採用しない／条件付きの案 | 理由 |
|---|---|---|---|
| 短い選択・条件 | PCは起点に近接、狭幅は下部シート | 画面右端・中央への無条件固定 | 毎回のマウス移動を減らす |
| ニュースの種類 | 上部横一列・常設・即時切替 | 種類を開いてから選ぶ | 頻用操作を1クリックで済ませる明示特例 |
| 多軸の絞り込み | 同じ面で下書き編集→適用／取消 | 全条件を多段常設、全入力を即適用 | 内容領域と、まとめて条件を作る操作を守る |
| アプリ切替 | その場の固定4入口 | 中継ランチャーページ、全画面へ常設4項目バー | 普段の主役を圧迫せず直接移る。全一覧は既存ランチャーへ |
| 管理 | 共通の枠＋アプリ固有の保存契約 | 全フォームの自動生成、一括保存の強制 | 見方を揃え、業務境界は維持する |
| 動画の判断 | 常時表示して三軸をまとめて保存 | 判断ボタンを押すまでフォーム非表示、単軸変更で次へ | 繰り返す作業の開閉を減らし、同じ1本を判断しきる |
| 長文・画像拡大・重要確認 | 内容を確認できる専用面 | すべてを小さな近接ポップアップへ変換 | 対象確認と可読性が必要。距離は別に測る |

<a id="decisions"></a>

## 3. 決定：共通ルールとタイプ固有の契約

この節は採用したルール。全アプリへの適用完了を意味しない。実装・未適用は第5・6節で確認する。

<a id="interaction-proximity"></a>

### 3.1 操作の近さ・常設・適用

| ID | 決定 | 実装・確認の基準 |
|---|---|---|
| D01 | 短い選択・条件・切替は起点の近くへ | PCは8 CSS pxを基本間隔にする。画面端のみ補正・上下反転。起点のない直接URLは画面内へ配置 |
| D02 | 選択から適用まで同じ小さな範囲で完結 | 条件パネルは内容に合う高さ。現行ReadingSheetは最大520px、編集面は最大640px。長い本文を内部スクロールし操作帯を見失わない |
| D03 | 種類と条件を区別 | 単一範囲の選択は即時切替、多軸条件は下書き→適用。取消は未適用値を破棄 |
| D04 | ニュース種類だけは開閉しない | 全部・記事・作品・漫画・SNS・トレード・PG・アダルトを上部一列。既存の表示可否設定を守り、狭幅は横スクロール |
| D05 | 開閉で文脈を壊さない | Esc・戻る・フォーカス復帰・未保存保護・背景スクロール制御。最前面以外へキー操作を漏らさない |
| D06 | 位置計算を共通化 | `useAnchoredPanel`が起点・画面端・高さ・resize・visualViewportを所有。AppSwitcher／ReadingSheet／対応フォームで利用し、各アプリへ複製しない |

狭幅は下部シートを使い、キーボード・安全領域・短い画面でも操作可能にする。CSS上の8pxは起点との間隔であり、利用者の物理マウス移動量を測った値ではない。

<a id="shared-ui"></a>

### 3.2 アプリ切替と管理

固定入口は **ニュース → お気に入り → 学習 → ランチャ**。名前・画像・URL・順序はmanifest/catalogを正本とし、履歴APIの成功を表示条件にしない。現在のアプリを選ぶと閉じるだけ。実装済み3アプリでは通常操作を同一タブの正式URLへつなぎ、別タブは通常のリンク操作で選べる。

切替はダイアログの履歴を閉じ、離脱保護を通してから遷移する。未提出回答・未保存入力・応答不明の処理を共通側が勝手に保存・再送しない。録音等の資源解放と、ジョブ処理継続の意味はアプリ側が所有する。

| 管理の共通枠 | 決定 |
|---|---|
| 入口・現在地 | アプリ名／管理／項目と、主作業へ戻る入口。直接URL・再読込でも戻れる |
| 区分 | 設定・登録対象・状態／履歴のうち、存在する項目だけ出す |
| フォーム | 項目名、対象、保存範囲、入力、説明、エラー、未保存、確定操作を揃える |
| 保存状態 | 未保存・保存中・保存済み・失敗・結果確認待ちを分ける。失敗をtoastだけで消さない |
| 保存方式 | 明示保存と既存の即時保存を区別。複数業務を一括保存へ丸めない |
| 危険操作 | 登録解除・復習リセット・全再生成等は対象と影響を個別表示 |
| URLとAPI | 既存routeを尊重。管理画面のために存在しない書込API・空区分を増やさない |

共通化するのは表示枠、移動、状態の見せ方、入力保護の接続。採点、請求、動画判断、再送の可否、完了判定は各アプリが所有する。UI統一のための新認証・DB・queueや、全アプリ同時mountは導入しない。

<a id="card-ui"></a>

### 3.3 情報カード

ニュース・お気に入り・シグナル・YouTube要約では、カードと選んだ本文が主役。対象の内容・出典・必要な状態が見え、読む→開く→元の位置に戻る流れを守る。

- 種類・棚・レンズと、今回の追加条件、継続する表示設定を分ける。ニュース種類の常設特例を他の全条件へ拡張しない。
- PCの多列とスマホの縦スクロールを使い分ける。画像、漫画、人物、構造化本文を同じカード高さへ潰さない。
- 画像上からも縦スクロールできる。画像送り・ドラッグを必要な場所に限定し、タッチ開始領域を奪わない。
- 読みやすさを保ちながら内容の見える量を増やす。フィルタの行数削減だけで品質を判定しない。
- 読込中・空・取得失敗・古い情報を区別。新着や再取得で読んでいる位置を勝手に移動させない。

<a id="learning-ui"></a>

### 3.4 学習

**「クイズ」「フリーテキスト」を同じ階層・強調度の主機能として扱う。** 主ナビ「今日・練習・記録」と、今日の推奨一つは維持する。

| 決定 | 必須の振る舞い |
|---|---|
| 正式名を統一 | 入口・切替・見出し・記録でクイズ／フリーテキストを使う。「思い出して答える」「自分の言葉で説明する」は説明に留める |
| 二形式を対等に | 今日・練習・記録から一方だけへ偏らせない。対話・個人問題は補助機能。教材不足等でも形式名と使えない理由を残す |
| 回答前に答えを出さない | many / much、正解英文、模範解法、答えを示す課題名・能力ラベル・推奨根拠を回答前の一覧へ出さない |
| 選択・入力と提出を分離 | 両形式とも下書き→「回答を提出する」。提出前の変更で採点しない |
| 同じ形式で続ける | 結果→次のクイズ／次のフリーテキスト。書き直しは任意。形式変更で対象・入力を無断で失わない |
| 記録と管理を分離 | 履歴は保存情報に基づく形式表示。教材・評価処理・AI設定は管理へ。内部方式を通常回答の操作メニューにしない |

対等とは教材数や問題数の機械的な半分ずつではない。選べる入口と学習の流れを対等にし、教材・採点の品質と形式別の不足は別に評価する。

<a id="video-ui"></a>

### 3.5 動画仕分け

**主役は、サムネイルで内容を判断する動画。** 三軸判断は主要機能、フォルダ設定・サムネイル生成・ジョブ監視は準備と管理。デスクトップを主用途とし、モバイルは判断保存の補助とする。

| 決定 | 必須の振る舞い |
|---|---|
| 全体の時系列を見渡す | 一覧は全フレームから等間隔に選ぶ最大3×3枚。先頭9枚だけにしない。時刻、なければ番号を表示 |
| 何の動画かを見失わない | ファイル名はスクロールしても固定。一覧はカード内、詳細はヘッダー直下。大きな診断欄まで固定しない |
| 判断欄を常時表示 | 「この動画を判断」を押さなくても評価・属性・処遇を操作できる。一覧は保存後も開いたまま。詳細はPCで横、狭幅で画像下 |
| 同じ動画にまとめて判断 | 三軸変更だけで次へ進まない。詳細は保存成功後に次へ。保存失敗・競合を保持 |
| 判断保存とファイル反映を分離 | 判断済み／未反映を区別。反映は対象と変更予定を確認。実ファイル削除を通常のUndoで戻せると約束しない |
| 続けやすく戻れる | 前へ、保留、未反映判断を戻す、一覧位置復元。新着を作業中の並びへ勝手に混ぜない |
| キー操作も同じ業務処理へ | 選択中の1本が対象。入力中・IME・長押しは抑止。判断の文字キーは変更／無効化可能、移動キーは固定 |
| 名前からフォルダを開く | 導入済みWindows連携で対象・版・実ファイルを照合しExplorerを開く。Windows以外はパスコピーであり、遠隔PC起動ではない |
| 進行を追える | `/jobs`と詳細、フォルダ設定を分離。受付・進行・部分失敗・ファイル別の結果を同じ完了に丸めない |

モバイルで保存した判断を後でPCから確認・反映する使い方は可能性のある補助導線。反映依頼は「PCでの承認待ち予約」と同義ではなく、指定時刻実行・PC起動予約は未提供。物理スマホの一連の受入は別途必要。

| 5／P2 | 追加距離候補：不具合未確定 | S08契約の下部操作、S11動画生成、S12反映確認、S13通知再送、S14メモ端の配置を測る | 確定バグ／改善候補／問題なしへ判定。対象確認は維持。[事故台帳](../../docs/tasks/03_active/共通画面-アイコン誤表示と遠い操作導線を修正する.md) |

P0の端末確認が接続待ちでも、独立して進められる主力整備は止めない。完了範囲を戻してやり直さず、不足分だけを台帳へ具体化する。

### 6.2 思想・既存設計の補強順

| 順位 | 対象と課題の種類 | 整理する判断 | 現時点の扱い |
|---|---|---|---|
| 1 | AI作業プロンプト：思想の補強 | 候補選択→内容確認・変数入力→完成文コピーで主役をどう移すか。スマホで候補をいつ畳むか | 3列を狭幅で縦にするだけでは段階設計の完成ではない。原文編集・AI実行は追加しない |
| 2 | コンテンツ即時要約：思想の補強 | 素材入力→進行→要約本文の優先表示。新規作成・履歴・審査・継続登録の主従 | YouTube要約閲覧の完了とは別。未提供の取消・再試行を約束しない |
| 3 | 体重：明確な思想の具体化 | 「継続優先・1日30秒」を通常日の最短入力、任意項目、保存範囲へ落とす | 30秒は目標であり実測合格ではない。日次と個別保存を混ぜない |
| 4 | 契約・請求：思想と実装の整合 | Action → Risk → Deadline → Costの順へ表示を合わせる | 主従の思想は既にある。近接フォーム修正だけでDashboardの順序まで解消したとしない |

ニュース・お気に入り・学習・動画・シグナル・YouTube要約・AI開発枠・画像管理・音声・ランチャ・メモは、主要思想を整備済み。残る実測・品質・未適用範囲を個別に扱う。

### 6.3 未決事項・今回追加しない機能

| 論点 | 現在の境界 | 決める条件 |
|---|---|---|
| 全アプリの同一タブ化・状態保持期間 | 先行3アプリの保存範囲のみ確定。全ページ位置の永続復元は未提供 | 各アプリの離脱保護と保存寿命を確認 |
| ピン留め・最近使ったアプリ・端末間同期 | 固定4入口に必須化しない | 実際の起動負担と保存先が確認できること |
| 管理route・書込APIの新設 | 実在する管理対象だけ扱う | 所有アプリと保存契約を確認してから判断 |
| 動画の予約・遠隔PC起動 | 判断保存と反映依頼のみ。指定時刻実行等は未提供 | 実行条件・待機・期限・承認の意味を先に確定 |
| 学習の教材バランス・採点品質 | UI修正の完了とは別、全課題の分布・利用率・AI応答は未測定 | 教材数・推奨分布・開始／離脱・採点品質を別の評価として計測 |
| 共通検索・CSV・印刷・Undo・自動保存 | 全アプリ必須にはしない | 利用目的と既存契約がある場合に限る |

## 7. 受入条件と、この文書の更新ルール

### 7.1 受入条件

| 観点 | 確認すること |
|---|---|
| 主役・必須操作 | 初期表示で目的の内容が見える。提出・保存・停止・判断が必要な段階で見つかる |
| 距離・寸法 | PC1280／1920／3840／5120px、狭幅390px、200%拡大、画面端・短い画面。入口→選択→適用の距離が画面幅に比例増加しない |
| 操作と復帰 | Tab・Esc・戻る・閉じる・フォーカス・スクロール復元。開閉取消で入力と元画面を失わない |
| 保存と外部作用 | 未保存・保存中・応答不明・失敗・競合を用意。二重送信しない。公開の読取検査と書込試験を分離 |
| 型固有 | 閲覧は読める密度、学習は正解先出しなし・二形式、動画は名前固定・判断常設、実行は受付と完了の区別 |
| 入口の識別 | 初回HTML・描画後・公開assets・旧URL・PWA・Windows入口を分けて検査 |
| 公開・端末 | ローカル成功だけで完了にしない。公開成果物と実APIを確認し、物理端末未確認は残す |

これは今後も使う受入基準であり、全画面・全幅で既に合格した一覧ではない。実施済み範囲は検証記録を参照する。

### 7.2 状態の書き方と正本

| 状態 | 意味 |
|---|---|
| 決定済み | 採用した方針。実装済みとは限らない |
| 候補・未決 | 根拠を集めて判断する段階。確定バグと区別 |
| 未実装／修正途中 | コードが未完成 |
| 検証済み・未反映 | 検査範囲は明記するが利用者はまだ使えない |
| 公開確認済み | 配布した成果物の対象操作を公開で確認 |
| 未確認 | 手段・対象・不足する確認を明記。成功へ読み替えない |
| 完了 | 合意した範囲の実装・必要な検証・反映・記録が揃い、その範囲の残件0 |

本書には思想・決定・特例・比較・状態の要約だけを置く。タスクを進めたら、詳細台帳と本書の該当行を同時に更新する。配布SHA・全試験ログ・日々の経過を追記して本書を再び巨大化させない。古い章番号参照より固定アンカーを使う。
