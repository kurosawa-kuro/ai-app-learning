## 対象者とゴール

自分用・業務用のアプリを作って使いたい非エンジニアが対象。本人の困りごとを小さな1課題に絞り、動くひな形を使ってAIへ変更を依頼し、結果を確認しながら改善できることを目指す。Java資格・転職・全技術の習得を前提にしない。

受講順は **01 GAS → 02 Web**、提供者の制作順は **02 Web → 01 GAS**。全5教材の履修は必須ではない。提供者が要望整理・環境・最初の公開を支援し、合意した回数・時間・期間で引き渡す。無期限の運用代行は含めない。

## 実行基盤・AI・認証

| 項目 | この版の構成 |
|---|---|
| 実行・画面 | Spring Boot／Spring MVC／Thymeleaf。RenderへDockerで公開 |
| データ・画像 | Supabase PostgreSQLへJDBCで接続。必要な教材はSupabase Storage |
| アプリ内AI | 写真日記・英語・じゃんけんの事前生成にOpenAI Responses API。templateにも疎通・下書き機能 |
| キーの保存 | ローカルはGit対象外の`.env`、Renderは環境変数に`OPENAI_API_KEY`。ブラウザーへ渡さない |
| 公開範囲・認証 | 現公開版は認証なし。Supabase AuthのGoogleログインは6アプリのコード実装済み、既定無効・実Google／Render受入は未実施 |

採用基盤の判断は[ADR 0001](../../../docs/adr/0001-web-app-stack.md)、認証の設定・権限境界は[Googleログインの設定と確認](docs/Googleログインの設定と確認.md)。利用者選択と本人認証を区別する。

AIの既定モデルは`OPENAI_MODEL=gpt-4.1-mini`で、管理画面の許可一覧にも登録する。コードのタイムアウト既定は20秒、10/28の公開設定は`OPENAI_TIMEOUT=30s`。`APP_AI_MODE=demo`の固定応答と`live`の実通信を区別する。明示操作とAI許可を前提に呼び出し、`store:false`を指定する。Geminiへのフォールバックや失敗時の自動再試行は行わない。

コードの質問・改造はDevin、アプリからのAI呼出しはOpenAI API、業務自動化の質問・作業はCursorという分担。AI不要の教材へ接続機能を追加しない。

## 始め方と改修の進め方

1. 上の一覧から1教材を選び、そのREADME・AGENTS.md・現行仕様を読む。共通基盤は[template](template/README.md)を参照する。
2. 架空サンプルで基本操作を体験し、変えたい箇所と期待結果を一つ決める。環境・DB接続・最初の公開は提供者が伴走する。
3. 新規教材はtemplate一式を丸ごとコピーする。既存5教材はコピー済みの土台を維持し、固有実装を全体上書きしない。[必須ルール](AGENTS.md)に従う。
4. 固定AI応答で入力・結果・保存・再読込を先に確認し、必要な実DB・Storage・実AI・公開先で受入する。共通修正はtemplateと該当教材へ反映する。
5. 確認した業務ルール・入力例・期待結果をGASへ引き継ぐ。本人には依頼文・確認方法・戻し方を渡し、合意した支援枠を終了する。

別用途への横展開は、対象者・データ・ルール・公開範囲を改めて定義して小さく試す。本人による応用と、正式教材の追加制作は分ける。既存データと適用済みFlywayを保全し、秘密情報はGit・ログへ入れない。
