# 教育用スターターの最小構成

2026-10-27更新。教育目的の軽量化方針。過去の完了報告・課題一覧より、この範囲を優先する。

| 残す機能 | 教育上の役割 |
|---|---|
| 投稿CRUD・検索・10件ずつのページャー | データ保存、条件、一覧と詳細の関係を学ぶ |
| 投稿画像・ユーザーアイコン | ファイル選択、保存、表示、差替えを試す |
| ユーザー作成・編集・切替・デフォルト指定 | user : post = 1 : m を試す。認証ではない |
| 画像／AIのON・OFF、AIモデル制限 | 設定でアプリの動きを変える |
| OpenAI疎通・本文＋任意画像の下書き | AI呼出し、結果確認、採用／破棄を試す |
| CSVエクスポート | 保存データを外へ出して確認する |
| じゃんけんUI例・12件のシード | 別題材への応用と、実データのある画面を確認する |

## 外したもの

- Basic認証、ログイン設定、APP_ACCESS_USER／APP_ACCESS_PASSWORD。
- 独自バックアップZIP・別スキーマ復元・状態と復旧画面。
- HTTP操作フィルターと監査記録のDB書込み。
- AI要求のDB台帳、期限切れ定期処理、再起動をまたぐ下書き復元。
- 全画面の環境・接続情報バナー、接続識別値の計算。
- 投稿者選択時の全投稿件数集計、アイコンのユーザーごとの照会、無関係な画面のJS／CSS。

## 軽量化しても維持すること

入力検証・画像上限・CSRF・設定のサーバー側確認・モデル制限・入力保持・二重送信対策・編集競合・参照中ユーザーの削除防止・画像保存失敗時の補償を維持する。画像の後片付けは保存／削除時と明示CLIだけで行い、監視画面やスケジューラーは持たない。

AI下書きは1ブラウザーセッションの直近1件だけを保存する。本文反映後は普通の投稿保存で確定する。生成中の同一要求再送は再実行せず、同じブラウザーの並行生成も拒否する。新しい生成・セッション終了・再起動で古い下書きは失われる。長期保持・監査・復旧は教材の共通要件にしない。

## DBと既存データ

既存投稿・画像・設定は維持する。適用済みFlywayは書き換えない。V10で[DBを6表へ再設計](database-design.md)。旧 `operation_events`・`ai_requests` はデータがある場合だけ別の `_legacy` スキーマへ退避する。投稿・画像参照・設定は維持し、アイコンをユーザーへ統合、許可モデルを行単位へ正規化する。

認証なしはAPP_AUTH_ENABLED=falseの場合。Googleログインのコードは実装済みで、trueではSupabase Authとapp_adminsにより管理者だけに全操作を許可する。管理者間のデータは共有し、投稿者選択は本人認証ではない。実Google・Render受入は未実施。[設定と確認](../../docs/Googleログインの設定と確認.md)を参照。

2026-10-28決定：Supabase Authによる本格版へ移行する予定（[ADR 0004](../../../../../docs/adr/0004-auth-gas-simple-web-supabase.md)）。コードは実装済み、実環境受入・有効化は別途必要。Basic認証・APP_ACCESS_USER／APP_ACCESS_PASSWORDは「外したもの」のまま戻さない。

## 手動DB接続確認（2026-10-28追加）

ユーザーの明示依頼により、管理画面に「DB接続を確認」を追加。押したときだけ `SELECT 1` を実行し、成功・失敗と所要時間を表示する。初期状態は未確認。接続先・パスワード・SQL例外は画面へ返さない。自動監視・全画面での確認・監査記録は追加していない。確認は接続可否の判定であり、全機能の動作保証ではない。
