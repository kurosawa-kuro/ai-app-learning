## 共通AI基盤との関係

本課題は[共通仕様F1・F2](shared-foundation-requirements.md)の最初の一歩。まず固定文1回の疎通を実装するが、使い捨てのController内HTTP処理にはせず、後で教材から呼べる小さな公開APIとAdapterに分ける。

疎通に加え、検証済み画像の任意入力、AI要求の状態・成功結果の再取得、下書きの確認・破棄・本文反映を実装した。日記生成・英語採点・セリフ生成の指示と確定保存は各教材が担当する。疎通成功だけでこの共通基盤全体や3教材が完成したとはしない。

## 目的と範囲

提供者が、WebテンプレートからGeminiへ接続できるかを管理画面で確認できるようにする。受講順は01 GAS → 02 Web、提供者のコード・解説作成は02 Web → 01 GASのため、まずこのWeb側で接続とエラー処理を固める。

対象は明示的な1回の疎通確認。日記生成・会話・画像生成・自動呼出し・実課金集計は別課題とする。

## 接続設定

- キーはテンプレートの `.env` にある **`GEMINI_API_KEY`** を正とする。公開先では環境変数で管理する。
- キーの値をソース・HTML・ブラウザーの通信・ログ・ドキュメントへ含めない。画面には設定済み／未設定だけを表示する。
- モデル名等の非機密設定は型付き設定で管理し、実装時に公式情報と実環境で利用可能なモデルを確認する。会話メモのモデル名や料金を固定しない。
- 未設定でも通常の投稿・ユーザー管理・設定画面は起動できるようにする。

## 操作と責務

1. 管理画面にGeminiの設定状態と「接続を確認」ボタンを設ける。
2. サーバー側でAI許可設定を検査する。禁止中・キー未設定なら外部通信せず理由を表示する。
3. CSRF付きPOSTを受け、固定の短い確認文をサーバーから1回だけ送る。本文や個人の画像を勝手に送らない。
4. 接続先・認証・タイムアウト等を具体的Adapterへ閉じ込め、Domain/ApplicationへHTTPクライアントやキーを持ち込まない。
5. 成功時は、実際に応答を受け取ったこと、確認時刻、使用モデル、所要時間を表示する。
6. 認証失敗・利用制限・タイムアウト・接続失敗を区別し、再試行できる説明を出す。上流の生のエラー本文やキーは表示しない。

起動・画面表示・設定保存だけで疎通通信を発生させない。通信中は二重操作を防ぎ、結果が不明な場合に自動で再送しない。

## 実装と検証記録（2026-10-27）

- 入口：機能管理の「Gemini接続確認を開く」→ `/admin/ai`。実行は `/admin/ai/check` のCSRF付きPOSTのみ。
- `ai` モジュールの公開API `AiConnectivity`、Application `CheckGemini`、Port `GeminiGateway`、Adapter `GeminiHttpGateway` を追加。ApplicationにHTTP・Spring・秘密情報を持ち込まない。
- 設定：`GEMINI_API_KEY`、`GEMINI_MODEL`（初期値 `gemini-3.5-flash-lite`）、`GEMINI_TIMEOUT`（初期値20秒）。APIキーはサーバーの認証ヘッダーのみ。画面には設定状態だけを表示する。
- 同じセッショントークンの再使用を拒否し、同一プロセス内では並行実行も拒否。成功結果の永続再取得や複数サーバー間の制御は対象外。
- Javaの追加テスト14件成功。固定文・認証ヘッダー、禁止／未設定時の0回通信、401／403／400の無効キー、429、404、5xx、タイムアウト、不正応答、排他、トークン再送を確認。
- Springの模擬GatewayとPlaywrightで、管理画面の導線・禁止・CSRF拒否・確認中表示・成功・重複拒否・失敗・再確認・スマホ表示を確認。画面記録は `target/gemini-ui/`（Git対象外）。
- 既存テストは初回全体実行で成功。追加ブラウザーテストのみ、遷移中表示の観測方法を修正して再実行し成功。過去の別機能の全Playwrightケースを今回再実行したという意味ではない。
- `.env` のキーで利用可能モデルを取得後、実装したAdapterから固定文を1回送信。`gemini-3.5-flash-lite`、SUCCESS、4366 ms。投稿・写真・ユーザーデータの送信はない。
- 実APIテストは通常スキップ。内部の実APIテストは `RUN_GEMINI_LIVE=true` の明示指定時だけ有効にする。運用用CLIは後続のモデル制限追加で、起動中アプリの経路を使う方式へ変更した。自動テストで課金APIへ送信しない。

公式参照：[generateContent](https://ai.google.dev/api/generate-content)、[認証](https://ai.google.dev/api)、[モデル](https://ai.google.dev/gemini-api/docs/models)。確認日2026-10-27。Renderデプロイ・GAS実装は行っていない。

## モデル制限の追加

2026-10-27、管理画面に許可モデルの保存を追加。V8でDB保存し、全体のAI許可とは独立管理する。既定は疎通済みモデル1件、空欄は全禁止。画面表示時と送信直前に完全一致で判定し、使用モデルは `GEMINI_MODEL` のままとする。許可リストの保存ではAIへ送信しない。CLIも同じサーバー側判定を通す。

モデル制限追加後の検証：全体64件中63件成功・実APIテスト1件を意図的にスキップ。Playwrightで許可リストの保存・再読込み・空欄禁止・ワイルドカード拒否・直接POST拒否を確認。CLIの同一制限経路も追加確認して成功。通常設定と許可リストは検証前の値へ復元。今回のモデル制限検証では実Geminiへ送信していない。
