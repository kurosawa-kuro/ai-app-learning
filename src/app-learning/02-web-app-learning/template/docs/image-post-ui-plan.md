# 画像投稿を前提としたUI改善案

更新日：2026-10-27。状態：**実装済みの受入仕様**。横展開前課題の [P1-01・P1-06](improvement-backlog.md)を具体化する。

現行の部品・レイアウトは[共通UI設計](ui-foundation.md)が正本。カード化・画像拡大・編集フォームを実装済み。最新の検証結果は[完了記録](completion-report.md)を参照する。

## 解消した問題

改修前の一覧は管理用の表へ小さなサムネイルを追加していた。画像を読むための領域が小さく、画像・本文・投稿者の優先順位が曖昧になっている。改修前は3:2の切抜き表示で、図や文字入り画像の全体も確認しにくい。

画像あり・なしを同じ表へ押し込むのではなく、投稿を読むカード型フィードへ変更する。ユーザー管理・機能設定の管理画面までフィード化することは求めない。

## 一覧の到達像

PCでも中央の**1列フィード、幅760〜800px程度**を基本案とする。スマホでも情報の順序を変えない。写真を探すことが主目的となった場合に、グリッド表示を別途検討する。

| 領域 | 方針 |
|---|---|
| カード上部 | ユーザーアイコン・表示名・投稿日時をまとめる |
| 本文領域 | タイトル、本文の短い抜粋、続きを読むを配置 |
| 画像領域 | カード幅を使って大きく表示。押すと拡大 |
| 画像なし | 空の画像枠やダミー画像を設けず、文章だけで自然な高さにする |
| 管理操作 | 投稿詳細の末尾や管理画面へ配置し、閲覧中の主操作にしない |
| ページ操作 | フィード下部に既存ページャーを維持。総件数・表示範囲も残す |

```text
［アイコン］青木 はるか
            10月27日 09:00

今週は「ひとつ動かす」から始める
やりたいことを並べたら、思ったより……
続きを読む

┌─────────────────────┐
│                     │
│       投稿画像       │
│                     │
└─────────────────────┘
```

「画像あり」ラベルは復活させない。画像そのものから内容を判断できるようにする。写真日記から移植した配色とadmin-picoの共通部品を活用する。

## 画像表示と操作

- 縦横比を保持し、一覧では高さに上限を設ける。縦長画像で一投稿が画面を占有しすぎないようにする。
- 図や文字入り画像を勝手に切り抜かない。全体表示と拡大後の可読性を確認する。
- 読込前から表示領域を確保し、画像の読込完了で後続の文章や操作位置が大きく動かないようにする。共通領域 `clamp(15rem, 40vw, 26rem)` を確保し、`object-fit: contain` で全体を表示する。
- 画面外の画像は遅延読込を維持する。ページ単位のDB取得だけでなく、表示する画像の容量・寸法も確認する。現行の5MB上限・10件単位・遅延読込で扱い、専用サムネイル生成は追加しない。
- 読込失敗は「画像なし」と区別し、本文と他の投稿の操作は継続できるようにする。再読込等の導線を用意する。

| 操作対象 | 動作 |
|---|---|
| タイトル・続きを読む | 投稿詳細へ移動 |
| 投稿画像 | 拡大表示を開く。閉じたら元の閲覧位置と操作対象へ戻る |
| 拡大画面 | 閉じるボタン・Escape・キーボード操作に対応し、フォーカスを適切に管理 |
| 投稿一覧へ戻る | 投稿者条件・ページ・閲覧位置を復元。新規作成後の遷移とは分ける |
| ページャー | 投稿者条件を維持して前後へ移動。移動できないボタンは無効化 |

カード全体を単一リンクにして、画像拡大や投稿者操作と衝突させない。文字のリンクと画像の操作を区別し、キーボードでも操作対象が分かるようにする。

## 詳細・投稿フォーム

詳細は投稿者と日時、タイトル、本文全文、画像を自然に読み進められる順にする。本文の行幅を抑え、画像は広く見せられる配置とする。削除等の管理操作は末尾へ置く。

新規投稿・編集フォームは、画像の選択・プレビュー・差し替え・解除を一つの領域にまとめる。画像は任意の1枚という現在の範囲を維持する。編集時には「保存済み画像を維持する」「新画像へ差し替える」「画像を外す」を明確に区別し、保存が成功する前に旧画像を失わない。保存済み投稿の編集機能は [P0-01](improvement-backlog.md)として実装済み。

## 実装順と受入確認

最初に混在データを用意し、**一覧のカード化 → 画像の拡大 → 詳細の配置 → 投稿フォーム**の順で進める。

| 確認対象 | 合格条件 |
|---|---|
| 混在一覧 | 画像あり／なし、短文／長文、縦長／横長／正方形を同じ一覧で読みやすい |
| 図・文字入り画像 | 一覧で全体が欠けず、拡大して内容を読める |
| PC・スマホ | 1280px・390pxを含む画面幅で、横はみ出し・操作の重なりがない |
| 読込中・失敗 | レイアウトが大きく跳ねず、失敗と未添付を区別できる。本文は読める |
| 拡大と戻る | 閉じる・Escape・フォーカス復帰・閲覧位置の復元を確認 |
| ページと絞込み | 12件以上のシードで2ページ目へ移動でき、詳細から戻っても条件を維持 |
| 編集の失敗 | 入力内容と保存済みの画像を保持し、再試行・キャンセルできる |
| 実環境への反映 | シードの画像が実際に保存され、一覧と詳細で取得・デコードできる。隔離E2Eの成功だけで完了としない |

一覧800px、画像領域最大26rem、詳細画像最大34rem、拡大最大78dvhを採用。Playwrightとスクリーンショットで混在データを確認し、仕様を[共通UI設計](ui-foundation.md)へ反映する。
