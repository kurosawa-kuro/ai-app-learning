# 公開環境の速度改善と測定

2026-10-27。疎通成功だけを公開完了として扱い、デモの操作速度を受入条件に入れていなかった点を是正する。

## 原因と修正

同じRender無料サービスで、DBを使わないじゃんけん画面でも約10秒、投稿一覧・AI管理画面も毎回約10秒だった。起動待ちだけでは説明できない。

1. HTTP Basic認証の結果をセッションへ保存しておらず、CSS・JS等の取得でもパスワード照合を繰り返していた。Spring Security標準のHttpSessionSecurityContextRepositoryをBasicと共通の照会先に設定し、認証済みセッションを再利用する。パスワードの照合強度、匿名アクセス拒否、CSRFを維持。
2. PageContextの画面用DB照会が画像レスポンス・非同期保存でも走っていた。画像GETとJSON保存ではレイアウト用の照会を行わない。通常のフォームエラー画面では従来どおりモデルを作る。
3. 静的ファイルのURLへ内容ハッシュを付与し、1年間のブラウザーキャッシュを許可。内容変更でURLが変わるため、更新時に古いCSS・JSを使い続けない。投稿・AI応答・画像の機密データへこのキャッシュ設定を適用しない。

## 同一環境の実測

WindowsからPlaywright Chromiumで測定。各gotoからnetworkidleまでの時間で、静穏確認の500msも含む。下表は稼働中の測定であり、休止状態からの起動時間や大量画像・同時利用の性能保証ではない。

| 画面 | 修正前 | 最終修正後の稼働中 |
|---|---:|---:|
| じゃんけん | 10.070秒 | 2.290秒 |
| 投稿一覧（最初の訪問） | 10.299秒 | 2.344秒 |
| AI管理 | 10.013秒 | 1.578秒 |
| 投稿一覧（再訪問） | 9.983秒 | 1.987秒 |

認証再利用の最初の修正だけでも投稿一覧2.100〜2.102秒、AI管理2.100秒となった。DBのない画面を含めた大幅改善と実装差分から、繰り返し認証が主要因と判断する。DB照会除去・キャッシュ各単独の寄与を切り分けた値ではない。

最終デプロイ直後の初回測定は、じゃんけん11.073秒、投稿一覧3.801秒、AI管理2.705秒、一覧再訪2.690秒だった。初回も高速になったと説明しない。最終コミット7631003、デプロイdep-dbg9h90473hc73fib340、21:30:33 JSTにlive。

## 確認

- PublicAccessTests：認証結果のセッション保存、Basic資格情報を再送しないCSS・管理画面取得、匿名／誤資格情報拒否、CSRF拒否、ハッシュ付きURLとCache-Controlを確認。
- PageContextPerformanceTests：画像・非同期操作で画面用サービス呼出し0、通常アイコンフォームでレイアウトを保持。
- Playwright：画像フィード・再送・編集・名前変更、およびゲーム操作を再確認。
- 公開先：HTTPS、匿名401、認証あり表示、DB／Storage、公開スキーマ、CSRFなし更新403を再確認。今回の速度試験ではGeminiへ送信していない。
- 測定スクリプト：tests/render-performance.cjs。環境認証は環境変数から受け取り、出力しない。
- 生の記録：.local/performance-before.jsonl、performance-after-stable.jsonl、performance-final-first.jsonl、performance-final-repeat.jsonl（Git除外）。

## 残る環境上の制約

Render無料Webサービスは15分アクセスがないと休止し、次のアクセスで再起動する。公式では起動に約1分とされている。今回の通常操作改善では、このサービス制限を解除していない。デモ直前に起動・画面表示を確認する必要があり、いつ開いても即時表示が必要なら常時稼働する構成を別途選ぶ。料金プランは変更していない。

公式根拠（2026-10-27確認）：[Spring Securityの認証状態保存](https://docs.spring.io/spring-security/reference/servlet/authentication/session-management.html)、[Render無料枠の休止](https://render.com/docs/free)。
