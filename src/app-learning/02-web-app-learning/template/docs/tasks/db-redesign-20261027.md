2026-10-27。仕様の正本は[教育用DB設計](../database-design.md)。

## 実施済み

- V10移行、Repository、投稿保存処理、設定保存、ユーザー単体照会を修正。
- 稼働用テーブル8表→6表。ユーザーアイコンをユーザーへ統合。モデル許可は1行1モデルへ正規化。旧運用2表は空なら削除、データがある場合は別スキーマへ保全。
- 投稿要求と投稿の外部キーを設定。削除後の要求再送は明示拒否。
- 画像アップロードを投稿作成のトランザクション／要求ロックの外へ移動。DB保存失敗の参照確認、同時再送時の未使用画像後片付けを維持。
- 空の検索語による本文走査、単体ユーザー照会での不要な件数集計、重複する索引を除去。
- 開発用Supabaseスキーマ `app_template` をV10へ移行し、新コードをlocalhost:8080で起動。

## 反映範囲と限界

開発DBとコードの変更は完了。Renderのコード・DBには未反映。V10は旧コードと非互換のため、公開反映は旧アプリの停止を伴う切替とする。旧版を稼働させたまま自動デプロイしない。

開発環境の投稿一覧は画像込みのnetworkidle待ちで初回約3.1秒、スマホ用の新しいブラウザーでも約3.0秒だった。Supabase通信と500msの静止待ちを含み、公開Renderの改善証拠ではない。今回の成果はDBの構造・整合性・画像保存時の接続占有の改善。表示速度全体が解決したとは扱わない。
