# 教育用テンプレートの変更ルール

この配下はプログラミング教育用スターター。目的は、本人に意味のある一つの題材でAIへの依頼・実行・結果確認を経験すること。提供者の制作・説明・検証・フォロー負担を小さく閉じる。

## 最優先の制約

- 「横展開可能」を「本番運用に必要な機能を全部備える」と解釈しない。実務で有用という理由だけでは共通機能へ追加しない。
- 機能追加前に、対象教材・学習目標・最初の体験に必要な理由を明確にする。対応する教育上の必要性がない機能は追加しない。既存コードで十分なら増やさない。
- 現在は認証なし。Basic認証、ログイン、APP_ACCESS_USER／APP_ACCESS_PASSWORD、権限管理を、公開するからという理由で再導入しない。ユーザーから明示的な方針変更がある場合だけ扱う。
- 独自バックアップ／復元基盤、DB監査ログ、AI要求の永続台帳、期限切れ定期処理、全画面の接続情報表示を共通必須へ戻さない。過去の課題表にあっても、今回の廃止判断を優先する。
- 管理画面のユーザーは投稿者データであり、本人認証・管理者権限ではない。
- 教材に必要な投稿・画像・ユーザー選択・設定・CSV・AI連携は維持する。軽量化を理由に画像サイズ検証、CSRF、入力保持、参照中データの削除防止を壊さない。
- 画面で必要なデータだけを照会する。画像／JSON応答にレイアウト用DB照会を付けない。選択欄に投稿全件の件数集計を使わない。アイコンをユーザーごとにDB照会しない。
- CSS／JavaScriptは使用画面にだけ配信する。削る場合も、アイコン編集・入力エラー再表示など全利用経路を確認する。

## 完了と呼ぶ前の確認

- ローカルに存在するだけでは配布済みとしない。Git追跡・ビルド同梱・公開先のHTTPステータス／MIME・実際のスタイル適用を確認する。
- 投稿0件で測った速度をデモの性能として報告しない。12投稿、4画像、縦長／横長／正方形、2ページ目、長文／短文を使う。
- PC・スマホで、CSS・画像の取得、画像デコード、横はみ出し、ページャー、作成・編集、ユーザー切替を確認する。見出しが出るだけでは合格ではない。
- 起動直後と稼働後、初回と再訪、画面応答と画像取得を区別して記録する。遅い測定値・失敗を除外しない。
- 測定前に「Springだから」「無料枠だから」と原因を決めない。コード・SQL・ネットワーク・環境を実測で切り分ける。
- 既存データを無断で削除・入替しない。不要になった機能の旧テーブルは、アプリの参照停止とデータ削除を分けて扱う。

詳細：[今回の失敗と再発防止](docs/education-scope-incident.md)。

- デプロイ・セッション失効後のフォーム送信も確認する。403を英語のエラーだけで終えず、本文・選択画像・要求IDを維持して送信準備を回復できること。公開先でも画像付き保存まで試す。
