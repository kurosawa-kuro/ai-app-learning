# Webアプリ横展開の必須ルール

この配下のWeb版5アプリ（`skill-janken-game`・`photo-diary`・`online-shop`・`english-trainer`・`cast-evaluation`）を作る際に適用する。ルートのAGENTS.mdと、コピー元templateの現在の教育用最小構成も守る。

## 絶対に丸ごとコピーから始める

**各アプリは、必ず同階層の `template` の中身を丸ごとコピーしてから実装する。コピーした土台を活かし、必要箇所のみ追加・修正する。これは任意の推奨ではなく、ユーザーが指定した必須の開始条件。**

- コピー元は必ず `02-web-app-learning/template`。他の派生アプリをコピー元にしない。
- 空のプロジェクト・別のひな形・部分コピー・templateを参考にした再実装は禁止。コピー前に固有実装を進めない。
- ソース・画面・資産・設定ひな形・起動／ビルド／公開手順・テスト・資料・隠しファイルを一式で引き継ぐ。「使わない」という理由でコピー時に間引かない。
- 今日までの未コミット変更や未追跡の必要ファイルも確認し、古いコミットの内容で置き換えない。
- 固有編集の前にコピー元の版と、相対パス一覧・内容の照合結果を記録する。コピー済みと宣言するだけで先へ進まない。
- 秘密値・実利用データ・ローカルキャッシュ・生成物の扱いは方針書に従い、除外する具体的なパスと理由を記録する。これを部分コピーの口実にしない。
- コピー先に既存作業があれば保全して整合させる。全体再コピーで固有実装を上書きしない。

## コピー後の追加・修正

- 共通の構造・UI・CSS・設定・保存・画像・AI・起動・検証方式を維持する。アプリごとに土台を作り直さない。
- アプリ名・項目・画面・データ・業務ルールなど、用途に必要な箇所だけ追加・修正する。不要な一括改名や大規模整理を混ぜない。
- コピーした実アプリで、ダミーデータと固定AI応答を使って画面・操作・通常計算・保存・再読込を先につなぐ。その後に必要な実接続を確認する。
- 共通修正はtemplateにも戻し、該当する他アプリへ同じ差分を反映する。アプリ間の不要な差を増やさない。
- 現templateから外した独自復旧・監査DB・AI永続台帳を、横展開の前提として復活させない。認証はSupabase Authによる本格版へ移行する予定（[ADR 0004](../../../docs/adr/0004-auth-gas-simple-web-supabase.md)）。templateで方式を確定してから各アプリへ同じ差分で反映し、アプリごとに別の認証を作らない。Basic認証・独自ログインは戻さない。
- コピー完了、ダミー機能の確認、実接続、公開受入は分けて記録する。

実装先と始め方は[README](README.md)、公開版と受入結果は[公開・検証状況](docs/rollout-status.md)を参照する。以後の改修でも、既に丸ごとコピーした土台を維持する原則は変わらない。
