# 教育用のコード構成

現在の範囲は[最小構成](educational-baseline.md)を優先する。過去の「本番運用まで共通化する」構成は廃止した。

| モジュール | 役割 |
|---|---|
| posts | 投稿CRUD・検索・ページ・画像。教材の実例 |
| authors | 投稿者・選択・デフォルト・アイコン |
| settings | 画像／AI許可、許可モデル |
| ai | Gemini疎通と一回の下書き生成 |
| exports | 投稿・ユーザーのCSV |
| games | ゲーム型画面の例 |
| shell | 画面組立て・ナビ・必要なCSS／JS選択 |
| platform | 画像保存・検証・トランザクション・CSRF |
| bootstrap | 明示実行する開発シード |

機能単位のフォルダーを保ち、内側の業務処理をSpring・HTTPから分離する。汎用CRUD生成、運用監視、復旧エンジンなどのために新しい共通抽象を増やさない。

## 通常の処理

画面 → Controller → 機能の処理 → Repository／Storage。投稿一覧は10件を取得する。投稿者の選択欄は名前だけを取得し、使用件数は管理一覧・参照検査でだけ使う。個別ユーザーはID条件で検索し、全投稿・全ユーザーを集計しない。

画像・JSONの応答には画面のモデル照会を付けない。ユーザー選択ではアイコンの有無をまとめて照会する。画像の実体は非公開Storageからアプリ経由で返す。

画像の保存は新画像のアップロード→DB更新→旧画像の後片付け。更新失敗時に既存の投稿・画像を保持する。ImageReferencesは削除対象の参照チェックだけを提供し、全画像列挙・復旧データの登録は持たない。

## AI

GenerateDraftは許可・モデル・入力を確認してGeminiを一度だけ呼ぶ。DraftControllerはブラウザーセッションに直近の実行状態・結果1件だけを保持する。同じIDの直近要求は再実行せず、生成中の別要求は拒否する。DBへの要求保存・期限切れ定期処理・自動再送はない。再起動やセッション終了で消える。

投稿保存とAI生成は別。AIの結果を読む・直す・破棄する操作を学習の中心に置く。

## 画面と保護

認証・ログインはない。Spring SecurityはCSRFと標準ヘッダーだけに使う。ユーザー選択Cookieは本人認証ではない。公開先でも同じ仕様。

Pico CSS・admin-pico・共通UIを使い、投稿用JSは投稿画面、ゲーム用JSはゲーム画面だけに配信する。アイコン編集にも画像プレビューが必要であることを資産選択テストで確認する。

旧operationsモジュール・監査フィルター・RecoveryDataset・RuntimeInfoは削除した。V10で過去の台帳を稼働スキーマから外し、データがあれば別スキーマへ保全する。[DB設計](database-design.md)に6表の構造と移行条件を定義する。
