## 実装範囲

写真3枚・タグ5個・AI下書き・本人の手直し・保存・一覧・詳細。保存後の編集・削除は今回の教材範囲外。

入口：`http://localhost:8091/diary`。既存の投稿ノート例は `/posts` に保持。ログインは追加していない。ユーザー選択は本人認証ではない。

追加DB：diary_entries / diary_tags / diary_photos。Flyway V11で追加し、コピー元の6テーブルは維持。
既存のDB・画像・ユーザー・AI公開インターフェースを再利用する。教材固有の参照先をUserReferences／ImageReferencesへ登録し、関連データのあるユーザーや画像の削除を防ぐ。

## 起動・確認

このアプリのディレクトリで実行する。

```powershell
./run-local.ps1 -SecretsFile ../template/.env -Action run
# 別ターミナルで、確認後に停止
./run-local.ps1 -Action stop -Port 8091
```

共通の秘密値のみを参照し、DBスキーマ・画像バケット・ポートはアプリごとに分離する。学習用データは架空に限定する。
**Supabase Session poolerの接続枠15件を実測で確認。5アプリや統合テストを同時に起動せず、1アプリずつ起動・停止する。** 2026-10-27の複数起動時には接続枠超過で起動に失敗した。容量を増やして解決済みとはしていない。

```powershell
npm ci
./run-local.ps1 -SecretsFile ../template/.env -Action test
node tests/diary-acceptance.cjs
```

ブラウザー確認スクリプトは指定ポートの開発用アプリに架空データを作る。公開先へ無条件には実行しない。既存データは消さない。

## 共通基盤へ戻した変更

- 複数画像を含むAIテキスト生成の公開インターフェースと、外部通信しない固定応答モード。
- `-SecretsFile` による必要な秘密値だけの参照。秘密ファイルそのものは複製しない。
- Grid内の表がスマホ幅を押し広げない共通CSS。5アプリへ同じ差分を反映。
- Windows PowerShell用の日本語スクリプトはUTF-8 BOMを保持。

独自バックアップ・監査DB・認証・AI要求台帳・期限切れ定期処理は追加していない。

## 最初の操作

1. ユーザー管理で架空の名前を登録。
2. 機能管理で画像投稿とAI連携を許可。
3. 日記を書く画面で写真・タグ・メモを入力し、下書きを生成。
4. 本人が本文を手直しし、保存後に一覧と詳細を確認。
5. 開発用の架空データ追加は `node tests/seed-diary.cjs`。同じ固定IDのシードは重複追加しない。

公開先でも実Gemini・3画像保存・セッション失効からの再送を確認済み。容量超過の確認は `node tests/diary-upload-limit.cjs`（既定はローカル）で実行でき、日記は保存しない。公開先での確認時だけ `DIARY_URL` に明示的なURLを指定する。

## タグ管理（2026-10-28）

- 日記作成では既存タグをチェック式で最大5個選択する。選択数とチェック印を表示する。
- 日記一覧の複数タグ選択はOR条件（どれかを含む）。ページ移動でも選択条件を維持する。
- 管理・設定 → タグ管理で追加・名前変更・未使用タグ削除。使用中の削除は画面とDBの両方で防ぐ。
- V12でタグマスター `diary_tag_catalog(id, name, version)` と中間テーブル `diary_tags(entry_id, tag_id)` を分離。既存の日記・タグ関連を移行し、名前変更後もIDで関連を維持する。
- タグ名は30文字まで、重複名とカンマを禁止。変更競合はversionで検知する。
- 管理画面のDB接続確認は手動のみ。接続情報・秘密値は表示しない。
