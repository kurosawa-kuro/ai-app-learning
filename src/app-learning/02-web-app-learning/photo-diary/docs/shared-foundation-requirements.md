# 教材から決める共通機能

[教育用の最小構成](educational-baseline.md)が採用範囲。実務運用の網羅性ではなく、教材の体験に必要かで判断する。

| 共通機能 | 使用例 |
|---|---|
| 投稿・ユーザー・画像・設定 | 写真日記、記録、1対多のデータ |
| テキスト＋任意画像のOpenAI呼出し | 写真日記の下書き、英語学習の応答 |
| AI許可とモデル制限 | 教材で利用するAIを指定する |
| 結果の確認・反映・破棄 | AIの出力を本人が判断する |
| ページャー・検索・CSV | データを保存した後で読み返す |

AIは一回の明示要求、ブラウザーの直近1件だけ保持する。再起動をまたぐ要求台帳・会話管理・監査・課金集計は共通必須にしない。AI料金の画面はダミー表示であり、実課金ではない。

写真日記・評価・英語訓練はGASとWebで同じ基本機能を完成範囲にする。Webだから運用機能を増やすことはしない。じゃんけんはWebでスキルと事前AIセリフ、ショップはWebでカート経由注文という小さな差分にとどめる。詳細は[アプリ学習の対応表](../../../README.md)を参照。

利用者参照のチェック・画像の参照保護は各教材で小さく実装する。独自の復旧対象登録や汎用運用エンジンへの対応を、横展開の前提にしない。
