# 共通UIの設計と拡張

2026-10-27。管理機能を備えたスターターを、投稿とゲームの両方で利用するための規約。

カード型フィード・画像拡大の受入仕様は[画像投稿UI改善案](image-post-ui-plan.md)に分離する。両方とも実装済み仕様として扱う。横展開前の機能課題は[課題一覧](improvement-backlog.md)を参照する。

## 責務

| 部品 | 実装 | 役割 |
|---|---|---|
| AppShell | `templates/ui/shell.html` | ブランド、サイドバー有無、共通資産、本文、削除確認。投稿者・画像フラグ・投稿URLに依存しない |
| ナビ定義 | `UiContext.java` / `ui/navigation.html` | アプリ名・リンク・現在位置・追加CSS/JS。PCとモバイルで同じリンクを使う |
| PageLayout / PageHeader | `ui/page.html` | 見出し・主操作・本文を一つの幅に収める |
| Form | `ui/form.html` | テキスト・本文・スイッチ・操作列。ラベル、必須／任意、補足、項目エラー |
| List / Detail | `ui/collection.html` | 一覧の操作・空状態・データ領域、詳細の補足・本文・次の操作 |
| Feedback / Confirm | `ui/feedback.html` / `ui/ui.js` | 成功・失敗・空状態・保存中・削除確認・フォーカス復帰 |
| 投稿機能 | `templates/posts` / `static/features/posts` | 投稿者選択、入力保持、任意画像、投稿固有の表示 |
| ユーザー切替 | `static/features/authors/user-selection.js` | 一覧取得・検索・選択Cookieの更新依頼・成功イベント。共通JSから分離 |
| ゲーム例 | `templates/examples/skill-janken.html` / `static/examples` | 中央の選択・決定・結果。投稿やユーザーのRepositoryを使わない |

既存画面は `layout :: page(title, kind, heading, actions, content)` を入口にする。`layout.html` は共通シェルへの薄い委譲だけを行う。画面追加時に共通シェルを複製しない。

Javaの `UiContext`・`PageContext` は `shell/internal/adapter/web` に配置する。`ui/ui.js` は共通操作だけを扱い、`AppUI` に保存中表示・ポップアップ配置・トリガー取得を公開する。ユーザーAPIへの通信は機能別JSが担当する。じゃんけんは `janken-rules.js` に勝敗・加点の純粋関数を分離し、`skill-janken.js` でDOM操作を行う。Java側との対応は[構造と改修の入口](architecture.md)を参照する。

## 幅と配置

| kind | 上限 | 用途 |
|---|---|---|
| feed | 800px | 画像・文章を読む投稿一覧 |
| standard | 1200px | 一覧・ユーザー管理・管理画面 |
| form | 800px | 新規投稿・機能管理 |
| detail | 960px | 詳細。本文の行幅はさらに40em以内 |
| play | 960px | ゲームの選択・決定・結果 |

値は `static/ui/ui.css` のトークンに集約する。全ページで中央寄せし、タイトルと本文の左端・右端をそろえる。狭い画面では幅100%、余白16px。本文16px・補足14pxを基準にし、説明の文字色にも可読性を確保する。

管理・投稿画面は1024px以下で同じナビをドロワーにする。ゲームは常設サイドバーを持たず、上部の短いナビで移動する。管理画面はゲームからも到達可能だが、ゲームの操作領域に管理用の表やユーザー選択を押し込まない。

左メニューは上部の「アプリ」の移動リンクと、下部の「管理・設定」・ユーザー切替に分ける。「管理・設定」はユーザー切替のすぐ上に配置し、間の余白はアプリリンクとの間に取る。管理ポップアップからユーザー管理・機能管理・CSVエクスポート・管理の一覧へ進む。現在の管理画面のリンクと管理ボタンに現在位置を示す。ゲームの上部も同じ管理ポップアップを利用する。

メニュー下部に「選択中のユーザー」と名前を表示し、未選択時は「未選択」とする。Cookieの選択、なければDBのデフォルトを表示する。名前を押すと検索付きの切替ポップアップを開き、CSRF付きPOSTで選択Cookieを更新する。画面を移動せず `app:user-selected` イベントを発行し、投稿固有JSが下書きの投稿者を更新する。入力・添付・デフォルト・既存投稿は維持する。フォーム内だけで変更した投稿者は保存までは下書きとして扱う。共通シェルは任意の `sidebarContext` を受け取り、Repositoryを直接参照しない。ゲームにはユーザー切替を表示しない。

ポップアップにはHTML Popover APIを利用する。共通JSが画面内への配置、Escでのフォーカス復帰、Tab移動を管理する。管理・選択のどちらも外側クリックで閉じる。スマホでポップアップを閉じるEscがドロワーまで閉じないようにする。ユーザー一覧は開くたびに再取得し、空・読み込み中・通信失敗を示す。未確認の切替を成功扱いにせず、開き直してサーバーの選択を確認できるようにする。

## 投稿の操作

- 共通ヘッダーから投稿者表示を撤去する。投稿フォーム冒頭の「投稿者：名前／変更・追加」に集約する。
- 初期値は、URLで明示した投稿者 → ブラウザーで前回選んだ投稿者 → DBのデフォルト → 未選択。フォーム上で変更した値が、その下書きの投稿先になる。
- 変更・新規追加は同じ画面内で行い、タイトル・本文・選択画像を維持する。新しい投稿者を追加した時点では投稿は保存しない。
- 一覧の絞込みは閲覧条件だけ。新規投稿の投稿先を黙って変えない。
- 一覧は1ページ10件とし、総件数・表示範囲を示す。1ページだけの場合や0件の場合も下部に「前へ／現在ページ／次へ」を表示し、移動できない操作は無効化する。投稿者条件はページ移動でも維持し、絞込み変更時は1ページ目に戻す。
- 本文と日時・投稿者は詳細で一度だけ表示し、画像は縦横比を保持する。削除は本文の後の折りたたみ領域に置く。

## 状態と失敗

- 入力エラーは概要と項目の近くに表示し、概要のリンクから項目へ移動できる。閉じた投稿者選択も必要時に開く。
- 投稿は通常のHTMLフォームに加え、同じ保存処理を使うJSON応答を用意する。JavaScript有効時は現在の文書を保ったまま送信し、成功してから詳細へ移動する。
- 通信・DB・画像の失敗では入力を維持する。通信断は保存済みの可能性もあるため、投稿一覧で確認してから再試行するよう案内する。永続ブラウザーストレージへの本文保存や、自動再送は行わない。
- クライアントでも画像の5MB上限を検査する。サーバーでも容量・画像内容を検査する。画像選択の解除ボタンを用意し、画像を外して本文だけ再送できる。
- JavaScript無効時の通常POSTでは、処理できたリクエストの入力エラーを再表示する。ブラウザーが再表示したファイル入力は復元できないため再選択を案内する。リクエスト全体がサーバーで拒否される場合、通常POSTの下書き保持は保証しない。
- 保存中はボタンを無効化し、保存中と表示する。これはブラウザー内の二重操作防止であり、通信断をまたぐサーバー側の冪等保証ではない。
- 削除確認は対象名と「元に戻せない」を表示し、初期フォーカスはキャンセル。Escapeでも閉じ、元のボタンへ戻る。削除に失敗したら対象を残して再試行できる。
- 投稿0件と絞込み0件を分け、前者は作成、後者は絞込み解除へ案内する。

## admin-picoの扱い

カード・フォーム・ナビ・ダイアログの部品は同梱admin-picoを再利用する。配色はユーザー指定により、`photo-diary/src/client/vendor/admin-pico/admin-theme.html` の値を `static/ui/photo-diary-theme.css` に移植した。淡いピンクの背景、白いカード、ピンク〜パープルの主ボタン、濃い文字、赤いエラー、ピンク・ラベンダー・ミント・ピーチの補助色を使う。同ファイル下部で既存部品へ色を適用し、共通UI・ゲームのCSSは色の役割を表す変数を参照する。HTMLとブラウザーのフォームもライトテーマとし、同梱JSによるダーク固定を解除する。写真日記側への変更・自動同期は行わない。

部品の組合せ・幅・レスポンシブ・状態は `static/ui/ui.css`、アプリ専用CSS/JSは `UiContext` から渡す。参考元のパレットを更新するときは文字・背景のコントラストと、ポップアップ・フォーム・危険操作・ゲームまで確認する。

静的資産はコントローラーのURLと衝突しない場所へ置く。投稿専用資産は `/features/posts/` に配信し、`/posts/{id}` の経路へ混在させない。

## ゲームの適合確認範囲

`/examples/skill-janken` は、既存 `skill-janken-game` の「仲間・スキル → 手の選択 → 明示的な決定 → 結果」の操作順を用いるUI体験。固定のサンプル対応表とブラウザー内の勝敗・得点計算を使う。GASのマスター、所有状態、履歴、AIセリフには接続しない。全員を最初から選べ、再読込みすると得点はリセットする。この制限を画面に明記する。

共通UIの再利用の確認と、GAS版の移植・永続化の完成は別の判定とする。

## 検証

Playwrightで投稿・管理・ゲームを操作し、390 / 768 / 1280 / 1920pxの画面を記録する。フォームと本文の基準線、横はみ出し、キーボード操作、削除キャンセル、入力保持、保存中、実Storageを検証する。テスト結果と視覚確認はREADMEの検証記録へ残す。

## AI下書き

投稿フォームの本文・今回選択した画像を、明示ボタンで送信する。生成中も元の本文・画像を残す。結果は読み取り専用欄へ表示し、「本文へ反映」「破棄」を分ける。反映後に破棄した場合は反映直前の本文へ戻す。途中で手直しされた本文を置換・破棄する場合は確認する。通常の投稿保存までは確定データを作らない。

AI下書きはブラウザーセッションの直近1件のみ保持する。再起動・セッション終了・次の生成で前の結果は消える。通信が途切れた場合は同じ要求の結果確認ボタンを出す。確認はGETのみで新しいAI通信を行わない。禁止・未設定・モデル制限・結果不明は固定案内で区別する。
