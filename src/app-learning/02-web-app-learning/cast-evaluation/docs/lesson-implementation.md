# キャスト評価の実装・検証記録

2026-10-27開始。コピー元の検証記録を、この教材の検証結果へ読み替えない。

## 実装範囲

単一店舗のメンバー登録・編集・在籍状態、日次5項目の実績入力・編集、配点、月次集計・順位。過去月も現在の配点で再計算。

入口：`http://localhost:8092/evaluation`。既存の投稿ノート例は `/posts` に保持。ログインは追加していない。ユーザー選択は本人認証ではない。

追加DB：evaluation_members / evaluation_records / evaluation_rules。Flyway V11で追加し、コピー元の6テーブルは維持。
既存のDB・画像・ユーザー・AI公開インターフェースを再利用する。教材固有の参照先をUserReferences／ImageReferencesへ登録し、関連データのあるユーザーや画像の削除を防ぐ。

## 起動・確認

このアプリのディレクトリで実行する。

```powershell
./run-local.ps1 -SecretsFile ../template/.env -Action run
# 別ターミナルで、確認後に停止
./run-local.ps1 -Action stop -Port 8092
```

共通の秘密値のみを参照し、DBスキーマ・画像バケット・ポートはアプリごとに分離する。学習用データは架空に限定する。
**Supabase Session poolerの接続枠15件を実測で確認。5アプリや統合テストを同時に起動せず、1アプリずつ起動・停止する。** 2026-10-27の複数起動時には接続枠超過で起動に失敗した。容量を増やして解決済みとはしていない。

```powershell
npm ci
./run-local.ps1 -SecretsFile ../template/.env -Action test
node tests/evaluation-acceptance.cjs
```

ブラウザー確認スクリプトは指定ポートの開発用アプリに架空データを作る。公開先へ無条件には実行しない。既存データは消さない。

## 確認したこと

2か月の架空実績、同点1位・次の3位、実績編集後の再集計・再読込を確認。売上は月集計後に切り捨てるテストあり。AIは使わない。
PC幅と390pxのスマホ幅で操作を確認。画像・表・メニューは実画面も確認する。テストログはコピー元 `template/.local/` の `*-regression.log` と教材別ログに保存（ローカル生成物）。公開受入は別途記録する。

## 共通基盤へ戻した変更

- 複数画像を含むAIテキスト生成の公開インターフェースと、外部通信しない固定応答モード。
- `-SecretsFile` による必要な秘密値だけの参照。秘密ファイルそのものは複製しない。
- Grid内の表がスマホ幅を押し広げない共通CSS。5アプリへ同じ差分を反映。
- Windows PowerShell用の日本語スクリプトはUTF-8 BOMを保持。

独自バックアップ・監査DB・認証・AI要求台帳・期限切れ定期処理は追加していない。

## 実接続・公開

DBは分離したSupabase開発スキーマへ接続済み。画像を使う写真日記のみ専用Storageを使用。
AI固定応答の確認と、実Geminiへの接続結果は区別する。Render公開・実AIの最終確認結果は、[横展開の進捗](../../docs/rollout-status.md)を正とする。

最終集計ではこのアプリのJava回帰テストは失敗0。実AIの自動テスト1件は意図的にスキップし、必要な教材では別途ブラウザー確認した。詳しい件数・公開状態は横展開記録を参照。

## 最初の操作

1. 評価画面のメンバー管理で架空のメンバーを登録。
2. 営業日と5項目を入力。
3. 対象月を切り替えて集計を確認。
4. 実績・配点を変更し、順位の変化を確かめる。
5. 教材の操作主体（共通ユーザー）と評価対象のメンバーは別のデータ。メンバーを退店扱いにしても過去実績は残る。
