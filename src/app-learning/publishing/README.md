## 三つの独立した設定

| 出口 | 設定 | 初期状態 |
|---|---|---|
| ① 本名公開・一般 | [realname-general](realname-general/publish.yaml) | 本名サイトの準備用。公開無効 |
| ② 本名非開示・専門 | [alias-nightlife](alias-nightlife/publish.yaml) | 公開無効。公開水準も未決定 |
| ③ 本名非開示・一般 | [alias-general](alias-general/publish.yaml) | 本名サイトを待たず準備可能。公開無効 |

公開名・ブランド・問い合わせメールはすべて `null`。他出口・本名から自動補完しない。②と③は別の活動名・連絡先を使い、それぞれ独立したプロフィールを持つ。検査では、設定済みの活動名・メールが②・③で重複していれば拒否する。

①は独自ドメイン必須、②・③は独自ドメイン必須ではない。簡易サービスでも原稿・設定・検査をできるだけ共通にする。契約、ドメイン所有、配置先での実表示の確認はローカル入力検査の対象外で、公開前に各出口の運用手順で確認する。

## 置く場所

- `catalog.yaml`：素材ID、入力パス、出力候補パス、許可出口、依存素材、レビュー状態。
- `common/content/`：複数出口で使える中立的な本文。日記の基本説明と初回の進め方。
- 各出口の `content/`：トップ・題材別の導入。公開候補へそのまま渡す本文だけを書く。
- 各出口の `assets/`・`samples/`：出口固有の画像・架空データ用。現在は素材未登録。
- 各出口の `publish.yaml`：本人情報の扱い、題材、公開水準、公開用プロフィール、選択素材ID。
- `scripts/`：教材設定・入力の検査に加え、紹介用WIPと名刺見本の生成。アップロード・公開は別操作。
- `dist/<出口ID>/`：検査済み生成物。現在は②③の紹介用WIPのみ。Git管理外。

本文の中立部分は手動コピーせず共通素材へリンクする。公開候補のMarkdownリンクは入力ファイルの場所ではなく、台帳の `output` を基準に書き、リンク先IDを `dependencies` に登録する。リンク先は同じ出口の選択・依存素材として解決されなければならない。

現在は①4素材、②5素材、③4素材を参照する。全出口で日記の基本・初回手順を再利用するが、台帳そのものは出力対象ではない。全素材が `draft` であり、掲載済み・配布済みを意味しない。

## ローカル検査

実行ディレクトリは `src/app-learning/publishing`。Python 3.13.5・PyYAML 6.0.2で確認した。依存がない環境だけ、先に `python -m pip install -r requirements.txt` を実行する。

```powershell
python scripts/check_publication.py
python scripts/check_publication.py --site alias-general
python scripts/test_publication.py
```

終了コード0は設定・対応する原稿の検査成功。全出口検査でも各出口の結果を別々に表示する。公開名の未設定や `draft` は、編集時の構造検査では許容する。

公開準備の設定検査は追加オプションで行う。

```powershell
python scripts/check_publication.py --site alias-general --ready
```

**初期状態では終了コード1で「公開は無効です」となるのが正しい。** この判定を通すためだけに公開フラグやレビュー状態を変更しない。公開水準、名義・連絡先、選択素材のレビューが揃った出口だけを個別に判断する。①が未設定でも③の準備判定を独立して行える。

`--ready` が成功しても、公開承認・実環境の認証確認・配置は行われない。教材素材の生成・配布は未実装。紹介用WIPの生成・配置とは区別する。

## 検査の範囲と限界

検査するのは、固定した3出口の2軸、素材の選択と許可、依存関係、出力先の重複、素材パス、Markdownの内部リンク、一般向けの専門語混入候補、設定された本名側の公開名・メールが非開示版本文や名義設定へ混入していないか、公開準備設定。

現在は単純なMarkdownだけを対象とする。HTML、外部URL、参照形式リンク、画像・PDF・ZIP等は専用の検査を追加するまで登録できない。禁止語チェックは補助であり、言い換え、未登録の本名、画像メタデータ、実際の問い合わせ表示まで自動保証しない。原稿と実環境の人による確認が必要。

検査ログに本文や本人情報の原文を表示しない。コード・設定のテストは一時フォルダーの架空設定だけで行い、実際のプロフィールを書き換えない。

## 次の作業と禁止する配置

教材を公開する際は、正式な公開名・連絡先・②の教材公開水準を確定し、素材の生成・配置と実環境受入を実装する。出力するのは選択・許可済み素材と必要な公開表示だけ。全台帳、設定ファイル、制作元README、内部資料、Git履歴を配信しない。

フォルダー名でアクセス権限は分かれない。制作リポジトリの非公開化や現行デモの停止・認証変更は今回の整備では実施していない。
