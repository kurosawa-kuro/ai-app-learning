## 正本と更新責任

| 情報 | 管理先と更新ルール |
|---|---|
| 全体の入口と優先順位 | README。詳細の重複を増やさず、現状要約は01と同期する |
| 役割分担と現行状況の索引 | 01。状況更新には正本・仕様版・確認日・根拠を示す |
| 教育方針・対象者別成功条件 | 02。対象者仮説と観測した成果を分ける |
| 基盤比較・受入・提供前検証 | 03。仕様版・実装版・教材版と未実施事項を残す |
| 拡張候補・横断的な追加案 | 04。掲載だけで採用・開発・提供予定へ昇格させない |
| 商品構想・価格・需要 | 05。仮説と実績を分け、事業化時点で条件を検証する |
| 他用途へ応用する型 | reference。現行機能や新規教材計画として案内しない |
| 個別仕様・コマンド・実装・試験結果 | 各プロジェクトのREADMEとそこから参照する正本。本一式へ複製して二重管理しない |

採用する変更は、対象プロジェクトで範囲・受入条件を定めてから個別正本へ反映する。全体レビューの結果だけで業務モデルを統合しない。外部サービスの料金・条件・具体コマンドは実装・提供時に公式情報と照合する。
