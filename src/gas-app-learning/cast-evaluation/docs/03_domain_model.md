# 03 ドメインモデル

根拠: [基本仕様・設計 v0.3.0（Draft）](<tasks/01_idea/Cast Evaluation System — 基本仕様・設計.md>) §3、§5〜10。この文書は正本からの派生文書であり、矛盾時は正本を優先する。記載は設計・受入基準であり、実装・検証済みを意味しない。

## 用語

| 用語 | 意味 |
|---|---|
| Member | 評価対象のキャスト。自動発行ID・キャスト名・在籍状態を持つ |
| Performance | 1キャスト・1営業日の5項目の営業実績 |
| Evaluation Rule | 計算単位・配点・有効／無効を持つ評価基準 |
| Evaluation Result | 対象月の実績から都度算出するポイント・順位。保存テーブルを持たない |
| 営業日 | 店舗の実績を記録する日。日付境界・タイムゾーンの詳細は未決定 |
| 個人売上 | 既存会計・POS等で確定した、評価用に記録する整数円の金額 |
| 管理者 | MVPの操作主体。ルール変更の過去期間への影響を確認する |

## 状態・不変条件

メンバーの状態値は `ACTIVE` / `INACTIVE`。退店時は無効化し、メンバーと過去実績を削除しない。本名など不要な個人情報は保持しない。再在籍やINACTIVEメンバーへの新規入力可否は正本で未定義。

実績は `business_date + member_id` ごとに1レコードとし、過去分も編集できる。ドリンク・ボトル・指名・同伴は0以上の整数件数、個人売上は0以上の整数円。商品明細・指名詳細・売上按分はMVPで管理しない。

個人売上を本システムで確定・自動計算しない。既存システムを正本として、店舗が確定した値を入力する。

## 評価ルール

| category | 実績 | 計算単位の仮設定 | 配点の仮設定 | 初期状態 |
|---|---|---:|---:|---|
| DRINK | drink_count | 1杯 | 1P | 有効 |
| BOTTLE | bottle_count | 1本 | 5P | 有効 |
| NOMINATION | nomination_count | 1件 | 3P | 有効 |
| ACCOMPANIMENT | accompaniment_count | 1件 | 5P | 有効 |
| SALES | personal_sales | 10,000円 | 2P | 無効 |

配点数値は設計確認用であり業界標準ではない。数量評価との重複を避けるため売上ポイントは初期無効だが、個人売上の記録・表示・並び替えは行う。

## 月次計算

1. 対象月の営業実績をキャスト別に集計する。
2. 有効項目ごとに以下の計算を行う。
3. 有効項目のポイントを合算して総合ポイントとする。
4. 順位を計算し、5項目の月間実績・個人売上・総合ポイント・順位を表示する。

```text
数量4項目のポイント = 期間数量 × ポイント単価 / 計算単位
売上ポイント = floor(期間売上 / 計算単位) × ポイント
総合ポイント = 有効な評価項目のポイント合計
```

売上は日次で切り捨てず、対象期間の金額を合計した後に切り捨てる。例として6,000円＋6,000円を10,000円単位・2Pで計算すると、売上ポイントは2Pとなる。

数量ポイントについて、計算単位変更により生じる小数を一律に切り捨てる仕様はない。精度・端数表示は未決事項として扱う。

## ランキング

総合ポイント降順 → 同点なら個人売上降順 → 両方同じなら同順位。個人売上順の表示にも対応する。

同順位の後の順位番号（競技順位／密順位等）、売上順表示時の順位欄の意味、実績ゼロのメンバーの掲載方法は未定義。既定の同点判定と混同せず、必要な詳細のみ決定する。

## ルール・実績変更の影響

- 過去実績の修正は対象期間の集計へ反映する。
- ルールを変更すると過去期間も新しいルールで再計算する。運用開始後の変更は管理者の確認を必要とする。
- ルールのバージョン管理・過去評価の固定保存はMVPで行わない。固定が必要になった時点で履歴管理を検討する。
- 評価ランク、複雑な評価アルゴリズム、時給査定・給与反映はMVP対象外。

詳細な未決事項は [索引](00_index.md#未決事項)、計算例の検証は [テスト戦略](07_test_strategy.md) を参照。
