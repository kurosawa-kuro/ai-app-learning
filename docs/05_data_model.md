# 05 データモデル

このリポジトリ全体で共有するアプリDBは定義しない。[全体方針](../README.md)に基づき、支援の記録と、個別教材のデータを分ける。

## 初回支援の記録

[支援シート](templates/ai-pairing-session.md)を使う。以下は記録項目であり、新しい管理アプリやDBの実装要求ではない。

| 記録 | 内容 |
|---|---|
| 本人・課題 | 匿名の記録ID、希望、一つの課題、期待結果、教材・版 |
| 支援範囲 | 提供者と本人とAIの役割、回数・時間・期間・窓口、不具合時の扱い |
| 観測した成果 | 依頼文、操作、期待と実際の結果、本人の判断、補助した部分 |
| 引き渡しと終了 | 再利用材料、確認・復旧方法、終了日、未達・不具合・追加要望の扱い |

公開教材には架空・サンプルデータを使う。参加者の個人情報、顧客情報、私的な写真・会話、秘密情報を公開リポジトリやAIへの依頼文に混入させない。実データが必要な利用は、保存先・アクセス権・公開範囲を個別に設計する。

## 教材ごとの保存先

| 対象 | 方針と仕様の所在 |
|---|---|
| [GASの5教材](../src/app-learning/01-gas-app-learning/README.md) | Sheets等の表・関連・保存ルールは個別仕様。アプリ間の共通スキーマを新設しない |
| [Webアプリ](../src/app-learning/02-web-app-learning/web-app-support-strategy.md) | Supabase PostgreSQL、必要時にStorage。具体的なスキーマ・移行は実装時に確定 |

| [業務効率化](../src/office-automation-starter/README.md) | 元ファイルを保全し、コピーと出力で処理する |

## 設定・秘密・移行

各教材の設定方式を優先する。ルートの `env/config.yaml`・ローカルの `env/secret.yaml`・`doppler.yaml` は全教材共通の導入条件ではない。GASのScript Properties等は対象教材の実装と手順で確認する。

パス・ローカル設定・パッケージ名は[命名規則](00_index.md#命名規則)に揃える。既存の保存キー、クラウド側の名前・ID・URLは別に管理する。改名を理由に既存データを再初期化しない。

データ構造や保存先を変更する場合は、対象、バックアップ、移行・復旧方法、既存データの保持、検証結果を個別の仕様・作業記録へ残す。ローカル検証と実データ移行の完了は別に確認する。
