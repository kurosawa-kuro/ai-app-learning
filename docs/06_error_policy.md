# 06 エラー方針

[初回支援の要件](01_requirements.md)に沿い、学習者のつまずき、提供物の不具合、技術障害を分ける。全教材共通のエラーコードや自動再試行処理は定義しない。

## 切り分けと対応

| 状況 | 対応と記録 |
|---|---|
| 希望をAIに説明しづらい・操作に迷う | 提供者が言語化や操作を補助する。補助した部分を残す |
| AIの提案が期待と違う | 入力・期待結果・実際の差を整理し、採用しない、修正依頼、元に戻す等を判断する |
| 課題が大きすぎる・前提が足りない | 支援の枠内で課題を縮小するか、準備や次の扱いを合意する。別技術を必修として増やさない |
| 提供側の教材・環境の不具合 | 本人の理解不足と扱わず、事前に決めた不具合対応へ分ける。未修正を成功にしない |
| 通信失敗・外部サービス停止・保存結果不明 | 個別教材の手順で状態を確認する。二重保存や追加課金を避け、根拠なく再送しない |
| 合意した支援枠の終了時に未達 | 未達・原因・残件を記録し、終了または別枠等の扱いを決める。黙って延長しない |
| 新しい機能や別の課題を希望 | 今回の不具合と区別し、新しい相談として範囲を決める |

## 再現・ログ・復旧

AIや提供者へ相談する際は、対象教材・版・環境、行った操作、入力、期待と実際、エラー文を整理する。サンプルで再現できる範囲を優先し、APIキー、認証情報、個人情報をログや依頼文に出さない。

保存・送信を伴う処理は、失敗表示だけで未実行と断定しない。要求ID、保存先、公開版等の確認方法は各教材のエラー方針・runbookに従う。復旧のために既存記録を黙って削除・上書きしない。

不具合を修正した場合は、再現条件、変更、検証結果、未確認事項を残す。[検証方針](07_test_strategy.md)に従い、修正コードがあるだけで実環境復旧済みとしない。支援の終了条件は[支援シート](templates/ai-pairing-session.md)で確認する。
