# 03 ドメインモデル

ここでは[全体方針](../README.md)に共通する支援上の用語を定義する。アプリ固有の業務ルール・状態・データ構造は各教材の正本に従う。

## 用語

| 用語 | 意味 |
|---|---|
| 入口 | 本人の目的から選ぶ独立した取り組み。履修順ではない |
| 本人のゴール | 本人が使いたい・変えたい・理解したい具体的な状態 |
| 初回課題 | 今回の支援で扱う小さな一つの課題と期待結果 |
| AIとの並走 | 本人の希望をAIへ伝え、応答を使って試し、結果を確認すること |
| 初回成功 | 一つの課題でAIとの並走を経験できたこと。提供者の補助を認める |
| 横展開 | 依頼の仕方、データ・ルールの考え方、ひな形等を次の変更・機能追加・別用途へ使うこと。任意の活動 |
| 自立 | 自分の目的に応じて依頼・検証・問題の整理を進められる状態。初回成功と同一視しない |
| 支援の枠 | 合意した課題、回数、時間、期間、窓口、対応量 |
| 引き渡し | 成果、依頼文、確認方法、戻し方、残件の扱いを本人へ渡すこと |
| 支援終了 | 合意した今回の対応を閉じること。学習の終了や習得の保証ではない |

## 混同しない状態

| 管理するもの | 記録する状態・事実 |
|---|---|
| 教材 | 設計中、実装済み、ローカル検証済み、公開済み、実環境受入済み。版と対象環境を伴う |
| 学習成果 | 未実施、初回成功、未達。本人が行ったことと提供者の補助を記録 |
| 提供者の支援 | 準備、実施、引き渡し、終了。残件と期間を別に記録 |
| 資格 | 学習済み、受験予定、取得済み。実習成果・就職とは別 |

初回成功して支援終了する場合も、枠を使い切って未達のまま終了する場合もある。未達・提供物の不具合・追加要望は区別し、[支援シート](templates/ai-pairing-session.md)で扱いを残す。学習者の次の希望を、閉じた支援へ自動追加しない。

## 個別の意味を守る

- 子供の楽しさ・理解、英語への活用、店舗業務の運用、事務処理の正確さを同じ試験で評価しない。
- Javaの実務学習で確認する自力のコード・SQL修正を、非エンジニア向けの初回課題へ一律に課さない。
- アプリやAIが処理を完了した事実と、本人が理解・判断できた事実を分ける。
- フォルダー名は[命名規則](00_index.md#命名規則)に従う。改名だけでアプリの業務ルールや既存データの識別子を変えない。
