# ADR 0004：認証をGAS版は学習用の簡易版、Web版はSupabase Authの本格版に分ける

- 決定日：2026-10-28
- 状態：採用（ユーザー指定）。**Web版の実装は未着手**
- 根拠：ownerの「GAS版は引き続きユーザー認証機能は学習用途で簡易版。Web版はSupabase Authを使った本格版に変更していく」という指示。
- 関連：[Webスタック（ADR 0001）](0001-web-app-stack.md)、[Webアプリ支援戦略](../../src/app-learning/02-web-app-learning/web-app-support-strategy.md)、[教育用の最小構成](../../src/app-learning/02-web-app-learning/template/docs/educational-baseline.md)、[認証を外した経緯](../../src/app-learning/02-web-app-learning/template/docs/education-scope-incident.md)

## 決定

| 版 | 認証の扱い | 内容 |
|---|---|---|
| GAS版 | **学習用の簡易版を継続** | GAS標準の本人限定公開（`MYSELF`／`USER_DEPLOYING`）と、画面上の架空利用者の選択。独自ログイン・Supabase Authは追加しない。利用者の選択は本人認証ではない |
| Web版 | **Supabase Authによる本格版へ移行する** | 利用者本人がログインし、サーバー側で利用者を確認してから操作・データ参照を許可する。現在のユーザー選択Cookie方式を置き換える |

認証・認可をGAS版とWeb版の差別化点の一つにする。GAS版ではデータの関係と業務ルールに集中する。Web版では本人確認、利用者ごとのデータ分離、公開先での権限検証まで扱う。

## 以前の方針との関係

2026-10-27の軽量化で、Web版はBasic認証・`APP_ACCESS_USER`／`APP_ACCESS_PASSWORD`を廃止し、「ユーザーから明示的な方針変更がある場合だけ扱う」とした。今回の指示はその明示的な方針変更にあたる。ただし範囲は次のとおり限定する。

- 導入するのはSupabase Authだけ。Basic認証、`APP_ACCESS_USER`／`APP_ACCESS_PASSWORD`、独自のパスワード保存・ログイン実装は引き続き戻さない。
- 独自復旧・監査DB・AI永続台帳などの廃止判断は変えない。認証の導入を理由に、これらを一緒に戻さない。
- 静的ファイルの取得ごとにパスワード照合して画面が約10秒かかった前回の失敗を繰り返さない。認証結果を再利用し、CSS・画像の取得と画面応答の速度を受入で確認する。

## 進め方（予定）

1. **設計**：下記の未決事項を決め、templateで方式を確定する。
2. **template実装**：templateへSupabase Authを組み込み、ローカルと検証用Supabaseで受入する。
3. **5教材へ反映**：横展開の必須ルールに従い、templateと同じ差分を各教材へ反映する。既存データと利用者の対応付けを含む。
4. **公開先受入**：Renderで1教材ずつ受入する。公開先を一括で切り替えない。

## 未決事項（設計時に決める）

- ログイン方式：メール＋パスワード、マジックリンク、Google等の外部ログインのどれを使うか。新規登録を誰でもできるようにするか、招待制にするか。
- Spring Boot側の扱い：Supabase Authのトークンをサーバーでどう検証し、ログイン状態をどう保持するか。Cookieの属性、CSRFとの関係、ログアウト・期限切れ時の動作を含む。
- 認可とデータ分離：利用者ごとにデータを分ける範囲と、管理者の扱い。サーバー側の認可とRLSのどちらで担保し、どの接続ロールで有効になるかを決める。
- 既存データ：現在の`app_users`（投稿者データ）・架空データとSupabase Authの利用者の対応付け、移行方法。
- メール送信：登録確認・パスワード再設定のメール送信の設定と、プランの上限。
- 試験：試験用アカウントの用意、Playwrightでのログイン、未ログインと他人のデータへのアクセス拒否の確認方法。
- 教材としての見せ方：初回体験でのアカウント作成の負担と、子供・非エンジニアへの伴走範囲。

## 適用範囲と影響

- この記録の時点では、実装・環境変更・データ移行・公開を行っていない。Web版のtemplateと5教材は**現在も認証なし**。
- 「認証なし」を前提にしたWeb版の規約・最小構成・受入手順は、現状の説明として残し、本ADRへの参照を付ける。実装・受入が終わった時点で書き換える。
- Web版の受入条件に、未ログイン時の拒否、他人のデータへのアクセス拒否、ログアウト、期限切れ後の再ログインを加える。
- GAS版の受入条件・残作業は変更しない。
