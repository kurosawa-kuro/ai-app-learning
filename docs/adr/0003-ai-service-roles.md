# ADR 0003: AIの役割をDevin・OpenAI・Cursorに分ける

- 日付：2026-10-28
- 状態：採用（ユーザー指定）
- 対象：教材全体の学習支援、アプリ内AI、業務自動化、導入記事・動画
- 関連：[全体案内](../../README.md)、[共通作業方針](../../AGENTS.md)、[アプリ学習](../../src/app-learning/docs/README.md)、[導入資料の制作設計](../../src/解説/記事/README.md)

## 決定

| 質問・依頼の種類 | 使用するもの | この教材での役割 |
|---|---|---|
| プログラムコードについての質問・改造依頼 | Devin | 受講者がコードの意味、不具合、変更方法を相談し、調査・改造・確認を依頼する |
| プログラムコードからAIへの質問 | OpenAI API | アプリのコードがAPIを呼び出し、生成・採点・会話などの応答を受け取る |
| 業務自動化についての質問・作業依頼 | Cursor | 受講者が集計、資料整理、文面作成などを相談・依頼する |

**Geminiは教材アプリのAI接続先として廃止する。** 現行の導入先、代替API、フォールバックの候補に戻さない。OpenAIへの統一は、アプリ内AIが必要な教材・機能に適用する。AIを使わない教材へAPI機能を追加する意味ではない。

## 背景と意図

「人がコードについて質問する」「プログラム自身がAIへ問い合わせる」「人が業務自動化を依頼する」を区別する。すべての受講者作業をDevinにまとめる説明では、業務自動化のCursorと、アプリ実行時のOpenAI APIの役割が伝わらないため、三つの用途を明記する。

アカウント・教材との接続・料金・結果確認の案内も、用途ごとに用意する。全員に三つのサービスの登録を一律に求めない。子供への入力代行など、対象者に応じた支援は既存方針を維持する。

## ドキュメントへの反映

- 全体README、AGENTS、CLAUDE、共通要件・構成、各学習ルートの入口に役割分担を記載する。
- アプリ学習のコード質問・改造はDevin、アプリ内のAI呼び出しはOpenAI APIと表記する。
- 業務自動化の入口と導入資料ではCursorを標準として扱う。
- 導入記事・動画では、人が操作するツールとアプリの接続先を説明し分ける。
- 現行の学習設計でGeminiを推奨する記述は修正する。過去の試験・公開・判断記録は当時の事実を残し、現行方針との違いを注記する。

## 実装・検証との区別

この決定と文書更新だけで、全アプリ・公開環境のOpenAI移行完了とはしない。Gemini用のコード・設定名・手順が残る場合は移行対象として扱い、対象版ごとにコード、設定、実疎通、公開先での動作を確認する。Geminiでの過去の試験成功はOpenAIの検証証拠にならない。

2026-10-28の文書更新時点で、GASの英語訓練・写真日記とWeb共通テンプレートにOpenAI実装を確認した。GASの実通信については既存の[受入記録](../../src/app-learning/docs/tasks/gas-release-20261028.md)がある。Webの現行設定・進捗は[OpenAI移行記録](../../src/app-learning/02-web-app-learning/docs/tasks/openai-migration-20261028.md)を参照する。[横展開記録](../../src/app-learning/02-web-app-learning/docs/rollout-status.md)にはGemini使用時点の記録が含まれる。今回の作業で実通信や公開先の再検証は行わない。

提供者が教材を開発するためのCodex・Claude Code等の利用方針や、汎用ハーネス設計にあるツール例は、受講者向けの役割分担とは別に扱う。過去資料のファイル名に残る `gemini` も、現行採用を意味しない。
