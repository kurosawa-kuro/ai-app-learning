# 01 要件

[README](../README.md)・[AGENTS](../AGENTS.md)・[CLAUDE](../CLAUDE.md)の方針を具体化する。個別教材の機能仕様は、それぞれの正本に従う。

## 目的と最初の成功

IT入門者が、本人に意味のある小さな課題を一つ選び、AIへ希望を伝え、応答を使って試し、結果を確認する経験を得られるよう支援する。提供者が言語化や操作を手伝っても初回成功とする。

全分野・全教材・全技術を学ばなければプログラマーになれない、という設計にしない。全教材の修了、資格取得、自力のコード記述、別用途への応用は初回の条件ではない。

## 対象者と独立した入口

| 入口 | 対象者・本人のゴール | 最初の支援 | AIで広げる方向 |
|---|---|---|---|
| [GAS教材](../src/gas-app-learning/README.md) | 遊び・英語・写真・店舗業務等を通じて、身近な仕組みを理解・活用したい人 | 本人に合う題材、体験環境、小さな設定・変更 | データ・ルールの考え方を次の変更へ使う |
| [Webアプリ](../src/web-app-starter/web-app-support-strategy.md) | 自分用・業務用アプリを作って使いたい非エンジニア | 要望を絞り、ひな形・環境・必要な公開範囲を整える | 項目・画面・処理を用途に合わせて変える |
| [Javaキャリア](../src/java-career-learning/java-career-learning-strategy.md) | Java・Oracle系の仕事を目指すIT未経験者 | 仕事に必要な学習範囲、環境、最初のJava・SQL課題 | 例題・解説・レビューを使い、別課題や必要な技術へ進む |
| [業務効率化](../src/office-automation-starter/README.md) | 事務処理の手間やミスを減らしたい非エンジニア、特にIT人材・SES営業 | Windows・Cursor・サンプル・単独で使えるプロンプト | 入力・条件・出力を変えて別業務へ使う |

GAS内でも子供、英語学習者、写真日記の利用者、店長では成功条件が異なる。保護者の希望と子供本人の関心を分け、職業や属性だけで課題を決めつけない。GASの6工程・対面90分案を全員の必修順序にしない。

## 提供範囲

- 既存の教材・サンプル・学習戦略を整え、対象者に合う一つから始められるようにする。
- GASは `skill-janken-game`・`online-shop`・`cast-evaluation`・`photo-diary`・`english-trainer` の5教材を優先する。
- Web基盤はSpring Boot＋Thymeleaf＋Render＋Supabase。採用方針と実装・公開の完了を分ける。
- 提供者は課題、回数、時間、期間、質問窓口、不具合対応を開始前に決める。依頼文・確認方法・戻し方を渡して支援を閉じる。
- 追加要望は新しい相談とする。本人が学び続けることを、提供者が無期限に対応する条件にしない。

全員に同じ技術・資格・コード記述を課すこと、5教材の一括移植、新規教材の量産、就職・資格合格までの無期限フォローは範囲に含めない。資格取得・実習成果・就職は別の成果として確認する。

## 初回支援の中核の流れ（Golden Path）

これは支援の進め方であり、共通カリキュラムや全アプリ共通の画面操作ではない。記録には[初回支援シート](templates/ai-pairing-session.md)を使う。

| 段階 | 観測すること |
|---|---|
| 1. 課題と支援範囲を決める | 本人の希望、期待結果、対象教材・版、支援の枠が明確 |
| 2. AIに依頼して試す | 本人の希望が依頼に反映され、応答を使って課題を進めた |
| 3. 結果を確かめる | 本人が期待と実際を比較した。提供者が手伝った部分も記録 |
| 4. 引き渡して終了する | 再利用材料を渡し、成果・終了日・残件の扱いを記録 |

枠内で未達なら、未達のまま原因と次の扱いを記録する。支援終了だけを学習成功としない。変更・機能追加・別用途への応用は、その後に本人が選べる活動とする。
