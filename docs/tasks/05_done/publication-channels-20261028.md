# 3出口の文書・公開入力の分離

実施日：2026-10-28。対象：リポジトリ内の管理構成とローカル検査。

## Goal

本名公開・一般、本名非開示・ナイトワーク、本名非開示・一般の3出口を管理する。共通仕様をコピーせず、内部設計・公開原稿・出口設定を分離する。

## 実施

- [内部設計索引](../../../src/app-learning/docs/publication/README.md)と分離ポリシー、3出口の設計・運用を作成。
- [公開入力](../../../src/app-learning/publishing/README.md)に共通本文2件、各出口の導入原稿、素材台帳、独立した設定を作成。
- 原稿の依存リンク・許可・パス・2軸・公開準備状態を検査するPythonスクリプトと回帰テストを追加。
- root AGENTS、ルート・アプリ学習の総覧、関連索引を更新。既存アプリのコード・個別仕様は移動せず維持。
- [元の調査文書](../../../src/app-learning/docs/ナイトワーク特化版の情報出口と否かで設計を分ける.md)は調査記録・判断経緯・新正本への案内へ整理。
- `publishing/dist/` の3出口の空ディレクトリを用意し、Git管理外であることを確認。

## 検証

Python 3.13.5・PyYAML 6.0.2。既存環境を利用し、新しいパッケージのインストールは行っていない。

| コマンド・確認 | 結果 |
|---|---|
| `python src/app-learning/publishing/scripts/check_publication.py` | ①4素材・②5素材・③4素材の構造検査成功 |

## 実施していないこと

公開名・ブランド・問い合わせ先の具体値の決定、②の公開水準の採用、サイト生成・配置、認証の実装、リポジトリ公開範囲の変更、既存デモの停止・変更、外部への連絡は行っていない。全設定で公開無効、全素材はdraft。これらを完了したとは扱わない。

将来の①・②への整理は別判断。③の本名への置換、転送、ユーザー情報移管を自動化しない。進行中に見つかった他のREADME追記は維持し、他作業の変更を巻き戻していない。

## 引継ぎ対応

2026-10-28、別セッションの引継ぎメモと実ファイルを照合。README末尾の依頼メモは別作業で対応表に置換済みで、独自ドメインの条件も正本へ追加済みだったため保持した。③の題材はユーザーの明示した「ナイトワークに触れない」を維持。

ユーザーへ②・③の活動名を確認し、「別の活動名にする」と確定。正本・設計・運用の入口・元の調査文書・作業ルールの未決定表現を更新し、設定済みの活動名・メールの重複拒否を追加した。全半角・大小文字・空白の表記差も正規化して検出し、値の原文をログへ出さない。

教材単位で一般側から除外するのはキャスト評価だけで、他教材は中立的な説明なら掲載候補にできることを正本へ明記。①は独自ドメイン必須、②・③は必須ではなく、公開技術をできるだけ共通にする条件を各設計へ反映。

営業体制マスタは「本名の扱いは2系統、情報出口は当面3つ」に整理し、教材の分離要件は教材側の正本へリンクした。営業の実装・進捗には教材側の実施記録への参照を追加。既存の営業基盤の完了件数、DNS・契約等の実施状態は変更していない。
