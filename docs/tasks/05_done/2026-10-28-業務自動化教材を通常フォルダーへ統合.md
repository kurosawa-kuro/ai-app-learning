# 業務自動化教材を通常フォルダーへ統合

実施日：2026-10-28

## 目的と判断

`src/office-automation-starter` の独立したGit管理を終了し、同じパスの通常フォルダーとして `ai-app-learning` に取り込む。

当初の課題は「子でコミットし、親の参照を更新する」方針だった。ユーザーから「もう子リポジトリ不要」と指定されたため、サブモジュールを維持する案を取り下げ、教材ファイルを親で直接管理する方針に変更した。今後は親リポジトリで編集・コミットし、旧リポジトリとの同期は行わない。

## 対象範囲

- `src/office-automation-starter` のgitlinkを通常ファイル62件へ置き換える。
- 唯一のサブモジュールを記載していた `.gitmodules` を削除する。
- 親のローカルGit設定から、このサブモジュールの登録を解除する。
- 子の未コミットだったREADMEの方針追記も、現在の内容のまま取り込む。
- 元の教材とGit履歴をリポジトリ外へ退避する。リモートリポジトリの削除・pushは行わない。

## 退避と復元用の記録

退避先は、親リポジトリと同じ階層にある次のフォルダー。

```text
../ai-app-learning-backups/office-automation-starter-20261028-155736/
├ worktree/           教材ファイルと元の.gitのコピー
├ original-git/       元の作業フォルダーから移動した.git
├ manifest.json       退避前102ファイルのSHA-256
├ tracked-files.json  子で追跡されていた62ファイルの一覧
├ other-changes.json  別件の変更3ファイルのハッシュ
├ parent.gitmodules   変更前の.gitmodules
└ parent.gitconfig    変更前の親のローカルGit設定
```

旧子のHEADは `170da0cc5c80f387ef5e33aecbfcce71a2cf5896`。READMEの未コミット変更は退避先の `worktree/README.md` にも保持している。復元が必要な場合は、この退避を元に、復元時点の変更を保全してから対象だけを戻す。

## 残す変更と確認の範囲

課金管理の説明を追加した解説資料3ファイルは別件として保持し、この取り込みコミットには含めない。したがって親リポジトリ全体の変更一覧が空になることは、このタスクの完了条件にはしない。

VS Codeでフォルダーをファイルとして開こうとしていた問題に対し、原因となるgitlinkを取り除いた。既存のエラータブや表示キャッシュの再描画は、画面上では未確認。古いタブが残る場合は閉じ、通常ファイルの差分を開き直す。

## 再確認用コマンド

親リポジトリのルートで実行する。

```powershell
git -C src/office-automation-starter rev-parse --show-toplevel
git ls-tree HEAD -- src/office-automation-starter
git submodule status
git status --short -- src/office-automation-starter .gitmodules
git status --short
```

`git ls-tree` は、旧形式の `160000 commit` ではなく `040000 tree` を返す。対象パスの変更表示が空で、別件の変更だけが残ることを確認する。
