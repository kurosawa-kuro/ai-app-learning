# 08 教材提供・公開・支援終了の手順

[README](../README.md)・[AGENTS](../AGENTS.md)・[CLAUDE](../CLAUDE.md)に従う。教材文書の更新、アプリの公開、学習者への引き渡しは別の作業であり、リポジトリ全体を一括デプロイする手順はない。

## 提供前

1. 対象者、一つの課題、期待結果、教材の版を決める。
2. [支援シート](templates/ai-pairing-session.md)で支援の回数・時間・期間・窓口、不具合・未達時の扱いを決める。
3. 対象教材のREADME・正本と[検証方針](07_test_strategy.md)を確認する。設計案、ローカル実装、公開、実環境受入を区別する。
4. 提供者が同じ環境・サンプルで主要操作と戻し方を予行する。実機未確認のものを確認済みと案内しない。

教材の文書変更ではリンク・整合・差分を確認する。ルートの `make test` は提供可否の判定に使わない。

## アプリの公開が必要な場合

対象アプリのrunbookで、公開先、認証主体、アクセス範囲、保存先、費用条件、戻す版・手順を確認する。文書更新の依頼だけで公開操作を始めない。

| 対象 | 手順の所在・扱い |
|---|---|
| GAS | [教材一覧](../src/app-learning/01-gas-app-learning/README.md)から個別README・公開手順へ。push・公開版更新・実環境受入を区別 |
| Web | [Webアプリ制作の案内](../src/app-learning/02-web-app-learning/README.md)と[採用判断](adr/0001-web-app-stack.md)。Render・Supabaseの具体手順は実装時に確定 |
| Java | [学習戦略](../src/java-career-learning/java-career-learning-strategy.md)。資格学習やローカル課題にWeb公開を一律に課さない |
| 事務処理 | [教材README](../src/office-automation-starter/README.md)。元ファイルを保全して出力を確認し、不要な公開を増やさない |

公開後は、対象アプリ固有の主要操作を期待結果まで確認する。保存がある場合は再読込や重複要求、権限がある場合は公開範囲を確認し、[受入記録](templates/platform-acceptance.md)へ残す。学習支援の流れを、アプリの操作試験の代わりにしない。

不一致があれば提供を止め、対象の復旧手順で公開版とデータを確認する。アプリを旧版へ戻す操作とデータ復元は別に判断し、無条件の削除・巻戻しをしない。ルート共通のマイグレーションコマンドは定義しない。

## 引き渡しと支援終了

[初回支援の流れ](01_requirements.md#初回支援の中核の流れgolden-path)に沿って、本人がAIへの依頼・試行・結果確認を経験したかを記録する。終了時には次を渡す。

- 今回の成果と、再利用できるAIへの依頼文。
- 期待結果の確認方法、困った際の情報の整理方法、元に戻す方法。
- 今回の支援終了日と、未達・提供物の不具合・追加要望の扱い。

本人が次の課題を選ぶことと、提供者が今回の支援を終えることは両立する。別課題は新しい相談とし、資格合格・就職・全技術の習得まで対応を延長しない。枠を使い切った未達を成功扱いせず、不具合は事前の取り決めに従う。

## 終了後の改善

実際の成果と支援量を振り返り、同じ課題の説明・確認方法を改善する。新教材の追加や5教材の一括移植を自動的な次工程にしない。確定した手順は対象教材または共通文書へ、未実施の案は作業記録へ残す。
