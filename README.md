# AI App Learning

このREADMEは提供者向けの内部総覧です。全教材と用途を含むため、そのまま公開・配布しません。教材と3情報出口の設計は[3出口の分離管理](src/app-learning/docs/publication/README.md)と[公開原稿](src/app-learning/publishing/README.md)で管理します。実際の3サイトのコード・固定URL・検証・公開操作は[sites](../sites/README.md)を正本とします。教材リポジトリの設定変更だけでサイトが公開されるわけではありません。

IT入門者がAIを活用して、ITの基礎、プログラミング、業務効率化、資格取得に取り組むための教材・サンプル・学習戦略をまとめたリポジトリです。

このリポジトリでは、**誰の、どんなゴールに対して、最初の一歩をどう支援し、その後AIで何を横展開できるようにするか**を、取り組みごとに設計します。遊びからITに興味を持つこと、自分のアプリを使うこと、仕事の手間を減らすこと、資格と実習を就職につなげることでは、必要な支援も成果の測り方も異なります。

## AIの役割分担（2026-10-28更新）

| 質問・依頼の種類 | 使用するもの |
|---|---|
| プログラムコードについての質問・改造依頼 | **Devin** |
| プログラムコードからAIへの質問・生成・採点などの呼び出し | **OpenAI API** |

## 誰のゴールを、どう支援するか

**まず、何か一つでAIとの並走を覚えてもらえれば成功です。** 本人に意味のある小さな課題を選び、希望をAIへ伝え、応答を使って試し、期待した結果か確認します。提供者が言語化や操作を手伝っても成功です。

ここにある全分野・全教材・全技術を学ばないとプログラマーになれない、という設計にはしません。必要な学びは本人の目的や目指す仕事に合わせて選びます。初回成功のために資格取得、自力のコード記述、全教材の修了、別用途への応用を求めません。

提供者の支援は、最初に合意した1課題と回数・時間・期間で区切ります。AIへの依頼文、結果の確認方法、戻し方を渡して今回の支援を終え、その後の別課題は新しい相談として扱います。**本人が学び続けられることと、提供者が無期限に対応することを分けるから、提供を続けられます。** 未達や提供物の不具合は事前の条件に沿って扱い、達成したことにはしません。

[初回支援シート](docs/templates/ai-pairing-session.md)で開始・終了条件を決め、[1人・1課題の検証案](src/app-learning/docs/06_first-pairing-pilot.md)から具体例を選べます。協力者は現在未定です。

アプリ学習の受講順は、[01 GASでのアプリ入門](src/app-learning/01-gas-app-learning/README.md) → [02 Webアプリ制作](src/app-learning/02-web-app-learning/README.md)です。[アプリ学習の案内](src/app-learning/README.md)に沿って進めます。Java・Oracleの資格支援と事務処理の効率化は、目的に合わせて選ぶ別の入口です。以下の横展開は支援の方向性であり、すべての機能や教材が提供済みという意味ではありません。

提供者がコード・解説を作る順番は **02 Web → 01 GAS** です。動作確認と自動テストを行いやすいWeb側で仕様・実装・解説を先に整え、その成果をGAS側へ展開します。受講順と制作順の方針は[アプリ学習の横断設計](src/app-learning/docs/README.md)を参照してください。

GAS・Webの**両版で完成版を配布するのは、写真日記・キャスト評価・英語訓練の3教材だけ**です。じゃんけんとショップに両版の完成品を揃える要件は設けません。3教材は同じ基本機能で完成とします。じゃんけんはGASの通常対戦からWebのスキル・AIセリフ事前作成へ、ショップはGASの直接注文からWebのカート経由の注文へ進みます。横展開は目標提案・参考プロンプト・確認例を渡す範囲を基本とし、応用先をすべて制作する前提にしません。[配布・応用の対応表](src/app-learning/README.md)を参照してください。

| 取り組み・誰に | 本人のゴール | スタートの支援 | AIで横展開するもの |
|---|---|---|---|

## GAS：本人に身近な世界から始める

GAS（Google Apps Script）は、Google Sheetsなどと組み合わせて小さな仕組みを学ぶ入口です。現在は次の5教材を深め、仕様・確認方法・解説を整えることを優先します。

| 誰に・教材 | 本人のゴール | スタートの支援 | AIで広げる方向の例 |
|---|---|---|---|
| 遊びからプログラミングに関心を持つ子供：[skill-janken-game](src/app-learning/01-gas-app-learning/skill-janken-game/README.md) | 自分でルールを変える楽しさを知り、結果の理由を説明できる | 大人が環境とAI操作を支え、遊ぶ・予想する・小さく変える体験を用意する | 本人の「こう遊びたい」を、大人とAIが条件やルールの変更案にする。本人が試して結果を確かめる |
| 海外で働くことに関心がある英語学習者：[english-trainer](src/app-learning/01-gas-app-learning/english-trainer/README.md) | 英語学習を改善し、ITを使った成果と自分の担当部分を説明できる | クイズや会話を体験し、回答・評価・履歴の読み方と小さな改善を支援する | 別の学習場面に合う改善案や練習課題をAIと考え、自分の学習へ応用する |
| 写真日記を身近に感じる人（ナイトワークの女性など）：[photo-diary](src/app-learning/01-gas-app-learning/photo-diary/README.md) | 写真・日記・タグの関係を理解し、自分の記録を整理する力をつける | サンプル画像で記録を体験し、日記とタグの関係を言葉や図で整理する | 分類・検索などの改善案をAIへ伝え、身近な情報整理へ考え方を応用する |
| 複数キャストを雇う予定の独立希望者・店長：[cast-evaluation](src/app-learning/01-gas-app-learning/cast-evaluation/README.md) | 自分の店の評価業務を運用し、ルール変更の結果を確認できる | 評価業務の必要性を確かめ、検証用MVP、導入案内、店舗設定の伴走を準備する | 店舗固有の要望を仕様にし、設定で足りない改修をAIへ依頼して検証する |
| 商取引の仕組みを学びたい人：[online-shop](src/app-learning/01-gas-app-learning/online-shop/README.md) | 商品・注文・明細の関係と、確定時点の情報を守る理由を理解する | 設計中の注文シナリオを、サンプルデータと期待結果で学べる形にする | 注文・明細の考え方を別の取引課題へ応用する案をAIと検討する。具体的な対象者像は未確定 |

GAS教材では、**体験 → 理解 → 設定 → 改修 → 検証 → 自立**を指導の枠組みとして使います。どこまで進めるか、何をもって成功とするかは対象者ごとに決めます。子供は楽しさと理解、英語学習者は学習への活用、店長は評価業務を運用できることなどで確認します。保護者の希望と子供本人のゴールも分けて扱います。

横展開の例は追加機能の採用決定ではありません。現在の設定範囲・公開範囲を確認し、必要な改修だけを個別に設計します。職業や属性だけで関心を決めつけず、本人の課題を確かめます。

記事・動画による自習と、対面30分×3回の伴走を組み合わせる指導案もあります。教材や指導方法は準備・検証の対象であり、90分で開発や公開まで修了する約束ではありません。

## Webアプリ：非エンジニアが自分の道具を作って使う

本人のゴールは、自分用・業務用のアプリを作り、実際に使えることです。最初に支援するのは、欲しい機能を小さく絞ること、動くひな形と環境を用意すること、必要な公開範囲で使い始めることです。技術やアカウント準備が増えて着手できない状態を減らします。

AIには、本人の業務の説明を仕様や画面・データの案にすること、最初に動いたアプリを用途に合わせて変更すること、確認手順を用意することを担わせます。本人は必要な処理と期待する結果を判断し、実際の利用で確かめます。その経験とひな形を、別の入力項目・集計・身近な業務へ応用することが横展開です。全員にコードを自力で書くことや資格取得を求める設計にはしません。

成功は、本人の用途で主要操作が完了すること、変更した結果を確かめられること、問題が起きたときに復旧・相談できることで確認します。

[Webアプリ制作の案内](src/app-learning/02-web-app-learning/README.md)に従い、画面・業務処理はSpring Boot＋Thymeleaf、アプリの実行・公開はRender、DBはSupabaseのPostgreSQLに統一します。画像保存などに必要な場合はSupabase Storageを扱います。Java・SQLの知識やひな形を再利用し、導入・AI改修・検証の支援を蓄積します。具体的な環境設定・料金・運用条件は実装時に確認します。

[GAS資料](src/app-learning/01-gas-app-learning/README.md)の発展版も同じSpring Boot構成に揃えます。GAS版とSpring Boot版を共通の業務要件・受入条件で比較し、既存5教材を1題材ずつ整備します。基盤を揃えても、本人のゴール・スタート支援・AIで横展開する範囲は取り組みごとに分けます。GAS修了やJava資格の取得をWebアプリ利用の条件にはしません。

## 資格学習を実習につなげる

[Java・Oracle Bronze × Devin 学習戦略](<src/java-career-learning/java-career-learning-strategy.md>)は、Java・Oracleを扱う業務システム開発・保守の仕事を目指す人に向けた学習案です。

スタートでは、狙う仕事に必要なJava・DBの基礎へ範囲を絞り、環境準備と最初の実行・修正課題を支援します。Devinには例題、解説、エラー再現、レビューを担わせます。本人が学んだことを次の課題でも使えるようにし、応募時に説明できる成果を残します。

- Java・Oracle系の仕事を目指す場合は、Java Bronze、Oracle Databaseの基礎、SQL実習、GitHubで示せる成果物から、応募先に必要な目標を選びます。
- 資料末尾の追記を踏まえ、Java Bronzeは優先取得、Oracle Bronzeは学習を先行し、受験は必要性に応じて判断する方針です。学習済み・受験予定・取得済みを区別します。
- DB管理の学習に加えて、自分でSQLを書き、JavaからDBを操作する実習を行います。
- Javaの小さな課題から始め、目指す仕事に必要ならOracle／SQL、Web開発が必要ならSpring Boot、運用が必要ならLinux・AWSを選びます。全項目の修了は必須ではありません。
- Devinを実装例・解説・課題・レビューに活用し、本人による説明、テスト、AIなしでの小さな修正で習得を確かめます。

横展開では、学んだ文法やSQLを使う別の演習をAIに用意させ、本人が解きます。技術を深める際は、同じアプリをDB連携・Web化・運用へ発展させます。どちらも、本人が担当できる課題や業務の範囲を広げるために行い、AIが完成させた機能数で習熟を評価しません。

資格取得・実習成果・就職の成果はそれぞれ確認します。ITパスポートや基本情報技術者試験も含め、目的や応募先に応じて学習を選びます。試験範囲・受験料・AIサービスの利用条件は、利用時点の公式情報を確認してください。

Web教材の実行DBはSupabaseのPostgreSQLとし、Oracle固有の管理・SQL実習は資格学習側で扱います。Spring Boot段階では共通のWeb教材を活用できます。Linux・AWSは志望する仕事に応じた追加学習であり、Web教材の標準公開先はRenderです。

## 事務処理からAIを使い始める

[Cursor業務効率化スターター](src/office-automation-starter/README.md)は、Windows 10/11を使う非エンジニア向けの教材です。主な想定読者はIT人材・SES営業担当者で、業務の具体例とコピーして使えるプロンプトを用意しています。

最初は[クイックスタート](src/office-automation-starter/docs/教育資料/01_クイックスタート.md)から、[事務処理タスク集](src/office-automation-starter/src/office-task/README.md)の小さな課題を一つ試します。このリポジトリを取得済みの場合は、`src/office-automation-starter/` をCursorで開きます。

この教材ではPython・Node.jsの追加インストールを前提にせず、Windowsの機能や手元の業務ツールを使います。ファイル操作はコピーに対して行い、元ファイルは変更・移動・削除しません。無料枠での利用を想定した資料ですが、利用可能な機能や制限は開始時に確認してください。

最初の1件ができたら、プロンプトの対象ファイル、抽出条件、集計単位、出力形式を自分の業務に合わせて変えます。AIへ調整を頼み、次のCSV集計や資料整理へ応用します。各プロンプトは単独でコピーして使える形を保ちます。

成果は、出力の正確さ、作業時間や手戻りの変化、次回も同じ手順で処理できるかで確かめます。アプリ開発やプログラマーへの転職を、この取り組みの到達条件にはしません。

## 成果の確認も取り組みごとに決める

初回は1課題でAIと進めた経験と確認結果を残します。本人の目的、AIに任せた部分、本人が行ったこと、提供者の支援量、引き渡しと支援終了も記録します。以下は本人がその先のゴールを選んだ場合の観点で、初回成功の一括合格条件ではありません。

| 取り組み | 確かめる成果 |
|---|---|
| GASの身近な教材 | 対象者ごとの興味・理解・活用。本人が予想して試し、変化を説明できたか |
| 自分用・業務用Webアプリ | 本人の用途で使えたか。必要な変更を依頼・確認し、使い続けられるか |
| Java・Oracleの資格／実務学習 | 知識の理解、自力のJava・SQL修正、テスト、資格・学習履歴、応募先へ説明できる成果 |
| Cursor業務効率化 | 出力の正確さ、時間・手戻りの変化、別の事務処理への応用と再現性 |

教材にはサンプルや架空データを使い、顧客情報、私的な写真・会話、APIキーなどを公開しません。AIへ渡すデータ、保存先、公開範囲を理解することも学習に含めます。
